# ゲーム寸法で読ませる ― 判定の作り方

> 個別の失敗と対処は `handbook/modeling-pitfalls.md`。
> 塗りの方針は `handbook/hand-painted-standard.md`。
> 本書はその手前の「**何を見て良し悪しを決めるか**」を書く。

## 経緯

ホネガラミ(第一地方の重量級、蔦に絡まれた骨の塊)の作り直しで、
造形の質が上がっているのにキャラクターらしさが下がる、という現象が
何版も続いた。原因はほぼ全部**判定の作り方**の側にあった。大きな
レンダーで細部を見比べ、足りない所へ形を足す、を繰り返していた。

## 1. 判定はゲームカメラ寸法で行う

ダンジョンでモンスターが占めるのは 96px 前後。この寸法では

- 読める: 頭蓋・胸郭・大きな骨片・太い蔦・巨大な足・手の塊
- 読めない: 細い指・細枝・小さな骨片・蔦の細かな潜行・棘・芽

したがって「設定画の情報量を3Dで全部再現する」は目標にならない。
**96pxに落とした設定画と実機レンダーを横に並べる**のが基本の判定画像。
それ以外の大きなレンダーは、原因を探すときだけ使う。

## 2. 明暗の役割分担を先に決める

似ていない原因は形の量ではなく明暗であることが多い。設定画とモデルを
同じ大きさに揃え、**部位ごとの平均輝度と基準部位に対する比**を測る。

ホネガラミの実測(設定画): 頭蓋107 / 手97・89 / 胸郭61。
いちばん暗いのは胸郭で、手は頭蓋に近い。手が汚れて見えるのは骨の色では
なく**骨と骨のあいだの暗部が広い**から。塊としての暗さはトレース(絵)に
持たせ、材質側は部位ごとの明度比だけを持つ。

**比が逆転していたら、足りないのは形ではない。**

## 3. 黒ベタで「何に見えるか」を確かめる

色を外して黒ベタにすると、シルエットが名前を持っているか(頭・手・足)が
一発で分かる。ただし**実機と同じ抜き**で作ること ―― Blender の
シルエット出力はアルファを見ないので、抜きカードが板のまま写る
(`modeling-pitfalls.md` 4-15)。

## 4. 邪魔しているものは数える

「頭が読めない」ときに部品を当てずっぽうで動かすと版を無駄にする。
空けたい帯を定義して、そこへ入っている面を部品ごとに数える。
ホネガラミでは上位5件が全部 蔦で、骨は1つも入っていなかった
(`modeling-pitfalls.md` 2-34)。

## 5. 指標に自己正規化を混ぜない

「下位4割を暗部とする」のような分位点しきい値は、暗さを足すと
しきい値も一緒に動いて変化を打ち消す。全身平均で割った相対輝度のように、
**加えた変化が必ず数字に出る**形にする(`modeling-pitfalls.md` 1-40)。

## 6. 大きな形を先に確定(LOCK)し、以後さわらない

層ごとに「もう触らない」を宣言して積み上げる。ホネガラミの順序は

  Skull → Hand → Hero Anatomy → Major Vine → (LOCK) → Texture

で、LOCK 後に足してよいのは**ゲームカメラで足りないと分かった大きな
流れ**だけ。棘・芽・細枝のような細部は最後。ここを守らないと
「密度は上がったが読みにくくなった」へ何度でも戻る。

## 7. 数値は故障検出、判定は目

IoU・占有率・被覆率はどれも「壊れていることを見つける」ためのもので、
「良い」を決められない。合格の判定は 96px の並べ画像と黒ベタで目視する。
数値が全部 PASS なのに見た目がおかしい、は何度も起きた。
