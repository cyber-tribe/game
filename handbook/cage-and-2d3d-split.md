# ケージ+Subdivision の造形と、3D/2D の分担

> あくびとかげ(四つ足のトカゲ)を設定画へ寄せる作業(2026-09、PR #1064〜と
> ブランチ `wip/akubitokage-v3`)で確立した方式。個別の失敗は
> `handbook/modeling-pitfalls.md` に「症状 → 原因 → 対処」で書いてある。
> ここには**次のキャラクターでも最初から採る方式**だけを残す。

## 経緯 ―― なぜ方式を変えたか

あくびとかげは「断面ロフト + `curve_tube` + `sculpt_merge`(voxel remesh)」で
作り、設定画へ寄せるために 4 回続けて修正した(#1064〜#1068)。
毎回どこかは良くなるのに、A/B で並べた印象は変わらなかった。

原因は造形の腕ではなく**方式**だった。`sculpt_merge` は和集合しか作れない。
首の細い谷、脇、腕と胸の境界、腹と腿の境界、顎下、指、背びれの根元、頬の面変化
――**設定画がキャラクターらしさを作っている場所は、ほとんどが負の空間**で、
voxel 融合はそれを片端から埋める。谷を深くしても融合で消え、また深くする、を
繰り返していた。

局所修正を続けるのではなく、方式を切り替えるべき合図はここにある。

> **同じ種類の指摘が 3 回続いたら、パラメータではなく方式を疑う。**

---

## 1. 胴と頭は「意味のあるエッジループを持つケージ + Subdivision」で作る

`C.section_loft` に手置きの断面を積み、`SUBSURF` で丸める。voxel remesh は
使わない。Subdivision はケージの谷をそのまま保つので、**負の空間が消えない**。

ループには意味を持たせる。あくびとかげの場合:

```
seat / rump_low / rump / pelvis / belly_low / belly / belly_high / ribs
/ chest / collar / throat / jaw / lip / mouth / cheek / snout_eye
/ brow / forehead / crown / top
```

名前が付いていると、レビューの指摘(「くびれが太い」「頭頂が細い」)が
そのまま「どの行の r_side を動かすか」に翻訳できる。**行が匿名だと、
指摘のたびに全体を探すことになる。**

断面は楕円にしない。前・後ろ・横の半径を別々に持たせ、さらに前半分の
平面視の絞り(`snout`)を持たせる。楕円だけでは「腹は前へ張る卵、頬は横へ張る、
口吻は前へ細くなる」を 1 ループで表せない。

```python
# (z, cy, r_front, r_back, r_side, snout, name)
(0.045, +0.005, 0.046, 0.039, 0.0405, 0.0, "belly"),
```

### 収縮の補正

Subdivision は多角形のケージを内側へ縮める(12角形で約 7%、20角形で約 2.5%)。
実測した半径をそのまま置くと**全体が一回り細くなる**。半径にだけ補正係数を
掛ける(中心位置は動かさない)。

### 四肢・尾・背びれは別メッシュのまま join する

融合しない。join しただけなら内部に面が残るだけで、外から見える谷は保たれる。
本番化のときも `join` → `decimate_to` の順で、voxel remesh は挟まない。

---

## 2. 顔面は「水平リングを押す」のではなく、bmesh の inset で島を切る

ケージのリングを前へ出して顔を作ると、**口の高さで頭を横断する「帯」**が
できる。トポロジーがそういう面を作りやすい構造だからで、パラメータでは直らない。

顔だけ、ケージ段階で意味論的な島を切る:

- **目**: 3 列 × 2 行の面を 2 重 `inset_region` したリング。眼窩は掘らない。
  外リングの上側を盛って上まぶたにし、内側の眼裂だけをわずかに奥へ。下側は
  頬へつなぐ。**穴を掘ると「爬虫類の解剖学」になり、かえって設定画から離れる。**
- **口**: 3D では作らない(下記 4 を参照)。

ループの頂点は前半分(顔側)に集中させる。あくびとかげは前 180° に 12 点、
後ろ 180° に 8 点。顔の解像度が倍になり、胴には影響しない。

---

## 3. 顔の情報を 3D と 2D に分担する ―― 分担表を先に決める

**造形だけで設定画の顔を再現しようとすると、設定画に無いものを彫ることになる。**
あくびとかげの顔は「マズルのある動物顔」ではなく、「大きな一枚の顔面 + 重く
垂れた左右のまぶた + 極小の鼻 + 頬に埋もれた長い口 + 大きく柔らかな顎」だった。
深い眼窩・強いマズル・鼻翼を作り込むほど遠ざかる。

| 要素 | 3D | テクスチャ |
|---|---|---|
| 頭蓋シルエット・頬の大ボリューム・短い鼻先・下顎(あくび) | ◎ | ○ |
| 半目・上まぶた・鼻孔・通常時の口線・頬模様・細かな顔の陰影 | △/× | ◎ |

新しいキャラクターに着手したら、**設定画を見て最初にこの表を書く**。
「どこまでを形で作るか」を決めずに彫り始めると、Clay だけで完成顔にしようとして
何版も溶ける。

### ゲートを分ける

1. **Body ブロックアウト**: 単色 Clay で 5 角度 + ワイヤー。IoU は見ない
2. **Face Clay Gate**: 「テクスチャ無しでも、頬・目を置く面・鼻を置く中央面・
   口周囲・顎の**立体関係**が成立しているか」。*Clay だけで完成顔に見えるか*
   ではない ―― そこまで求めると彫りすぎる
3. **Face Texture Gate**: 設定画から起こしたデカールを載せて「そのキャラに
   見えるか」
4. **Body Final Gate**: 顔を固定したうえで、プロポーションと全身の塗り

顔がロックできると、残差が「身体のプロポーション」と「全身の手描き
テクスチャ」に絞れる。逆順にすると「顔が違う」というノイズで身体を評価できない。

---

## 4. 通常時の口は BaseColor、あくびは顎ボーン + 顔アトラス

口を 3D の溝やスリットで作ると、次のどれかに必ずなる:

- 溝が「描いた口線」と**二重の口**に見える(位置を合わせても陰影が出る)
- 幅 1mm 以下の細い溝は**自動ウェイト(bone heat)を壊す**
- 下顎を切り離すと、頭と下顎を別々に Subdivision したときの**収縮量の差で
  境界がぴったり合わない**(crease で押さえても極限位置は一致しない)

採るべき形は「口腔の**見た目**は 2D、あくびした**動き**は 3D」。

- 顔だけ別マテリアルにして、**通常 / 予備 / 大あくび の 3 コマを横に並べた
  アトラス**にする(`C.atlas_horizontal`。ガルドのまばたきと同じ "eyelid" 方式)
- 顎ボーンの回転・頭の反り・胸の膨らみで動きを作る
- glTF の extras に `mouthTiles` / `mouthMaterial` を出し、エンジンは顔マテリアルの
  UV を 1/コマ数 ずつずらす

正面の絵が設定画に無くても、**側面から比を実測して正面へ補間**すれば想像で
描いたことにはならない(下記 5)。

## 5. 設定画の読み取り

### 高さごとに測る。中心は「胴の中心」で取る

三面図のマスクを高さ 5mm ごとに走査し、各行の区間を出す。このとき
**外接箱の中心を使ってはいけない** ―― 尾が横へ出ているぶん中心がずれ、
半幅がすべて狂う。体の高さ 45〜60% の行の中点の中央値を「胴の中心」にする。

あくびとかげでこの測り直しをして初めて、

- **腹の半幅(0.0405)が頭(0.042)とほぼ同じ**であること
- 頭の上半分をモデルが絞りすぎていたこと(目の高さ 0.036 対 実測 0.042)
- 腕の外端(0.0454)が腹の半幅より外に出ていたこと

が分かった。「丸い腹」「どっしり」「腕が独立した柱に見える」という指摘は
すべてこの 1 回の実測で説明がついた。**指摘を言葉のまま形に翻訳する前に、
まず測る。**

### 三面図の枠はシートから自動検出できる

キャラクターシートの三面図ブロックで連結成分を取れば、正面・側面・背面の
外接箱がそのまま出る。座標を手で書き写さないこと(シートが差し替わると腐る)。

### 設定画に無い視点は「補間」であって「創作」ではない

45° の設定画が無くても 45° のモデルは作る。同じように、正面のあくびが
無くても、側面のあくびから **口の色・開口量・口角・上下顎の関係**は既に
定義されている。不足しているのは正面投影だけなので、比を実測して写す。

> 「設定画から直接写す」は、**設定画に描かれていない視点を禁止する原則では
> ない**。禁止するのは、設定画が定義している情報を無視して発明することだけ。

## 6. 全身の塗りは三面図からのトライプラナー投影

顔だけデカールを貼ると、後ろから見たときにほぼ単色になる。設定画が持っている
情報量(頭・首・腕・腿・背中・尾の斑点)は、**造形よりはるかに大きく最終印象を
変える**。

- 三面図から斑点を抽出し、モデル座標へ写した 3 枚(正面 / 側面 / 背面)を作る
- モデル側は面法線の向きで 3 枚を混ぜる(トライプラナー投影)
- 顔の造作に重なる斑点は落とす(確定した目と口が読めなくなる)

### 色は「パレットのスウォッチ」ではなく「絵の中」から採る

設定画のカラーパレットの「おなか」(#d7cbc8)をそのまま使うと、実機で
**白く光る球**に見えた。絵の中の腹は体色の約 1.9 倍の明るさしかない
(実測 sRGB 113,102,113 対 59,55,68)。スウォッチは色相の指定で、
**明度の指定ではない**。

## 7. 評価の運び方

### 合格条件を先に固定してから試す

「試してから感覚で判断する」と、方式 1.1、1.2、1.3 …… と際限なく続く。
技術スパイクは**一度きり**にして、条件を先に書く。あくびの下顎分離では:

- 閉口の正面 / 45° / 側面で境界が口線からはみ出さない・二重線にならない・
  顎パーツ感が出ない
- ゲームカメラで現状より悪化しない
- 30° の開口で「口が開いた」と分かる
- ウェイト破綻を新たに生まない

満たさなければ**その方式は永久棄却**。「境界をあと 1mm」へ進まない。

### 指標は故障検出に使い、合否は人の目で決める

シルエット IoU・三角形数・ランドマークの一致は「壊れていないこと」しか
言えない。**指標を最適化して対象を最適化しない**典型に何度も落ちた。
合否は「設定画を左、Clay を右に並べて 3 秒見たときに同じキャラクターに
見えるか」で決める。

### 三面図は整合した投影図ではない(view authority)

3 面すべての一致度を同時に上げようとすると、どこにも似ないモデルになる。
面ごとに「その面が決めるもの」を割り当てる:

| 面 | 決めるもの |
|---|---|
| 正面 | 顔・腕・腹・足の配置と幅 |
| 側面 | 姿勢、頭〜背中〜尾のライン、大腿 |
| 背面 | 背びれ、腰、大腿、尾の付け根 |

### レビュー資料の型を固定する

「設定画 / Clay / ワイヤー」× 5 角度のシートに固定してから、指摘が
一気に具体的になった。テクスチャに騙されず、「肉塊ではなくなった。しかし
骨格とポーズが違う」といった診断ができるようになる。

## 8. リグ ―― 内部に部品が刺さったメッシュの自動ウェイト

融合しないぶん、join したメッシュの内部には四肢・尾・背びれの面が残る。
`build_armature` の自動ウェイト(bone heat)はこれを嫌い、取りこぼしが出る
(あくびとかげ v3 では実行ごとに 210〜2,430 頂点で揺れた。按分に
フォールバックするので破綻はしないが、品質は落ちる)。

- **薄い板(背びれ)は必ず取りこぼす**。内部からボーンを見通せないため。
  頂点グループを付けて `pin_weight_to_bone` で明示的に固定する。
  背骨に沿って 2〜3 区間に分けると、胴の変形にも自然に追従する
- 取りこぼし数は**ビルドログを毎回見る**。見た目が崩れていなくても、
  実機のアニメーションでスキニングの品質が落ちている

## 9. UV とテクスチャの密度

顔の絵をテクスチャに任せるなら、**顔の UV 密度を先に測る**。

| 展開 | 島 | 充填 | 顔の密度 |
|---|---|---|---|
| `smart_uv` | 276 | 35% | 0.75 テクセル/mm |
| `organic_uv`(赤道シーム)+ 顔 boost + `split_material_region` | 80 | 65% | 約 6 テクセル/mm |

設定画の眼裂は高さ 2mm しかない。1 テクセル/mm では 2 テクセルに潰れ、
「細いギザギザの線」になる。**2.8 テクセル/mm を下限**とし、顔は専用アトラスに
分離する。

顔を平行投影の UV で切り出す方法は使えない。同じ (x,z) を持つ複数の面
(口腔の奥壁・目の inset リング・頬の側面)が同じ UV に重なって破綻する。
`organic_uv` の boost でシームを引いてから `split_material_region` を使う。

## 10. まとめ ―― 次のキャラクターで最初からやること

1. 設定画を見て **3D / 2D の分担表**を書く
2. 三面図のマスクを**胴の中心基準**で高さごとに実測する
3. 意味のあるエッジループを持つ**ケージ + Subdivision** で胴と頭を作る
4. 四肢・尾は**別メッシュのまま**にし、voxel 融合しない
5. 顔面は **inset の島**で切る。眼窩は掘らず、上まぶたを盛る
6. 通常時の口は **BaseColor**。あくび等の開口は**顔アトラス + 骨**
7. 全身の斑点は三面図から**トライプラナー投影**で貼る
8. 色は**絵の中から実測**する(パレットのスウォッチは色相の指定)
9. ゲートを分け、**合格条件を先に固定**する。指標は故障検出に使う
10. 薄い板は **pin** し、ビルドログの取りこぼし数を毎回見る
