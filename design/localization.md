# 多言語対応方針

家庭用ゲーム機のソフトウエアに並ぶ配信を見据え、将来の多言語展開
(まず英語を想定)に備えたテキストの扱い方を定める。**今すぐ全文を
翻訳するための文書ではなく、あとから翻訳してもコードを壊さずに済む
土台**を先に決めておくもの。

## テキスト管理の方針

現状、モンスター名(`Species.name`)・アイテム説明(`ItemDef.description`)
など、日本語文字列がコードの中に直接埋め込まれている
(`src/entities/species.ts` `src/items/catalog.ts` 等)。これを
**id と表示文字列を分離する**形に寄せる。

```ts
// 例: src/i18n/ja.ts
export const ja = {
  "species.purun.name": "ぷるん",
  "item.healLeaf.description": "HPを25回復する。",
  // ...
};

// src/i18n/en.ts (将来追加)
export const en = {
  "species.purun.name": "Purun",
  "item.healLeaf.description": "Restores 25 HP.",
};
```

`Species` `ItemDef` 等のデータ定義側は `name` `description` に直接文字列を
持つのではなく、`nameKey` のような**id**を持ち、表示直前に現在の言語
テーブルから引く形にする。既存の定義ファイル(`species.ts` `catalog.ts`)
の構造そのものは変えず、文字列を差し替えるだけで済むようにするのが狙い。

## 固有名詞の翻訳方針

この作品は擬音語・語呂(`design/characters.md` `plan/monster-compendium.md`)
に頼った命名が多く、逐語訳すると意味が失われる。翻訳時の原則を先に
決めておく。

- **生態・性質に由来する名前(モンスター種族名)**: 音をそのまま
  ローマ字化せず、**同じ手触りの英語オノマトペ・意訳**に置き換える方針
  とする(例のイメージ: 「ぷるん」→ふるふる揺れる質感が伝わる語、
  「ガジリねずみ」→かじる仕草が伝わる語)。具体的な訳語一覧は本文書の
  対象外とし、翻訳担当が世界観(`design/world.md`)を踏まえて別途決める。
- **意味を伝えたい固有名詞(ヨリシロ・めざめの階段・夢のかけら等)**:
  世界観の理解に関わるため、音写ではなく**意味を汲んだ訳語**にする。
- **人名(ガルド・モグラ婆・ゲンド等)**: 基本は音写でよい。ただし
  「モグラ婆」のように役割が名前に混ざっているものは、役割部分だけ
  意訳し人名部分は音写にする、といった個別判断を認める。

## UIレイアウトへの影響

`design/ui-flow.md` のメニュー・HUDは日本語の文字数を前提に組まれる
想定だが、英語は同じ内容でも表示に必要な幅が変わりやすい(短くなる
場合も長くなる場合もある)。**固定幅のボタン・ラベルに文字列を
流し込む設計を避け、可変長のテキストを前提にレイアウトする**ことを、
`design/ui-flow.md` 側の実装時の注意点として申し送る。

## 優先順位

一度にすべてを翻訳する前提は置かない。実装コストを見積もりやすいよう、
優先度を分けておく。

1. **最優先**: 操作に直結するシステムメッセージ・メニュー・ステータス
   表示(遊ぶ上で必須)
2. **次点**: モンスター・アイテム・地方・NPCの名称、`description`
   (機能説明)
3. **後回しでよい**: `design/flavor-details.md` の `flavorText`・
   NPCのせりふプールなど、言葉遊びに頼った味付け部分。翻訳自体の難度が
   高く、遊びに支障はないため後回しにしてよい。
