# UI/画面構成

ここまでの設計で拠点(ネンネ村)の機能が数多く増えたので
(倉庫・ねむり小屋・ゲンドの工房・依頼板・図鑑小屋・実績帳・村の発展・
ダンジョン選択)、**全体としてどう1つの画面遷移にまとまるか**を一度
整理する。個々の機能はすでに仕様化済みなので、本文書は**地図**にあたる。
新しい機能は増やさない。

## 全体の画面遷移

```
タイトル画面
  ├─ はじめる/続きから(セーブ枠選択)
  ├─ 設定
  └─ (実績帳のハイライト・累計プレイ実績を軽く表示してもよい)
        │
        ▼
      拠点(ネンネ村。3D空間を歩き回る。plan/town-3d-exploration.md)
  ├─ 倉庫・持ち物選択(モグラ婆) ──── 既存実装
  ├─ ねむり小屋(仲間の預け入れ・夢あわせ・成熟) ── plan/monster-fusion.md, plan/companion-evolution.md
  ├─ ゲンドの工房(強化値・印) ────── plan/equipment-forging.md
  ├─ 依頼板(肝いりのオトネ) ──────── plan/quest-board.md
  ├─ 図鑑小屋(物知りのおキヨ) ─────── plan/monster-compendium.md
  ├─ 実績帳 ─────────────────────── plan/achievements.md
  ├─ 村の発展 ───────────────────── plan/village-development.md
  ├─ NPCとの会話(絆) ─────────────── design/village-life.md
  └─ 出発(洞窟の入口。ダンジョン選択) ─ plan/multiple-dungeons.md, plan/checkpoint-select.md

      いずれも、該当する建物/NPCに歩いて近づき確定キーで開く
      (plan/town-3d-exploration.md。個々の画面の中身は変えない)
        │
        ▼
     ダンジョン(選んだ穴・チェックポイントから)
  ├─ 探索・戦闘 ─────────────────── 既存実装
  ├─ 樽守りの技(Cキー) ───────────── plan/protagonist-arts.md
  ├─ 仲間への指示(Tキー) ─────────── plan/companion-orders.md
  └─ めざめの階段(区切り/踏破) ────── plan/checkpoint-select.md
        │
        ▼
      拠点へ帰還(踏破 or 全滅)
```

## セーブ枠

現状は `localStorage` に単一キーで保存している(`src/save.ts`)。
家庭用ゲーム機のソフトウエアに合わせ、**3枠のセーブデータ**を選べるように
広げる。

```ts
// localStorage のキーをスロットごとに分ける
const KEY_PREFIX = "garudo-dungeon/v1/slot";
```

複数人で交代しながら遊ぶ・縛りプレイ用に別データを試す、といった用途を
想定する。既存の単一キーのデータは `slot0` として自動的に引き継ぐ
(初回起動時のマイグレーションのみ必要)。

## 設定画面

新規に用意する。以下を最低限含める。

| 項目 | 内容 |
|---|---|
| 音量 | BGM/効果音を別々に調整(`design/audio-direction.md`) |
| メッセージ速度 | 戦闘ログ・会話の表示速度 |
| 操作説明の再表示 | README操作表に相当する内容をゲーム内でいつでも見返せる |
| キー配置の確認 | 既存キー(README記載)+本設計で増えたC・Tキーを一覧表示。再割り当ては本文書の対象外(必要になれば別途仕様化) |

## 拠点画面のまとめ方

個々の施設(ねむり小屋・工房・依頼板・図鑑小屋・実績帳・村の発展)は、
それぞれの文書で「一覧UIパターンを踏襲する」と定めてきた
(`src/ui/town.ts` の拡張)。本文書ではその上位に**1枚の拠点メニュー**を
置き、施設を選んで個別画面に入る構成にする。`plan/village-development.md`
の段階が低いうちは、未解放の施設をグレーアウトで一覧に表示し、
「この先何が増えるか」が常に見える状態にする(`plan/achievements.md`
で採用した「隠さない」方針と揃える)。

## エンドロール

`design/story.md` 第四章クリア時に、短いスタッフロール相当の画面を挟む。
このゲームはREADMEにある通りすべて自作(3Dモデル・今後の音楽含む)なので、
**制作物の一覧(モンスター・地方・NPCの名前がずらりと並ぶ)を、実質的な
クレジットとして使う**(実在の制作者名の掲示は本文書の対象外とし、
実装側の判断に委ねる)。`design/postgame.md` の「真の目覚め」後には、
追加の短い一枚絵・一言を差し込む。

## この文書が担う役割

新機能は増やさず、**すでに設計した機能どうしの置き場所を確定させる**
ことで、実装セッションが迷わず着手できるようにする。今後さらに拠点機能が
増える場合も、この地図に追記していく形にする。
