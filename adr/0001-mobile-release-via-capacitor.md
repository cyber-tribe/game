# 0001: モバイル配信は Capacitor によるネイティブラッパーで行う

- ステータス: 決定
- 日付: 2026-08-11

## 背景(Context)

これまで本プロジェクトはブラウザで動く Three.js 製の 3D ローグライク
として作ってきた(README 参照)。ここに、**スマートフォンアプリとして
リリースする**という方針が加わった。目的は次の2点:

1. 長期的に複数プラットフォーム(iOS / Android / 引き続き Web)へ展開すること
2. 収益化すること(アプリ内課金・広告など)

`src/` 以下のゲームロジック・描画・`tools/models/` の 3D モデル生成
パイプラインはすでに Web 向けに作り込まれており(TypeScript + Three.js、
Node 上でユニットテスト可能、CI でヘッドレスブラウザの通しプレイまで
検証済み)、これを活かせるかどうかが選択の分かれ目になる。

## 検討した選択肢

| 案 | 概要 | 評価 |
|---|---|---|
| **PWA 化** | `manifest.json` / service worker を足し、ホーム画面に追加できる Web アプリにする | 実装コストは最小で複数プラットフォームに強いが、iOS の PWA は機能制限が大きく、ストア外配信のため発見性・課金導線(ネイティブ IAP)が弱い。収益化を主目的に置くには弱い |
| **Capacitor によるネイティブラッパー** | 既存の Web ビルド(`dist/`)を WebView に包み、iOS/Android のネイティブプロジェクトとして生成する | 既存コード資産をほぼ全部再利用できる。App Store / Google Play への正式配信、ネイティブ IAP・広告 SDK・プッシュ通知等のプラグインが使える。ビルド設定・ストア審査対応の作業は増える |
| **ネイティブエンジンへの書き直し(Unity 等)** | Web という前提自体をやめ、ネイティブエンジンで作り直す | 長期的な性能・エコシステムでは有利な場合があるが、`src/` のゲームロジック一式・3Dモデル生成パイプライン・テスト資産をほぼ再利用できず、コストが見合わない |

## 決定(Decision)

**Capacitor を使ったネイティブラッパー方式を採用する。**

- 既存の Web 版(`npm run build` の `dist/`)はそのまま無料の Web 版として
  公開を続けられる。
- Capacitor でラップしたアプリ版を iOS / Android のストアに配信し、
  そちらで収益化(アプリ内課金・広告)を行う。
- ゲームロジック・描画・アセット生成パイプラインは変更しない。
  「配信形態を増やす」だけの変更として扱う。

## 結果として生じるトレードオフ(Consequences)

- 良い点: 既存のコード・テスト・3Dモデル資産をほぼそのまま活かせる。
  Web 版とアプリ版を同じソースから両立できる。
- 悪い点:
  - ネイティブプロジェクト(`ios/` `android/`)の生成・ビルドには
    Xcode / Android Studio など、この開発環境(CI 含む)にないローカルの
    ネイティブツールチェインが要る。そのため `ios/` `android/` の
    生成そのものはこのセッションでは行わず、手順を README に残すに留める。
  - ストア審査(プライバシー要件・課金ポリシー等)への対応が新たに発生する。
  - タッチ操作向けの UI/UX 調整(仮想パッド・ボタン配置など)が別途必要になる。
    これは別の実装単位として `plan/` 側に仕様書を立てて扱う。

## 関連

- Capacitor 導入自体の作業(依存追加・`capacitor.config.ts` の追加)は
  別コミットで行う。
