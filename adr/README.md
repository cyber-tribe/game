# ADR (Architecture Decision Record)

技術的な意思決定を記録するディレクトリ。`design/` `plan/` がゲームの
仕様・設定を扱うのに対し、こちらは **「なぜこの技術・構成を選んだか」**
という判断とその根拠・トレードオフだけを扱う。

## いつ書くか

後から「なぜこうなっているのか」を追えないと困る技術判断をしたとき。
プラットフォーム・配信形態・主要ライブラリの採用など、覆すのに
手間がかかる決定が対象。実装の細部(変数名・関数分割など)は対象外。

## 書式

- ファイル名: `NNNN-短い-タイトル.md`(連番4桁)
- 内容: 背景(Context)・決定(Decision)・検討した代替案・
  結果として生じるトレードオフ(Consequences)
- 一度書いたら基本的に上書きしない。決定を覆したら新しい ADR を足し、
  古い方は冒頭に「`NNNN` により置き換え」と追記して残す
  (経緯そのものが記録として価値を持つため)。
