# 0008: Dependabotの更新はpatch/minorだけ自動マージし、majorは人が見る

- ステータス: 決定
- 日付: 2026-08-12

## 背景(Context)

`.github/dependabot.yml` により、npm依存(`package.json`)と
GitHub Actions(`ci.yml` `models.yml` の `uses:`)の更新を週1回まとめて
PRにしている。個人開発でこれを毎回すべて人手でレビュー・マージするのは
継続的な負担になり、放置すると依存関係が古びてセキュリティ更新も
遅れる。一方で、依存の更新は互換性を壊すリスクを常に伴う。

## 検討した選択肢

| 案 | 概要 | 評価 |
|---|---|---|
| **すべて自動マージする** | 更新種別を問わず、CIが通れば自動でマージする | 破壊的変更(major)まで無審査でマージされてしまい、CIがカバーしていない範囲(実行時の細かい挙動・型定義の互換性等)で問題が入り込むリスクが高い |
| **すべて人がレビューする** | 自動マージを一切使わず、毎回人が見てマージする | patch/minorのような低リスクな更新まで人手を要し、個人開発の運用負荷として見合わない。放置されて依存が古びるリスクの方が実害として大きい |
| **patch/minorだけ自動マージし、majorは人がレビューする** | `dependabot/fetch-metadata` で更新種別を取得し、`version-update:semver-major` でなければ `gh pr merge --auto --squash` で自動マージキューに載せる。実際のマージはCIの必須チェック(型・テスト・ビルド・実機での通しプレイ)通過後 | 破壊的変更が起きやすいmajorだけ人の判断を挟みつつ、大半を占めるpatch/minorの更新は自動で継続的に取り込める。semver の慣習(majorだけが後方互換を壊しうる)に沿った線引きで、実務上の負荷とリスクのバランスが取れる |

## 決定(Decision)

**`.github/workflows/dependabot-auto-merge.yml` は、Dependabotが開いた
PRのうち `dependabot/fetch-metadata` の `update-type` が
`version-update:semver-major` でないものだけを自動マージ有効化する。
major更新はここでは何もせず、PRを開いたままにして人が見る。**

- 実際にマージされるのは、ブランチ保護の必須ステータスチェック
  (`ci.yml` の型・テスト・ビルド、実機での通しプレイ)が通った後。
- `package.json` / `package-lock.json` の変更は `ci.yml` の `changes`
  ジョブで「コード」判定されるため、通常どおり型チェック・テスト・
  ビルド・通しプレイがそのまま走る(`adr/0007` のスキップ対象外)。
- 認証は追加のシークレットを増やさず、ワークフロー実行のたびに
  自動発行される `secrets.GITHUB_TOKEN` だけで完結させる。
- Blenderモデル生成にだけ使う `bpy`(Python)はバージョンを
  固定しておらず(`pip install bpy` で毎回最新を取得)、Dependabot の
  対象には含めていない。

## 結果として生じるトレードオフ(Consequences)

- 良い点:
  - patch/minorという大半を占める低リスクな更新を、人手を介さず
    継続的に取り込める。セキュリティパッチの反映も早くなる。
  - CIの必須チェック(実機での通しプレイを含む)を経てからしか
    マージされないため、自動マージであっても最低限の動作確認は
    通っている。
  - 追加のシークレットを増やさない方針を維持できている。
- 悪い点:
  - `update-type` の判定はDependabot(および `fetch-metadata`)の
    分類に依存しており、パッケージ側がsemverの慣習を守っていない
    場合(minorのはずが実質破壊的変更、等)は自動マージのすり抜けが
    起こりうる。
  - CIがカバーしていない範囲の非互換(型は通るが実行時の細かい挙動が
    変わる等)は、自動マージ後に初めて気づく可能性がある。
  - major更新はPRが開いたまま溜まりやすく、放置されると
    そちらはそちらで古びていく。定期的に人が見に行く運用が
    前提になる。
