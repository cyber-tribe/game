> **一覧5種のうち3種を実装済み(2種は見送り)。** `src/entities/costumes.ts`
> (新規。`CostumeDef`型・`COSTUMES`配列・`costumeById`)・`src/save.ts`
> (`SaveData.unlockedCostumes`・`SaveData.equippedCostume`・
> `refreshUnlockedCostumes`・`equipCostume`)・`src/view/actorView.ts`
> (`ActorView.applyTint`。メッシュのマテリアル色にRGB倍率を掛けるだけの
> 色替え)・`src/main.ts`(フロアに入り直すたびに、装備中の衣装の色替えを
> プレイヤーの見た目へ掛け直す)・`src/ui/town.ts`(拠点に「身支度」
> カラムを追加。未入手の衣装も一覧表示し、入手条件を隠さない)。
> テストは `tests/costumes.test.ts`(13件。`ActorView.applyTint`の
> マテリアル色計算も含む)。動作はPlaywrightで実際に3体の衣装へ
> 着せ替えて色の変化を確認した。
>
> 実装にあたって次の判断をした。
>
> - **「宵祭りの装束」「腕自慢のはちまき」は実装しなかった。**
>   前者は`design/village-festivals.md`の宵祭り参加回数を記録する仕組み
>   自体が無く、後者は`plan/hidden-dungeon.md`の腕試しの間そのものが
>   未実装で、どちらも代替となる既存の進行度指標が無いため
>   (`plan/multiple-dungeons.md`等で使った「最深到達記録で章クリアを
>   代替する」という手も、対応する実体験が無ければ意味を持たない)。
>   対象の仕組みが実装された時点で着手する。
> - **残り3種の入手条件は、実装済みの指標に置き換えた。**
>   「おキヨお手製のはっぴ」(図鑑コンプリート)は本文どおり
>   `isCompendiumComplete`をそのまま使えた。「山を静めた者の羽織」
>   (第四章クリア)は`plan/village-development.md`の村の発展段階4
>   (同文書内で「第四章クリア」の代替指標として既に採用済み)を流用。
>   「最古の夢へ寄り添う衣」(真の目覚め/postgame)は、`postgame`自体が
>   未実装のため、`plan/multiple-dungeons.md`の「夜ごとの夢」を
>   ある程度深く潜った記録(`nightlyDreamBestDepth >= 20`)で代替した。
> - **「テクスチャ・一部メッシュの差し替え」は行わず、既存メッシュの
>   マテリアル色にRGB倍率を掛けるだけの色替えで表現した。** Blender
>   パイプラインへのアクセスが無いこのセッションのスコープ外のため、
>   新規テクスチャは作らない(モンスター図鑑拡充・進化等、これまでの
>   「新規3Dモデルを作らない」判断と同じ理由)。ガルドモデルは
>   `MeshStandardMaterial.color`を直接持つ(テクスチャマップは使っていない)
>   ことを実機で確認しており、この技法がそのまま効く構成だった。
> - **色替えは全身のマテリアルに一律で掛けている。** 個々のメッシュが
>   服・肌・髪のどれに対応するかを判別する手がかりがモデルデータに無いため、
>   「服だけ」を狙い撃ちできない。肌・髪も含めて色味が変わる想定で、
>   はっきり区別がつくよう倍率を強めに振った。
> - **「持ち物ギャラリー」(`plan/gallery-mode.md`)は、この実装によって
>   衣装スロットが埋まったため、着手できる状態になった。** 別セッションで
>   `plan/archive/gallery-mode.md`の実装ノートに追記する形で仕上げる想定。

# 衣装・見た目カスタマイズ

これまでの装備(`plan/protagonist-equipment.md` `plan/protagonist-weapons.md`)
はすべて戦闘に効く実利装備だった。ここでは**戦闘に一切影響しない、
見た目だけの衣装**を追加し、やり込みの記念・気分転換の手段にする。
`design/balance-philosophy.md` のパワーバジェットに触れない、
もっとも安全に「量」を増やせる領域として位置づける。

## 位置づけ

- 衣装は武器・盾・頭防具・装身具のスロットとは独立した**もう1つの
  見た目スロット**であり、ステータスには一切影響しない。
- 入手経路はすべて**これまでの機能の達成の記念**にする。専用の
  通貨・ガチャ的な抽選要素は作らない(`design/balance-philosophy.md`
  の「操作の複雑さを大きく崩さない」方針、およびこの作品の素朴な
  トーンに合わせる)。

## 衣装一覧(初期案)

| 衣装 | 入手条件 |
|---|---|
| 普段着(既定) | 最初から |
| 宵祭りの装束 | `design/village-festivals.md` の宵祭りに一定回数参加する |
| おキヨお手製のはっぴ | `plan/monster-compendium.md` の図鑑を全種埋める |
| 山を静めた者の羽織 | `design/story.md` 第四章クリア |
| 最古の夢へ寄り添う衣 | `design/postgame.md` の「真の目覚め」を終える |
| 腕自慢のはちまき | `plan/hidden-dungeon.md` の腕試しの間を踏破する |

## モデル制作上の方針

README記載の「かがやきの夢のかけら」(色替えでレア個体を表現する手法)
と同じ考え方で、**既存のガルドモデルのテクスチャ・一部メッシュの
差し替えだけ**で表現し、新しいリグ・アニメーションクリップは作らない
(README記載の5クリップ構成をそのまま使い回す)。制作コストを抑えつつ
種類を増やせる。

## データ構造

```ts
export interface SaveData {
  // ...既存フィールド
  unlockedCostumes: string[];
  equippedCostume: string; // 既定は "default"
}
```

## UI

`design/ui-flow.md` の拠点メニューに「身支度」を追加し、未入手の衣装は
グレーアウトしつつ入手条件を表示する(`plan/achievements.md` と同じ
「隠さない」方針)。

## バランス上の注意

- 衣装は**いかなる数値にも触れない**ことを唯一かつ絶対の制約にする。
  将来「见た目だけでなく少し防御力も」といった誘惑が出ても、それは
  `plan/protagonist-equipment.md` の頭防具側の役目であり、衣装側に
  染み出させない。
