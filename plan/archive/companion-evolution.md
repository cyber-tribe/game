`plan/monster-fusion.md`(夢あわせ)と `plan/monster-compendium.md`
(種族拡充・特技/特性)を前提にした拡張。**夢あわせの「何を糧に選んだか」
によって、軸にした仲間が別の姿へ育つ**進化(この世界では **成熟(せいじゅく)**
と呼ぶ)を仕様化し、夢あわせに「誰を選ぶか」という戦略の深みを足す。

## 世界観との接続

夢のかけらは特定の感情・記憶が形を取ったもの(`plan/monster-compendium.md`)。
**別の性質の夢と長く寄り添う(夢あわせを重ねる)うちに、元の感情そのものが
変わっていく**、という理屈で成熟を説明する。たとえば「小さな不安」だった
ガジリねずみが、「古い記憶の頑固さ」(ホネガラミ)と何度も夢あわせを
繰り返すと、不安を乗り越えて**いしずえねずみ**という、動じない仲間へ育つ。
進化は単なるステータス上昇ではなく、**その仲間の性格そのものが変わる
物語**として描く。

## 進化条件

1. 軸にする仲間が、そのままの姿での**成熟レベル**(種族ごとに設定。目安
   レベル10前後)に達している。
2. 直近◯回(目安3回)の夢あわせで、**特定の種族を糧に選んでいる**
   (毎回同じ相手である必要はなく、同系統の相手を選び続けていれば発生する、
   という緩い条件にする。厳密な「直前の1回だけ」にすると事故が起きやすく、
   達成感より理不尽さが先に立つため)。
3. 条件を満たすと、次に夢あわせを行った瞬間に進化が発生する
   (進化専用の操作を増やさず、夢あわせの延長として自然に起こる)。

## 進化の効果

- **種族(`speciesId`)そのものが置き換わる。** 見た目のモデルも変わる
  (新規3Dモデルが必要)。
- ステータスは「その時点のレベル相当の、進化後種族の基礎値」に
  再計算する。**単純加算で強くなるのではなく、種族が持つ基礎値の
  カーブに乗り直す**形にすることで、`design/balance-philosophy.md` の
  パワーバジェット上限を素通りしない設計にする。
- AI挙動(`AiKind`)や特性が変わることがある。上記の例では
  `coward`(すぐ逃げる)から `guard`(その場を固める)に変わり、
  **性格が変わったことが遊びの上でも分かる**ようにする。
- 特技(SkillId)は、進化前に覚えていたものを1つまで持ち越せる
  (`plan/monster-fusion.md` の「1体が持てる特技は最大2つ」の枠内で扱う)。

## 具体例

| 進化前 | 主な糧の傾向 | 進化後 | 変化の要旨 |
|---|---|---|---|
| ガジリねずみ(不安) | ホネガラミ(古い記憶) | いしずえねずみ | `coward`→`guard`。不安を乗り越え、その場を守れるようになる |
| ぷるん(まどろみの余韻) | ぷるん同士(同種を重ねる) | とこしえのぷるん | 被弾軽減の特性が常時発動になる。ステータスは`melee`のまま底上げ |
| ぷるん(まどろみの余韻) | マドロミダケ(眠気そのもの) | ゆめみるぷるん | 攻撃に眠り付与が乗るようになる。2つの「まどろみ」系統が混ざる分岐 |

**同じ種族から出発しても、糧の選び方によって別の姿に育つ**(ぷるんの2例)
という分岐を設けているのが本仕様の核。全種族・全組み合わせの一覧化は
本文書の対象外とし、上記を雛形として実装時・追加コンテンツ制作時に
広げていく。

## データ構造

```ts
export interface EvolutionRule {
  fromSpeciesId: string;
  toSpeciesId: string;
  requiredLevel: number;
  /** 直近N回の夢あわせのうち、過半数がこの種族(または種族グループ)であること */
  triggerMaterial: string | string[];
  lookbackFusions: number; // 目安3
}
```

`StoredMonster`(`plan/monster-fusion.md`)に `recentFusionMaterials:
string[]`(直近数回分の糧の種族id、`lookbackFusions` 件だけ保持)を追加し、
夢あわせの処理の最後に `EvolutionRule` との照合を行う。

## 図鑑・その他機能との連携

- 進化後の姿も `plan/monster-compendium.md` の図鑑に別エントリとして
  登録される(進化前を捕まえただけでは「未確認」のまま)。図鑑コンプ
  リートの達成難度に厚みを持たせる。
- 進化後の個体は、`plan/equipment-forging.md` の刻印石(その種族由来の印)
  についても、進化前・進化後どちらの性質を刻めるかは**進化後の種族**の
  ものとして扱う(単純化のため)。

## バランス指針との整合

- 進化は「積み増し」ではなく「種族の置き換え」である点を必ず守る。
  進化後の基礎値がその地方の実効戦力カーブ(`design/balance-philosophy.md`)
  を大きく超えないよう、進化先の種族は**概ね1〜1.5地方分先**の強さに
  収める(例: 第一地方のぷるん由来の進化先は、第二地方相当の強さまで)。
- 進化を巡り合わせ待ちの運要素にしない。`lookbackFusions` を満たせば
  確実に発生する条件にし、「時間と工夫をかければ必ず届く」という
  `plan/equipment-forging.md` の強化値と同じ安心設計の思想を踏襲する。
