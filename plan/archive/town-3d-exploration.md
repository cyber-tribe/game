# 拠点(ネンネ村)の3D化

`design/village-life.md`の「拠点UIとの関係」は当初、「奥行きのある3D村を
作り込むのではなく、既存の一覧UIパターンの延長で『誰の所へ行くか』を
選ぶだけの軽い実装で足りる」としていた。実際に動いているビルドを見ると、
拠点は横並びのリスト列(倉庫/持ち込む/出発地点/鍛え方/つれていく仲間/
ゲンドの工房/…)が起動直後に一度に開くだけの画面になっており、ダンジョン
側の3D探索とのギャップが大きく、「歩き回る」というゲーム体験の核心を
損なっていた。ここで方針を転換し、**拠点もダンジョンと同じ3D空間として
歩き回れるようにする。**

## 基本方針: 入り口だけを差し替える

個々の施設の中身(倉庫の一覧選択、工房の強化画面、依頼板の一覧 等)は
**一切変更しない。** 変えるのは「その画面にどうやってたどり着くか」
だけにする。

- **現状**: 拠点を開くと、横並びの列がすべて同時に表示される。
- **変更後**: 村を3D空間として表示し、`src/view/` の既存の移動・
  カメラ・入力システムでそこを歩き回る。各施設(建物やNPC)に近づいて
  確定キー(Space)を押すと、**今と全く同じ一覧UI画面がそのまま開く。**

こうする理由は、既にたくさんの施設UIが実装済み(多くは
`plan/archive/` へ移動済み)であり、それらを作り直すコストを避けつつ、
「歩き回れる」という体験の核心部分だけを獲得できるため。

## 技術的な裏付け

- `src/view/` はダンジョンの3D描画・移動・カメラ・入力を既に持っている。
  村マップは**固定の1枚のレイアウト**でよく、ダンジョンのような
  ランダム生成(`src/dungeon/`)は不要なので、実装コストはダンジョン
  生成システムよりずっと低い(座標に建物モデルを配置するだけ)。
- モデル制作パイプライン(`tools/models/`、Blenderスクリプト)は確立
  済みで、村の建物・地形モデルも同じ方式で作れる。

## 村のレイアウト(施設・NPCの配置)

`design/village-life.md` のNPC一覧と、既存の施設群を、それぞれ対応する
建物または立ち位置として村マップに配置する。

| 施設/NPC | 対応する既存UI |
|---|---|
| モグラ婆(倉庫番) | 倉庫・持ち込む道具選択 |
| 樽転がしのゲンド | ゲンドの工房(強化・印) |
| 肝いりのオトネ | 依頼板 |
| 物知りのおキヨ | 図鑑小屋 |
| ひよっこのポチ / 目覚めたおたま | 会話・絆(個別の一覧UIは無い) |
| 洞窟の入口 | 出発準備(持ち込む/出発地点/鍛え方/つれていく仲間をまとめて) |
| 村の発展の受付・実績帳 | 該当する既存UI |

洞窟の入口に近づいて確定すると、「出発」に関連する複数の列(持ち込む・
出発地点・鍛え方・つれていく仲間)は**まとめて1つの準備画面として開く**
扱いにする(元々1つの出発フローとしてまとまっているため、分割しない)。

## 移動・操作

`plan/touch-controls.md` で設計した入力層(`Input.held` を介した
抽象化)は村でもそのまま使える。ダンジョンと同じキー割り当て(矢印/
WASD、確定=Space)を踏襲し、プレイヤーが新しく覚える操作を増やさない。

## 段階的な進め方

- **第一段階(本文書の対象)**: 村を3D化し、歩いて各施設に近づいて
  確定すると既存のメニュー画面がそのまま開く。個々のメニューの中身は
  変えない。
- **将来の拡張(未決事項・対象外)**: NPCに近づくと一言喋る演出、
  `design/yorishiro-moods.md` の気分による村の見た目変化、時間帯演出、
  `plan/village-development.md` の発展段階に応じた建物の増改築の視覚的
  反映、等。村が3D化されて初めて活きる要素だが、実装コストが増えるため
  本文書の対象外とし、村が3D化された後に個別に仕様化する。

## 既存文書の更新

- `design/village-life.md` の「拠点UIとの関係」: 3D村を作らない、と
  していた記述を撤回し、本文書を参照する形に更新する。
- `design/ui-flow.md` の「全体の画面遷移」図: 村の中の項目を「歩いて
  各施設へ」という形に更新する。

## 対象外

- 施設UI個別の作り直し(タッチ対応含む。`plan/touch-controls.md` の
  「タップ=カーソルを合わせて確定」の規則がそのまま適用される)
- NPCの演出・会話内容の追加(`design/side-stories.md` 等、既存の設計を
  変えない)
- 村の外観・建物モデルの具体的なデザイン(実装時、または別途デザイン
  文書で扱う)

## 未決事項

- 村マップの広さ・移動にかかる時間感(施設間の移動が長すぎるとテンポを
  損なう。ダンジョン1フロアより小さく保つ、程度の目安は示すが具体的な
  数値は実装時に調整する)
- 建物へ「入る」演出(一言メッセージのみか、内部に入る短い画面遷移を
  作るか)
- 出発準備の複数列を1画面にまとめたままにするか、洞窟の入口に着く前に
  個別の立ち寄り(道具は倉庫の前で、仲間はねむり小屋の前で、等)に
  分割するか
- 村の発展段階が上がったとき、村マップの見た目(建物の増改築)をどう
  反映するか
