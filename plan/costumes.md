# 衣装・見た目カスタマイズ

これまでの装備(`plan/protagonist-equipment.md` `plan/protagonist-weapons.md`)
はすべて戦闘に効く実利装備だった。ここでは**戦闘に一切影響しない、
見た目だけの衣装**を追加し、やり込みの記念・気分転換の手段にする。
`design/balance-philosophy.md` のパワーバジェットに触れない、
もっとも安全に「量」を増やせる領域として位置づける。

## 位置づけ

- 衣装は武器・盾・頭防具・装身具のスロットとは独立した**もう1つの
  見た目スロット**であり、ステータスには一切影響しない。
- 入手経路はすべて**これまでの機能の達成の記念**にする。専用の
  通貨・ガチャ的な抽選要素は作らない(`design/balance-philosophy.md`
  の「操作の複雑さを大きく崩さない」方針、およびこの作品の素朴な
  トーンに合わせる)。

## 衣装一覧(初期案)

|---|---|
| 普段着(既定) | 最初から |
| 宵祭りの装束 | `design/village-festivals.md` の宵祭りに一定回数参加する |

| 腕自慢のはちまき | `plan/hidden-dungeon.md` の腕試しの間を踏破する |

## モデル制作上の方針

README記載の「かがやきの夢のかけら」(色替えでレア個体を表現する手法)
と同じ考え方で、**既存のガルドモデルのテクスチャ・一部メッシュの
差し替えだけ**で表現し、新しいリグ・アニメーションクリップは作らない
(README記載の5クリップ構成をそのまま使い回す)。制作コストを抑えつつ
種類を増やせる。

## データ構造

```ts
export interface SaveData {
  // ...既存フィールド
  unlockedCostumes: string[];
  equippedCostume: string; // 既定は "default"
}
```

## UI

`design/ui-flow.md` の拠点メニューに「身支度」を追加し、未入手の衣装は
グレーアウトしつつ入手条件を表示する(`plan/achievements.md` と同じ
「隠さない」方針)。

## バランス上の注意

- 衣装は**いかなる数値にも触れない**ことを唯一かつ絶対の制約にする。
  将来「见た目だけでなく少し防御力も」といった誘惑が出ても、それは
  `plan/protagonist-equipment.md` の頭防具側の役目であり、衣装側に
  染み出させない。
