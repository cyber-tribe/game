# 戦闘パーティクルVFX(ヒットスパーク・消滅・砂埃)

## 経緯

描画品質を家庭用機水準へ近づける施策の第4弾(第1〜3弾:
トゥーン化・ポストプロセス・リムライト+接地影)。

静止画の品質はここまでの施策で引き上がるが、**家庭用機との差を
プレイヤーが最も体感するのは戦闘の瞬間**である。現状の戦闘演出は
「攻撃側が踏み込む(lunge)+被弾側が傾く(hitクリップ)+赤フラッシュ
+ダメージ数字」だけで、打撃の重さ・手応えが画面に出ていない。
`src/view/`にパーティクル・スプライトの類は一切存在しない
(唯一の例外は`stage.ts`の`spawnExplosion`=拡大する半透明球)。

## 現状の土台

- `src/view/stage.ts`がゲームイベントを見た目に変換する唯一の場所で、
  フックはすべて揃っている:
  - `attack`(踏み込み)/ `damage`(被弾+フラッシュ+数字)/
    `die`(倒れるクリップ+`dying`タイマー)/ `explosion`(拡大球)
  - エフェクト置き場の`effectRoot`(`THREE.Group`)も既にある。
- `damage`イベントはワールド座標(`view.root.position`)を既に計算
  しており、パーティクル発生位置にそのまま使える。
- ポストプロセス計画のブルームが入ると、加算合成の明るい粒は
  自動的ににじんで光る(相乗効果が大きい。実装順はブルームが先でも
  後でもよいが、パラメータ調整はブルーム導入後に行うのが二度手間がない)。

## 修正方針

### パーティクルシステム本体(`src/view/particles.ts`を新設)

1種類の`THREE.Points`+`ShaderMaterial`をエフェクト種別ごとに1つ持ち、
固定長のリングバッファで粒を使い回す(生成・破棄をしない)。

```
ParticleSystem
  ├─ spark:  加算合成・明るい橙白・重力なし・放射状に散って減速
  ├─ burst:  加算合成・種族の体色・軽い上昇→落下・消滅演出用
  └─ dust:   通常合成・薄い土色・ゆっくり広がって消える
```

- 各粒の属性(発生位置・初速・寿命・サイズ)は`BufferAttribute`に書き、
  以降の位置計算は頂点シェーダーで`age`から算出する(CPU側は
  毎フレーム`uniform time`を進めるだけ。粒ごとのJS計算をしない)。
- 上限は種別ごとに256粒。あふれたら古い粒を上書きする。
- 描画コールはエフェクト種別ごとに1回(計3回)で固定。モバイルでも
  負荷が読める。
- テクスチャは接地影計画と同じ方式で、放射状グラデーションの丸を
  コードから1枚生成して共有する。

### イベントへの接続(`stage.ts`)

| イベント | 追加する演出 |
|---|---|
| `damage` | 被弾位置に`spark`を8〜12粒、攻撃方向へ扇状に散らす。`critical`時は粒数・サイズを1.5倍 |
| `die` | `dying`タイマー満了時(モデルが消える瞬間)に`burst`を20粒前後、体色で放つ。「夢のかけらが散る」世界観の見せ場 |
| 歩行 | `ActorView`の移動完了時に足元へ`dust`を2〜3粒。プレイヤーと大型モンスターのみ(小型・浮遊系は出さない) |
| `explosion` | 既存の拡大球に`spark`大量発生を重ねる(球は残す) |

- `burst`の「体色」は、モデルの最初のマテリアルの`color`を
  `Assets`から引く(種族ごとの専用色テーブルは作らない)。
- 遠隔攻撃(`ranged`)の弾の飛翔体表現は現状存在しない(`attack`
  イベントに射程の区別がない)。弾トレイルはイベント側の拡張が要る
  ため今回のスコープから外す(対象外)。

### 更新ループ

`stage.ts`の毎フレーム更新から`particles.update(dt)`を呼ぶ。
`uniform`の時刻更新のみで、粒が0のときのコストは実質ゼロ。

## 受け入れ基準

1. 攻撃が当たった瞬間、被弾位置から火花が散る(クリティカル時は
   明確に派手になる)。
2. モンスターを倒すと、消える瞬間に体色の粒が散る。
3. プレイヤーの歩行で足元に砂埃が立つ(毎歩ではうるさければ間引く)。
4. 爆発が従来より明確に「爆発らしく」見える。
5. パーティクル追加後もスマホ実機で体感できるフレームレート低下がない。
6. 階を降りても粒・ジオメトリがリークしない(`effectRoot`と同様に
   フロア遷移で状態がリセットされる)。
7. `npm run test`・`npm run typecheck`・`npm run build`がすべてgreen。

## 対象外

- 遠隔攻撃の弾の飛翔体・トレイル(イベントデータの拡張が必要なため、
  別の決定として扱う)。
- 状態異常(眠り・混乱)の常時表示アイコン的なパーティクル。
- 天候・環境の環境パーティクル(浮遊塵など)。効果はあるが、まず
  戦闘の手応えを優先する。

## 未決事項

- 粒数・寿命・サイズ・色の最終値(ブルーム導入後の見た目で詰める)。
- 歩行砂埃を出す種族の線引き(「大型」の判定をバウンディングボックス
  で機械的にやるか、種族フラグにするか)。
- `reduce motion`(OSのアニメーション減設定)への配慮を入れるか。
