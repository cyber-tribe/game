# 拠点パネルがセーフエリアを考慮せず、ノッチ側の見切れ・ハンバーガーボタンとの重なりを起こす問題を直す

## 経緯

「メニューが画面内に収まってません」という指摘(添付は`洞窟の入口`
=出発の支度画面。6列と、拠点の全建物中もっとも列数が多い)。同じ
スクリーンショットで、右側の列のテキストに「≡」ボタンが重なって
見える現象も確認できる。

## 診断

`index.html`の`.town-box`の基本サイズ定義:

```css
.town-box {
  width: min(1180px, 96vw);
  max-height: 92vh;
  ...
}
```

**`--safe-left`/`--safe-right`を一切差し引いていない。** 96vwは
画面の物理的な横幅全体に対する割合で、ノッチ・ホームインジケータ
ぶんの余白(セーフエリア)を考慮しない。列数が少ない建物
(1〜2列)ではパネル自体が十分小さく収まるため問題が表面化しないが、
**列数が最多(6列)の`洞窟の入口`ではパネルが最大幅(1180px)まで
育ちやすく**、ノッチのある横向きの画面で以下の2つの症状が同時に
起きる:

1. パネルの片端がノッチ側の物理的な角に近づき、列の内容が見切れる
   (`interior-panel-safe-area-left.md`で内装パネルに施した対応と
   同種の問題が、拠点のメイン`.town-box`にも残っていた)。
2. パネルの反対側の端が、常に画面右上に固定表示される「≡」ボタン
   (`.touch-menu-btn`、`right: calc(16px + var(--safe-right))`)の
   領域まで届き、ボタンがパネルより手前(拠点画面が開いている間は
   `#ui.town-open #touch { z-index: 31; }`でジョイスティック操作を
   通すため意図的に手前に出している)ため、列のテキストの上に
   重なって表示される。

「≡」ボタン自体を手前に出す設計は、拠点画面でも仮想パッド・決定・
もどるを操作可能にするための意図的な対応(issue #483)であり、
そちらは変更しない。**直すべきは、パネル側がその領域を避けて
描かれるようにすること。**

## 修正方針

- `.town-box`の幅の計算にセーフエリアを差し引く:
  `width: min(1180px, calc(96vw - var(--safe-left) - var(--safe-right)))`
- あわせて、`.touch-menu-btn`が陣取る右上の領域(幅42px+余白16px、
  ミニマップ用に既にある`--zone-tr-reserve`と同種の考え方)を、
  `pointer: coarse`かつ拠点画面が開いているときだけ`.town-box`の
  右上に確保する。具体的には`#ui.town-open`かつ
  `@media (pointer: coarse)`の条件で、`.town-columns`(またはパネル
  自体)に`padding-right`を追加し、ボタンの footprint と重ならない
  余白を作る。
- `#ui.village-interior .town-box`は`interior-panel-safe-area-
  left.md`で左側の対応が既に入っているため、本書は**拠点のメイン
  `.town-box`(内装でない、村の広場・洞窟の入口等で使う既定の
  スタイル)**を対象にする。

## 受け入れ基準

1. iPhone実機の横向き(ノッチが画面左右どちらに来る向きでも)で、
   `洞窟の入口`(6列)のすべての列が見切れずに読める。
2. 「≡」ボタンが、パネルのどの列のテキストにも重ならない。
3. 列数の少ない他の建物(旅の看板・村の広場等)の見た目に変化がない
   (パネルが元々小さいため、今回の余白計算が影響しない)。
4. デスクトップ(`pointer: fine`、「≡」ボタン非表示)では見た目が
   変わらない。

## 対象外

- `#ui.village-interior .town-box`(`interior-panel-safe-area-
  left.md`で対応済み、変更なし)
- 「≡」ボタン自体の位置・拠点画面での手前表示の仕組み(issue #483の
  対応はそのまま維持する)

## 未決事項

  決める)
