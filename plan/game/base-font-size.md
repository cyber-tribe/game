# ベースフォントサイズの概念を導入し、文字サイズを1箇所から制御する

## 経緯

「ベースフォントサイズの概念を導入してください」という指示。
UIの文字サイズを個別のpx直書きでなく、基準値(ベース)からの
相対指定に統一する。

## 診断(実測)

`index.html`の現状:

- `font-size`宣言が**94箇所**、うち約80箇所がpxの直書き。
- 使われている値は**18種類**(9.5 / 10 / 10.5 / 11 / 11.5 / 12 /
  12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 17 / 18 / 20 / 22 / 27 / 30px)。
  11〜13px帯に近接値が密集しており、「なんとなく選んだ値」が
  積み重なった状態。基準が無いため、新しいパネルを足すたびに
  また別の値が生まれる。
- 文字サイズのアクセシビリティ設定(`plan/difficulty-modes.md`由来、
  保存値`fontSize: "normal" | "large"`)は、
  `body[data-font-size="large"] #log, ... {zoom: 1.25}`という
  **14セレクタの列挙**で実装されている。列挙に入っていない画面
  (HUD・タッチUI・新設パネル)には効かず、パネルを追加するたびに
  列挙へ足し忘れるリスクがある。`zoom`は余白ごと拡大するため
  レイアウト崩れの温床でもある。

## 変更内容

### 1. ベース値を1つ定義し、remで参照する

- `:root`(または`html`)に基準を置く:
  `html { font-size: var(--font-base, 13px); }`
  (13pxは現状の最頻値帯11〜13pxの上端。実装時に見た目を比較して
  12〜14pxの範囲で確定してよい)。
- すべての`font-size: NNpx`を**rem指定に置換**する
  (`13px → 1rem`、`11px → 0.85rem`のように、ベース13px換算で
  機械的に変換する)。

### 2. 値を型スケールに整理する

- 18種類の値を、役割ベースの**6〜7段のスケール**に集約する
  (数値はベース13px時の目安。近接値は最寄りの段へ寄せる):

  | トークン | rem | px相当 | 用途の目安 |
  |---|---|---|---|
  | `--fs-xs` | 0.8rem | ≈10.5px | 補足・ヒント・脚注 |
  | `--fs-sm` | 0.88rem | ≈11.5px | HUDのサブ情報・ラベル |
  | `--fs-md` | 1rem | 13px | 本文・メニュー項目(既定) |
  | `--fs-lg` | 1.15rem | ≈15px | 見出し小・強調(階数表示等) |
  | `--fs-xl` | 1.4rem | ≈18px | パネル見出し |
  | `--fs-2xl` | 1.7rem | ≈22px | 拠点タイトル等の大見出し |
  | `--fs-3xl` | 2.3rem | ≈30px | 演出的な特大(エンディング等) |

- ダメージポップ(20/27px)のような**演出用の例外**は、スケール外の
  rem直指定を許すが、必ずremで書く(pxを残さない)。
- 9.5px(タッチUIの1箇所)のような極小値は、可読性の観点からも
  `--fs-xs`へ吸収できないか実装時に確認する。

### 3. 文字拡大設定をベース差し替えに置き換える

- `data-font-size`属性の付与先を`document.body`から
  `document.documentElement`へ移し(`src/main.ts:1393`)、
  `html[data-font-size="large"] { font-size: calc(var(--font-base) * 1.25); }`
  の**1行**で全UIを拡大する。
- 現行の14セレクタ列挙+`zoom: 1.25`は削除する。これにより
  列挙漏れ(HUD・タッチUI・今後の新設パネル)が構造的に消える。
- `zoom`は余白ごと拡大していたため、rem化後は「文字だけが
  大きくなり、箱は内容に応じて伸びる」挙動に変わる。既存の
  large設定利用者にとっては見え方が変わるが、標準的で崩れにくい
  挙動への移行として受け入れる(パネルの`max-height`・スクロールは
  既存のまま働く)。

### 4. モバイル圧縮モードの整理(同PR内・最小限)

- `@media (pointer: coarse)`帯の個別`font-size`縮小(10.5px等の
  多数の上書き)は、可能な範囲でトークンの差し替え
  (例: その帯だけ`--fs-sm`を一段下げる)に寄せる。ただし
  全面的な再設計はせず、**px→remの機械変換を優先**し、トークンへの
  寄せは近接値の統合で自然にできる範囲に留める(見た目を大きく
  変えないことが今回の主目的のため)。

### 5. 規律

- 以後、`index.html`(および将来のCSS)で`font-size`をpxで
  直書きすることを禁止し、トークン(`--fs-*`)またはremのみとする。
  この規律を本書に定め、実装PRのレビュー観点とする。

## 受け入れ基準

1. `font-size`のpx直書きが`index.html`から無くなる(grepで0件)。
2. 既定状態の見た目が実質変わらない(主要画面の新旧
   スクリーンショット比較で、1px未満の丸め差以外に変化が無い)。
3. 文字サイズ設定「大きい」が、HUD・タッチUI・拠点・すべての
   確認ダイアログに効く(現行は列挙14箇所のみ)。
4. `zoom`によるレイアウト拡大が廃止され、largeでもパネルが
   画面からはみ出さない(モバイル横向きで確認)。
5. 新しい`font-size`値を追加する場合の規律(トークン/remのみ)が
   本書で参照できる。

## 対象外

- 余白(`padding`/`margin`)・行間のrem化(文字サイズのみを対象と
  する。余白のスケール化は必要になったら別途)
- 型スケールの段数・比率の凝った設計(まず現状の近接値統合として
  導入し、見た目の変更は最小限にする)
- フォントファミリーの変更

## 未決事項

- `--font-base`の最終値(13pxをたたき台に、実機の見た目で12〜14pxの
  範囲で確定)
- large倍率1.25の維持か見直しか(rem化で効く範囲が広がるため、
  1.15前後に下げたほうが破綻しにくい可能性。実機で確認して決める)
