# スマホ版の画面構成を全面的に見直す

## 実装ノート(実装セッションによる追記)

このセクションはあとから実装したセッションが追記した。以下、下の
「未決事項」への回答も含め、実装内容と決定事項をまとめる。

### 1. HUDバー

`index.html`の`#status`(既存のDOM・`src/view/hud.ts`のJSはそのまま)を
`@media (pointer: coarse)`だけでflexの横並びに組み替えた。階数・Lv・HP
(テキスト+幅34pxの小さいバー)・まんぷく(同様)を1行(目安どおり
高さ40px、状態異常やタル持ちで文字が増えると自動で2行に折り返す)に
収めた。**次のLvまでの数値(`#hud-exp`)は触UIでは非表示にした**
(未決事項「HUDバーに満腹度・所持金までを含めるか」への回答: 満腹度は
含めるが、経験値の残数は優先度が低いと判断して省いた。所持金はもともと
HUDに出ていないため対象外)。「なかま」パネル(`#allies`)はHUDバーの下へ
寄せ、`max-height`+`overflow-y:auto`で下のゾーンを侵食しないようにした。

satietyの表示は仕様書が例示した「アイコン+数値」ではなく、既存の
短い日本語ラベル(「まんぷく」)+数値のままにした。絵文字アイコンを
新設するより既存のt()文言を流用するほうが実装・保守コストが低く、
文字数もアイコンと大差ないため。

### 2. ミニマップ

`#minimap-wrap`を`@media (pointer: coarse)`で縮小(`height:
min(25vh, 25vw, 92px)`、`aspect-ratio`でcanvasの縦横比を保持。横持ち
前提なので短辺=vhを基準にしており、目安の「短辺の1/4以下」を満たす)し、
背景の不透明度を0.82→0.4へ下げた。

**未決事項「タップで拡大/縮小」は実装した。** `src/ui/minimap-zoom.ts`が
クリックのたびに`#minimap-wrap`へ`expanded`クラスを付け外すだけの薄い
配線で、拡大時のサイズもCSS(`#minimap-wrap.expanded #minimap`)側に
留めてある。状態をクラス1つで表現でき、`src/ui/orientation-guard.ts`と
同じ「ロジックはDOMに持たせる」形に収まったため、コストが低いと判断して
採用した。拡大時は「≡」ボタン・メニューの位置もその分下げる必要があるため、
`body:has(#minimap-wrap.expanded)`で`--zone-tr-reserve`を切り替えている
(`:has()`はChromium 105+/Safari 15.4+/Firefox 121+が対象。非対応環境では
単に拡大自体が起きないため実害はない)。

### 3. メッセージ帯 + 全文ログモーダル

- **フェードアウトまでの秒数は4秒を採用した**(未決事項の3〜5秒案の
  中央値。`src/entities/messageBanner.ts`の`BANNER_FADE_MS`)。
- **表示行数は3行**(`BANNER_LINE_COUNT`)。
- 状態遷移(「新しいメッセージで表示に戻す」「フェードアウトする」)は
  `src/entities/messageBanner.ts`に純粋関数として切り出し、
  `tests/messageBanner.test.ts`でテストした。実際のタイマー配線
  (`setTimeout`)は`src/view/hud.ts`側に置いてある。
- `src/view/hud.ts`の`log()`は、既存の`this.lines`(デスクトップの
  `#log`・バグ報告ボタン用`recentLog`、最大6件)とは別に、
  `this.fullLines`(最大300件)という新しい履歴を持つ。この履歴から
  直近3行を`#logBanner`に出し、全件を`#logModal`(「≡」→「ログ」で
  開く全画面モーダル)に出す。デスクトップの`#log`・`recentLog`の
  挙動・件数は一切変えていない。
- 全文ログモーダルは、開いた時点の履歴をリスト化して末尾(最新)へ
  自動スクロールする。閉じるボタンタップ・背景タップの両方で閉じられる。
- `src/ui/touch-controls.ts`の「≡」メニューに、既存のキーコード方式
  (`data-code`→`Input.press/release`)に乗らない専用の「ログ」項目を
  追加し、`TouchControls`のコンストラクタに`onOpenLog`コールバックを
  増やした(`main.ts`から`() => this.hud.showLogModal()`を渡す)。
- 副次的に見つかった問題として、「≡」メニューの項目が6個に増えたことで
  画面の縦が短い端末(横持ちで高さ400px級)ではメニューが画面下に
  はみ出す場合があったため、`.touch-menu`に`max-height`+
  `overflow-y:auto`を追加してスクロールで全項目に到達できるようにした。

### 4. 文言のタッチ対応

`src/entities/inputText.ts`(`TextVariant` = `{ keyboard, touch }`と
`resolveText()`)を土台に、`src/ui/inputMode.ts`の
`currentInputMode()`(`matchMedia("(pointer: coarse)")`を都度引くだけの
薄い関数)で出し分けている。

**変換した文言:**
- `src/core/tutorial.ts`の`TUTORIAL_TIPS`全11件を`TextVariant`化。
  キー名を含むのは`moveAndAttack`(矢印/WASD/Xキー→パッド/攻撃ボタン)・
  `pickup`(Space→決定ボタン)・`barrel`(F/G→タル/投げるボタン)・
  `allyOrders`(Tキー→「≡」メニュー)の4件で、実際に言い換えた。
  残り7件はもともとキー名を含まないため、両方に同じ文面を置いてある
  (型を揃えるため。呼び出し側はどちらの入力方式でも同じ`tutorialTipText()`
  を通せばよい)。
- `src/entities/settings.ts`に`KEY_REFERENCE_TOUCH`を新設し、
  `src/main.ts`の「H」キー一括確認(`showKeyHelp`)と
  `src/ui/town.ts`の拠点設定画面「キー配置を確認する」の両方で、
  タッチ端末なら`KEY_REFERENCE`の代わりにこちらを表示する。
- ゲームオーバー・踏破・樽比べ終了の3オーバーレイの「R キーで拠点に
  もどる」(`src/main.ts`の`RETURN_TO_TOWN_HINT`)。タッチ版は
  「「拠点にもどる」ボタンで戻れる」とした。ボタン自体の追加は
  `plan/game/gameover-touch-return.md`側の担当(このPRの時点で未実装の
  場合がある)だが、文言の出し分けは経緯どおりこちらで行った。
- 拠点(村)を歩いているときの入店案内(`villageHintEl`)「Space: ○○へ」
  →タッチでは「決定ボタン: ○○へ」。
- 操作説明オーバーレイのフッター「Hでとじる」→タッチでは
  「「≡」→操作説明でとじる」。**あわせて、タッチ端末ではオーバーレイ
  自体をタップしても閉じられるようにした**(`Hud.showKeyHelp`に
  `onClose`コールバックを追加)。オーバーレイが全画面を覆うため、
  「≡」ボタン自体がその下に隠れて押せなくなり、閉じる手段が無くなる
  (行き止まりになる)ことに実装中の確認作業で気づいたための追加対応。
  ゲームオーバー等の`showOverlay`側にはこの自動クローズを付けていない
  (タップ即クローズにすると`gameover-touch-return.md`が別途入れる
  「拠点にもどる」ボタンの処理を経由しない中途半端な状態遷移になるため)。

**あえてタッチ対応しなかった文言:** 拠点画面(`TownScreen`)下部の
ヒント文(`ui.settings.hint`の「← 列を移る / ↑↓ 選ぶ / Enter
切り替え・一覧を見る / Space もぐる」等)。拠点画面はもともとタッチでは
タップ操作(`#308`)に置き換わっており、このヒント文自体は主にキーボード
利用者向けの補足情報という位置づけのため、今回は対象から外した
(全部を変換すると際限が無くなるため、doc本文が明示したtutorialTip・
R/Space/Xキーのメッセージ・`KEY_REFERENCE`を優先した)。

### 5. セーフエリア対応

`index.html`のviewport metaに`viewport-fit=cover`を追加し、今回
再配置した各ゾーン(HUDバー・ミニマップ・メッセージ帯・仮想パッド・
アクションボタン・「≡」ボタン/メニュー・全文ログモーダル)のオフセットに
`env(safe-area-inset-*)`を足した。いずれも`@media (pointer: coarse)`
またはそもそも触UI限定の要素の中でのみ足しており、デスクトップには
影響しない。

### 検証したこと・できなかったこと

- `npx tsc --noEmit` / `npx vitest run` / `npm run build` はすべて成功。
- Playwrightのヘッドレスブラウザ(`hasTouch: true`・800×400のスマホ
  横持ちビューポート)で実際に`npm run dev`を操作し、以下を確認した:
  HUDバー・ミニマップ・メッセージ帯・仮想パッド・アクションボタンの
  どの2つも矩形が重ならないこと/ミニマップのタップ拡大/「≡」→「ログ」で
  全文ログモーダルが開閉すること/チュートリアルtipにキー名が出ない
  こと/操作説明(タッチ版)にキー名が出ずオーバーレイタップで閉じられる
  こと/メッセージ帯が無操作4秒程度でfadedクラスになること。
  同じ手順を`hasTouch: false`・1280×800のデスクトップビューポートでも
  実行し、`#status`の幅が従来どおり(232px近辺)であること・`#log`が
  従来どおり表示されキー名入りの文言のままであること・`#logBanner`が
  非表示のままであること・`#touch`が`display:none`のままであることを
  確認した。
- 一方で、これはヘッドレスブラウザでの機械的な確認であり、実機での
  タップの押しやすさ・文字の可読性・ノッチ機種でのセーフエリアの
  見え方(手元にiPhone実機が無く、`env(safe-area-inset-*)`が実際に
  ノッチ回避として機能しているかは未確認)は検証できていない。
  受け入れ基準にあるとおり、最終的な確認は実機で行う必要がある。

## 経緯

タッチUI(`plan/game/archive/touch-controls.md`)と重なり対策
(`plan/game/archive/touch-ui-overlap-fix.md`)を入れた後の実機
スクリーンショットでも、ゲームアプリとして快適といえる画面に
なっていない。具体的には:

1. **メッセージログがHUD(階数・HP)に覆いかぶさる。** ログは
   行数が増えると上へ伸び、左上のHUDパネルを完全に隠す。
2. **ログが画面の1/3近くを占有し、盤面が見えない。** デスクトップの
   「左側に縦長のログ」をそのまま持ち込んでいるのが原因。
3. **チュートリアル文がキーボード前提。**「矢印かWASDで歩けるよ」
   「Xキーで攻撃できる」という文言が、キーボードの無い端末で
   そのまま出る。
4. **ミニマップが大きく、始めたばかりの階では中身がほぼ空。**
5. 終了オーバーレイ等の文言も「R キーで」「Space:」とキーボード
   前提(タップ可能なボタンの追加は
   `plan/game/gameover-touch-return.md` で別途扱う)。

## 方針: スマホ用は「重ねる」のではなく「別レイアウトを組む」

これまでの「デスクトップのパネル配置を基本にして、タッチ端末では
予約マージンでずらす」やり方(`--zone-tr-reserve` 等)は限界なので、
`@media (pointer: coarse)` ではパネルの寸法・位置・挙動そのものを
モバイル向けに切り替える。

### ゾーン割り(横持ち)

```
+--------------------------------------------------+
| [HUDバー]                       [ミニマップ(小)] |
|                                                  |
|                 (盤面 = 最優先)                  |
|                                                  |
| [仮想パッド]  [メッセージ帯(中央下)] [ボタン群] |
+--------------------------------------------------+
```

- **HUDバー(左上)**: 現在の縦積みパネルをやめ、
  「B1F・Lv1・HPバー」を1行に収めた**細長い横バー**にする。
  高さの目安は40px前後。満腹度などの追加情報はバー内にアイコン+
  数値で詰める。
- **ミニマップ(右上)**: 現在より一回り小さくし(目安: 短辺の
  1/4以下)、背景の透過を強める。タップで拡大/縮小をトグル
  できるとなおよい(未決事項)。
- **メッセージ(中央下の帯)**: 縦長ログパネルを廃止し、
  **最新2〜3行だけを表示する半透明の帯**を画面下部中央
  (パッドとボタン群の間)に置く。新しい行が来たら古い行を
  押し出し、**数秒操作が無ければ帯ごとフェードアウト**する。
  過去ログ全文は「≡」メニューの「ログ」から全画面で読める
  ようにする(スクロール可能)。
- **仮想パッド(左下)・アクションボタン(右下)**: 現状の配置を
  維持。メッセージ帯とはゾーンが分かれているため重ならない。

### 文言のタッチ対応

キー名を含むテキストを、タッチUI有効時はボタン名に差し替える。

- チュートリアルtip(`src/game.ts`の`tutorialTip`系)と
  ゲーム内メッセージのうち、「矢印/WASD」「Xキー」「Spaceキー」等の
  キー名を含むものを対象に、**入力方式(タッチ/キーボード)ごとの
  2パターンの文面**を持てる仕組みにする。例:
  - キーボード:「Xキーで、向いている方向へ攻撃できる。」
  - タッチ:「攻撃ボタンで、向いている方向へ攻撃できる。」
- 判定は既存のタッチUI表示条件(`pointer: coarse`)と同じで良い。
- 操作説明一覧(`src/entities/settings.ts`の`KEY_REFERENCE`)にも
  タッチ版一覧を用意し、タッチ端末の「≡」メニュー・拠点設定画面
  ではそちらを表示する。

### セーフエリア対応

PWA化(`plan/game/pwa-support.md`)で全画面表示になると、iPhoneの
ノッチ・ホームインジケータ領域にUIが食い込む。各ゾーンの端の
オフセットに `env(safe-area-inset-*)` を加算しておく
(`viewport-fit=cover` をviewport metaに追加する)。

## 受け入れ基準

1. スマホ横持ちで、HUD・ミニマップ・メッセージ・パッド・ボタンの
   **どの2つも重ならない**(ログが何行たまっても)。
2. 盤面(3Dビュー)を遮るのは半透明の帯・小パネルのみで、
   プレイヤーと周囲8マスが常に見える。
3. キーボードのキー名がタッチ端末の画面に一切出ない。
4. メッセージ帯は放置でフェードアウトし、全文ログは「≡」→ログで
   読める。
5. デスクトップ(pointer: fine)の表示・挙動は変わらない。

## 対象外

- 縦持ちレイアウト(引き続き「横向きにしてください」案内で対応)
- 終了オーバーレイへのタップボタン追加
  (`plan/game/gameover-touch-return.md`)
- 文字選択・ズーム誤発動の防止(`plan/game/touch-gesture-guard.md`)
