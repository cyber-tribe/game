# チュートリアル設計

> **実装済み。** `src/core/tutorial.ts`(ヒントIDと文面)・`src/core/events.ts`
> (`tutorialTip` イベント)・`src/game.ts`(各状況での発行)・
> `src/items/effects.ts`(状態異常付与時の発行)・`src/save.ts`
> (`seenTutorialTips` の永続化)・`src/main.ts`(既読判定・表示)。
> テストは `tests/tutorial.test.ts`。
>
> 実装時の簡略化・保留:
> - Game はセーブデータを持たないため、`tutorialTip` イベントは
>   `checkpoint` イベントと同じ設計で「毎回無条件に発行」し、
>   「初めてかどうか」の判定・既読管理は main.ts 側(`showTutorialTip`)に
>   委ねている。
> - 「ものを拾う」「タルを持ち上げる/投げる」は、それぞれ
>   「初めて見えたとき」「初めて隣接したとき」ではなく、実装コストを
>   抑えるため「初めて拾ったとき」「初めて持ち上げたとき」に簡略化した。
> - 「モンスターを弱らせてから樽をぶつける」は「最初のモンスターと
>   遭遇したとき」ではなく「プレイヤーが初めてモンスターを攻撃したとき」
>   に簡略化した(視界内への出現検知は追加コストが大きいため)。
> - 「満腹度」は「初めて50%を切ったとき」ではなく、既存の
>   `hungerWarning`(20%しきい値)にそのまま乗せた。
> - 「樽守りの技」ヒントは `plan/protagonist-arts.md` が未実装のため見送った。
> - 村側の施設(ねむり小屋・工房・依頼板等)解放時のヒントは
>   `plan/village-development.md` が未実装のため見送った。
> - 設定画面からの「いつでも読み返せる」機能は `design/ui-flow.md` の
>   設定画面自体が未実装のため見送った(ヒントはHUDのメッセージログに
>   通常のメッセージとして流れる)。
> - タイトル画面からの導入(オープニング)は対象外とした。

`design/story.md` の序章は「拠点→潜る→10階(現在は地方境目)→帰る」の
基本ループそのものだと定めていたが、具体的にどう手ほどきするかは
決めていなかった。ここでは**画面いっぱいの説明を最初に出す一括方式では
なく、初めてその状況に出会った瞬間にだけ短く教える「その場方式」**を
仕様化する。

## 方針

- チュートリアルの目印(ヒント)は**1つの状況につき1回だけ**、初めて
  遭遇したときに短く表示する。既読のヒントは二度と出さない。
- `design/ui-flow.md` の設定画面から**いつでも読み返せる**ようにし、
  最初の1回を見逃しても遊びを止めない。
- 新しいシステム(仲間・タル等)は物語序盤で段階的に出会う設計に
  なっている(README・`design/story.md`)ため、ヒントも**そのタイミングに
  素直に乗せる**だけで済み、専用の練習ステージは作らない。

## ヒント一覧と発生タイミング

| ヒント | 発生条件 |
|---|---|
| 移動と攻撃 | ダイブ開始後、最初の入力を受け付ける前 |
| ものを拾う | 床にアイテムが初めて見えたとき |
| タルを持ち上げる/投げる | タルに初めて隣接したとき |
| モンスターを弱らせてから樽をぶつける | 最初のモンスターと遭遇したとき |
| 捕獲成功・仲間の同行 | 初めてモンスターを仲間にしたとき |
| 満腹度 | 満腹度が初めて50%を切ったとき |
| 状態異常 | 初めて状態異常を受けたとき |
| レベルアップ | 初めてレベルが上がったとき |
| めざめの階段 | 初めて階段(チェックポイント)に到達したとき |
| 倒れたときの扱い | 初めて全滅したとき。`design/world.md` の「知識は失われない」
  原則にも軽く触れ、不安を煽らない言い回しにする |
| 樽守りの技 | `plan/protagonist-arts.md` の最初の技を覚えたとき |
| 仲間への指示 | 仲間が2体目に加わったとき(1体だけの間は指示の必要が薄いため) |

村側の機能(ねむり小屋・工房・依頼板等)は、`plan/village-development.md`
の発展段階に合わせて解放されるため、**その施設が初めて使えるように
なった瞬間**に短いヒントを1つずつ出す形にし、序章の時点で全部を
説明しない。

## データ構造

```ts
export interface SaveData {
  // ...既存フィールド
  seenTutorialTips: string[]; // 表示済みヒントid
}
```

`design/flavor-details.md` のせりふプールの仕組みと同様、既存の
イベント発生箇所(捕獲成功・レベルアップ・全滅など、`GameEvent` として
既にある通知)に「まだ見ていなければヒントを添える」1行を足すだけで
実装できる。ヒント専用の監視処理を新設しない。

## トーンの指針

`design/world.md` の「素朴で温かい民話」のトーンをヒントの文面にも
適用する。「◯◯するには△△キー」という無機質な説明だけでなく、
モグラ婆やゲンドが話しかけてくるような一言を添える(具体的な文面は
`design/flavor-details.md` 側の作り込みに委ねる)。
