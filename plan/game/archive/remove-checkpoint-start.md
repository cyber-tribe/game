# 村からめざめの階段へのショートカット(出発地点選択)を廃止する

## 経緯

`plan/game/archive/checkpoint-select.md`(実装済み)で、一度踏んだ
めざめの階段を「出発地点」として選び、村からその深さへ直接飛べる
ようにしていた。これを**廃止**する。

理由:

- めざめの階段の往復が対称(降りた深さから再開できる)だと、
  ダイブが「続きから遊ぶセーブポイント」になり、**1回のダイブを
  頭から組み立てるローグライクの緊張感が薄まる**。
- 進行方向の再設計(`plan/game/dungeon-per-region.md`(別PR)の
  地方別ダンジョン化、および主人公のランごとビルド)では、
  各ダンジョンを入口から潜り直すこと自体が遊びの単位になる。
  深部への直行ショートカットはこの設計と両立しない。
- めざめの階段の価値は「**帰りの安全**(区切って持ち帰る)」に
  一本化する。行きは常に入口から。

## 変更内容

1. **拠点の「出発地点」列(既知のめざめの階段から開始階を選ぶUI)を
   削除する。** 出発は常に1階(そのダンジョンの入口)から。
2. めざめの階段を踏んだときの記録(`addKnownCheckpoint`)は、
   **記録の間の実績・到達の記録としては残してよい**が、出発階の
   選択肢としては使わない。
3. めざめの階段の「区切って持ち帰る」(bankRun)・
   `plan/game/checkpoint-stairs-menu.md` の3択モーダルはそのまま
   (帰り側の機能はすべて維持)。
4. チュートリアル・操作説明・旅の看板等で「出発地点を選べる」ことに
   触れている文言があれば削除する。

## セーブ互換

- 既存セーブの `knownCheckpoints` 相当のデータは読み捨ててよい
  (削除もマイグレーションで消す方が事故がない)。

## 受け入れ基準

1. 拠点の出発準備に開始階の選択肢が無く、常に1階から始まる。
2. めざめの階段での区切り(持ち帰り)は従来どおり機能する。
3. 過去に深い階まで到達済みのセーブでも、エラーなく1階出発になる。

## 対象外

- めざめの階段そのものの廃止(帰還機能として残す)
- 腕試しの間などの特殊ダンジョンの出発仕様
