>   本文自身が明記するとおり対象外**(手作り固定フロア・ストーリー演出は
>   別途ストーリー実装側の仕様書に委ねる)。
> - **解放条件を「第◯章クリア」から「最深到達記録(`SaveData.deepest`)」
>   に置き換えた。** `design/story.md` の章立て・進行管理自体が未実装の

>   出ていなければ最終階で強制的に出す方式で実装した。** 候補となる

>   出せないため、数学的な100%保証ではないが、実用上ほぼ確実に出る。
> - **④夜ごとの夢のモンスター強化カーブは、既存の階数依存スケーリング

>   数式」は未決のままなので、既存の仕組み(高い階ほど強い種族が混じり、
>   `baseMonsterCount`が階数に応じて増える。ただし12体で頭打ち)で代替し、
>   将来チューニングする前提とした。
> - **未解放ダンジョンの一覧表示は、専用のグレーCSSを追加せず、実績帳と
>   同じ「テキストに条件を添えるだけ」の方式にした**(`(未解放: 最深N階
>   到達で解放)`)。既存の見た目の統一を優先した。
> - **出発地点(めざめの階段)の選択は表の寝穴だけの仕組みのまま**とし、
>   他のダンジョンを選んだ場合は常に1階から出発する。

# 複数のダンジョン

README の「これから」にある「複数のダンジョン」を仕様化する。
`design/story.md` の章構成(近道屋の裏の穴、山の芯)とも接続する。

## 世界観との接続

ダンジョンはすべて `design/world.md` の通り、眠る巨人ヨリシロの夢への
入り口だが、**どこから入るか(どの寝穴を使うか)によって、夢の性質が
変わる**、という理屈で複数ダンジョンを成立させる。地形生成のアルゴリズム
自体は共通のまま、パラメータと出現テーブルだけを穴ごとに変える。

## 既存実装の確認(良い前提が既にある)

`Game` の `RunOptions.maxDepth` は既に「省略時10」という形で外から
差し替え可能になっている(`src/game.ts`)。深さの上限自体はすでに
パラメータ化済みで、複数ダンジョンの実装コストは主に
「**出現テーブル・生成パラメータ・アンロック条件をダンジョンごとに
持たせて、拠点で選ばせる**」部分に絞られる。

## ダンジョン一覧(初期案)

### ① 表の寝穴(既存実装)
- 最初から解放済みのメインダンジョン。当初は10階のダンジョンとして
  実装されたが、`design/regions.md` により **8つの地方 × 各6階の全48階**
  へ拡張されている(本編クリアの目標プレイ時間・約15時間から逆算した
  規模。`design/balance-philosophy.md` 参照)。地方ごとの詳細・
  チェックポイントは同ドキュメントを参照。この文書での「①表の寝穴」は、
  以後は48階全体を指す。
- `design/story.md` の序章〜第四章で潜り始め、物語の進行に応じてより
  深い地方のめざめの階段が解放されていく(`plan/checkpoint-select.md`
  参照)。

### ② 近道屋の裏穴
- `design/story.md` 第二章で解放される特別なダンジョン。5階程度と短め。
- 近道屋が無理やり掘った穴という設定に合わせ、生成パラメータを変える:
  - `plan/monster-house.md` のモンスターハウス出現率を上げる
  - `plan/shops-and-thieves.md` の店(近道屋の出店)が必ず1つは出る
  - 出現モンスターの `minFloor` 判定を1〜2段階深いフロア相当にずらし、
    同じ階数でも表の寝穴よりきつくする
- 攫われた・眠り病にかかった村人を救出するイベントの舞台
  (`design/story.md` 第二章の記述)。

### ③ 山の芯
- `design/story.md` 第四章、対近道屋の決着点。ワンショットの特別な
  ダンジョンとして扱い、通常の乱数生成ではなく**手作りの固定フロア**を
  想定する(詳細な中身・決着の演出は本仕様の対象外とし、別途
  ストーリー実装側の仕様書を立てて詰める)。

### ④ 夜ごとの夢(クリア後の周回モード)
- 本編クリア後に解放される、**終わりのない**ダンジョン。`maxDepth` を
  設けず、潜れるだけ潜って自己ベースを更新するモード
  (`Game` 側は「クリア扱いになる階」を無くすだけで対応でき、既存の
  10階クリア判定を無効化する `maxDepth: Infinity` 相当の指定で足りる)。
- 階が深くなるほど出現モンスターのレベル・数を底上げする。
- スコア(到達階・撃破数など)を `SaveData` に記録し、拠点で自己ベストを
  確認できるようにする。README「これから」に将来的な広がりを持たせる
  意図も兼ねる。

## データ構造

```ts
export interface DungeonDef {
  id: string;
  name: string;
  /** 未指定なら無限(夜ごとの夢用) */
  maxDepth?: number;
  /** 拠点で選べるようになる条件 */
  unlock: "always" | { afterChapter: number };
  /** 通常のモンスター出現テーブルからのずれ(階層換算のオフセット) */
  floorOffset?: number;
  /** モンスターハウス・店の出現率倍率 */
  monsterHouseRateMul?: number;
  shopRateMul?: number;
}
```

`speciesForDepth` 等の呼び出し側に `floorOffset` を足した深さを渡すだけで、
既存の出現テーブル(`src/entities/species.ts`)を書き換えずに難易度を
ずらせる。

## 拠点UI

- 出発前に「どの穴に潜るか」を選ぶ画面を、道具の持ち込み選択
  (`src/ui/town.ts`)の前段に追加する。
- 未解放のダンジョンは一覧に灰色で表示し、解放条件(第◯章クリア、など)
  を短く添える。
- 選んだダンジョンに応じて `RunOptions`(`maxDepth` 等)を組み立てて
  `Game` を生成する。
