# めざめの階段のある階では落とし穴を出さない

## 経緯

落とし穴(罠)を踏むと `descend()` が即座に呼ばれ、その階を強制的に
離れる(`src/game.ts` の `case "pitfall"`)。めざめの階段のある階
(表の寝穴では6の倍数階、`src/game.ts` の `isCheckpointFloor` 判定)で
これを踏むと、**チェックポイントに触れる機会そのものを失って次の階へ
落とされる**。区切って持ち帰るつもりだったプレイヤーには、リカバリー
不能の理不尽になる(6階ぶん先の次のチェックポイントまで戻れない)。

## 変更内容

**めざめの階段のある階では、落とし穴の罠を生成しない。**

- 罠の種類抽選(`src/dungeon/populate.ts` の `TRAP_KINDS` からの
  `rng.pick`)で、その階がチェックポイント階なら `"pitfall"` を
  抽選対象から除く。
- フロアギミック「おちあなの階」(`src/dungeon/gimmicks.ts` の
  `pitfall`)も、**チェックポイント階には割り当てない**(ギミックの
  抽選時に除外する)。ギミック側だけ残ると、罠の除外と矛盾した
  演出(予告メッセージだけ出る)になるため。
- チェックポイント階かどうかの判定は `src/game.ts` に既にある
  `isCheckpointFloor` と同じ条件(`dungeon.id !== MAIN_CAVE_ID ||
  depth % REGION_SIZE === 0`)を生成側でも使う。判定ロジックは
  共通化して1箇所にまとめてよい。
- 既に生成済みのフロア(セーブからの再開)は対象外でよい
  (次のフロア生成から効けば十分)。

## 変えないこと

- チェックポイント階以外の落とし穴の出現率・挙動
- 落とし穴を踏んだときの挙動そのもの(descend)
- 「おちあなの階」ギミックのチェックポイント階以外での抽選

## 受け入れ基準

1. 表の寝穴の6の倍数階(6・12・18…)で、落とし穴の罠が生成されない。
2. 同じ階に「おちあなの階」ギミックが付かない。
3. それ以外の階では従来どおり落とし穴が出る。

## 未決事項

  チェックポイント扱いになる場合は自動的に落とし穴が出なくなるが、
  そもそも罠自体の生成有無が別で制御されているなら影響なし。
  実装時に確認)
