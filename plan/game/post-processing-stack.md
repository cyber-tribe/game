# ポストプロセスの導入(ブルーム・色調グレーディング・アンチエイリアス)

## 経緯

`plan/game/toon-shading-pipeline.md`(段階陰影+輪郭線)に続く、
描画品質を家庭用機水準へ近づける施策の第2弾。現状の`src/view/`には
`EffectComposer`をはじめとするポストプロセスが一切存在せず、
`renderer.render()`の直呼びのみで画面を出している。

家庭用機のトゥーン系タイトルの「画面の締まり」は、モデルの出来と
同じくらいポストプロセスで作られている。特に:

- モデル側には既に`emission`指定(ホネガラミ系の目の光、ボスの目、
  `mizukagami`の水鏡など多数)が入っているのに、**ブルームが無いため
  「明るい単色」にしか見えず、発光として知覚されない**。
- トゥーン化で輪郭線(黒縁)を入れると、アンチエイリアスの弱さが
  ジャギーとして目立つようになる。ポストプロセス系AAはその対策として
  ほぼ必須。

## 現状の土台

- `src/view/renderer.ts`: `WebGLRenderer({ antialias: true })`、
  `ACESFilmicToneMapping`、`toneMappingExposure 0.98`、
  `PCFSoftShadowMap`(`autoUpdate: false`の手動更新最適化あり)。
  描画は毎フレーム`this.renderer.render(scene, camera)`。
- three r185(`package.json`)。`EffectComposer`・`RenderPass`・
  `UnrealBloomPass`・`OutputPass`・`SMAAPass`はすべて
  `three/addons/postprocessing/`から追加費用なしで使える。
- 気分の視覚演出(`MOOD_VISUALS`)がFog・環境光の色を差し替える
  仕組みが既にあり、ポストプロセスの色調と干渉しないよう注意が要る。

## 修正方針

`Renderer`に`EffectComposer`を導入し、描画チェーンを次の構成にする。

```
RenderPass(scene, camera)
  → UnrealBloomPass(解像度は画面の1/2, strength≈0.35, radius≈0.4, threshold≈0.9)
  → ShaderPass(自作の色調グレーディング+ビネット)
  → SMAAPass
  → OutputPass   ← トーンマッピングと色空間変換はここで一括適用
```

要点:

1. **`OutputPass`をチェーン末尾に置く。** three r152以降、Composer利用時は
   トーンマッピング・sRGB変換を`OutputPass`が担う。`renderer.toneMapping`の
   設定はそのまま活き、既存の見た目(ACES+露出0.98)と発色が揃う。
2. **ブルームは全画面しきい値方式。** 既存モデルの発光は
   `emission 1.3〜3.0`で指定されており、しきい値0.9を超えるのは
   実質発光部位だけ。選択式ブルーム(レイヤー分け)の複雑さを避けて、
   モデル側の既存データがそのまま活きる。
3. **色調グレーディングはLUT画像を使わず、小さな自作ShaderPassで行う。**
   彩度・リフト/ガンマ/ゲイン・ビネットだけの数十行のシェーダーにする。
   このリポジトリは「アセットをコードから生成する」方針なので、
   外部LUTファイルの導入より一貫する。初期値は「わずかに彩度を上げ
   (+8%程度)、シャドウをほんの少し青に転がし、画面端を10〜15%暗くする」
   程度の控えめな設定から始める。
4. **AAは`SMAAPass`を第一候補にする。** `antialias: true`(MSAA)は
   Composer導入後はレンダーターゲット経由になるため効かなくなる。
   SMAAで輪郭線のジャギーを均す。モバイルで負荷が問題になる場合は
   FXAAへ差し替え(未決事項)。
5. **リサイズ対応。** 既存のリサイズ処理で`composer.setSize()`と
   ブルームパスの解像度更新を忘れずに行う。
6. **モバイル負荷への配慮。** ブルームは1/2解像度で計算する。
   `setPixelRatio`が高いモバイル端末で負荷が出た場合に備え、
   ブルームだけを無効化できるフラグを`Renderer`に持たせる。

## 受け入れ基準

1. ホネガラミ等の目の光が「にじんで光って」見える(ブルームが効いている)。
2. ビネット・彩度調整により、素のレンダリングと見比べて画面全体の
   色調に統一感が出ている(前後比較のスクリーンショットで確認)。
3. トゥーン輪郭線導入後の斜め線のジャギーが、AA無しと比べて明確に減る。
4. 気分の視覚演出(`MOOD_VISUALS`のFog・環境光差し替え)が従来どおり
   機能し、色調グレーディングと二重掛けで破綻しない。
5. 手元のスマホ実機で体感できるフレームレート低下がない
   (低下する場合はブルーム無効化フラグで回避できる)。
6. `npm run test`・`npm run typecheck`・`npm run build`がすべてgreen。

## 対象外

- 被写界深度(DoF)・モーションブラー・SSAO。負荷対効果が見合わないと
  判断したら導入しない(SSAOはAOベイク側の計画で代替する)。
- 図鑑ギャラリー(`gallery.ts`)の描画経路が別にある場合の対応は、
  実装時に確認して必要なら追いかけの決定にする。

## 未決事項

- ブルームの`strength`/`radius`/`threshold`、色調グレーディングの
  各パラメータの最終値(実機の見た目で詰める)。
- SMAAで負荷が出た場合にFXAAへ落とすか。
- 村(拠点)画面にも同じチェーンを適用するか、ダンジョンのみにするか。
