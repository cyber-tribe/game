# ダンジョンカメラを近づけ、モンスターをよく見せる

## 経緯

「カメラが引きすぎで、せっかく魅力的なモンスターが小さくてよく
見えない」という指摘。看板モデル計画・ガルドの衣装立体化等、
造形そのものへの投資を進めている一方で、**その造形をプレイヤーが
実際にどれだけの大きさで見ているか**を見直していなかった。

## 現状

`src/view/renderer.ts`のダンジョンカメラ:

```ts
private distance = 11.5;
private elevation = THREE.MathUtils.degToRad(48);
...
zoom(delta: number): void {
  this.distance = THREE.MathUtils.clamp(this.distance + delta, 6.5, 18);
}
```

既定の距離は11.5(可変域6.5〜18のほぼ中央よりやや手前)。ズーム
操作(`±`キー、操作説明にも表示済み)自体は存在するが、**多くの
プレイヤーは既定値のまま遊ぶ**と考えられ、モンスター・ガルドの
造形へ投じた工数(彫り込み・硬い部品・テクスチャ)が画面上では
小さくしか映らず、伝わりにくくなっている。

## 変更内容

### 1. 既定の距離を近づける

- `distance`の初期値を11.5から**8前後**まで近づける(可変域
  6.5〜18の下寄りに設定し直す)。プレイヤーは従来どおり`±`で
  引き引きできる(遠くを見渡したいときの逃げ道は残す)。
- 具体的な最終値は、盤面生成の最大部屋サイズ
  (`MIN_ROOM_W`〜`MAX_ROOM_W`=4〜11マス、`MAX_ROOM_H`=8マス、
  `src/domain/dungeon/generate.ts`)でも画面から部屋が大きく
  はみ出しすぎないか、エンジン内プレビューで実際の生成フロアを
  見ながら詰める。ミニマップが既に実装済みのため、多少視野が
  狭まっても盤面全体の把握はミニマップ側で補える。

### 2. 関連する定数の追随

- `src/view/particles.ts`のパーティクル基準サイズ計算が
  「カメラの標準距離11.5」を前提にコメントされている
  (`uBaseSize`の係数)。既定距離を変えると、画面上のパーティクル
  サイズの見え方が変わってしまうため、**同じPRで新しい既定距離に
  合わせて再調整する**(パーティクルだけ相対的に大きく/小さく
  見えることがないようにする)。

### 3. 触れないもの

- FOV(`CAMERA_FOV`, 46度)・カメラの仰角(48度)は変更しない
  (距離だけを詰めれば十分効果が出る見込みのため、変数を一度に
  複数動かさない)。
- ズームの可変域(6.5〜18)自体はひとまず変えない(引きたい人の
  ための上限はそのまま残す)。

## 受け入れ基準

1. 既定のカメラ距離で、モンスター・ガルドの姿がこれまでより
   明確に大きく見える(新旧比較スクリーンショット)。
2. 最大サイズの部屋(11×8マス)でも、部屋の輪郭が画面から
   大きくはみ出して迷いやすくならない(ミニマップでの補完を
   前提に許容範囲かを実機目視で確認する)。
3. パーティクルエフェクト(捕獲・撃破等)の見た目のサイズ感が
   崩れていない。
4. モバイル実機で60fpsを維持する(距離を縮めるとポリゴンの
   画面占有が増えるため、負荷の変化を確認する)。

## 対象外

- FOV・仰角・ズーム可変域の変更
- 村・図鑑ギャラリーなど、ダンジョン以外のカメラ距離
  (`renderer.ts`のダンジョン専用カメラが対象)

## 未決事項

- 既定距離の最終値(8前後をたたき台に、エンジン内プレビューで
  部屋サイズとの兼ね合いを見ながら調整する)
