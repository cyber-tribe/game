# 村のメニューを建物・村人ごとの役割に分ける(一元メニューの廃止)

## 経緯

拠点画面(`src/ui/town.ts` の `TownScreen`)は現在、0〜19の20列が
一直線に並ぶ一元メニューで、どの建物から入っても左右キーで全列を
横断できる(`plan/game/archive/town-3d-exploration.md` の
「どの建物から入っても実質すべての機能へたどり着ける」という設計)。

この一元化をやめる。**建物・村人ごとに役割を設け、アクセスすると
その役割に対応する操作だけができる**ようにする。狙い:

- 20列の横断は一覧性が悪く、特にスマホでは横スクロールの海になる
  (`plan/game/archive/gallery-mode.md` の実装注記でも列数増による
  表示崩れが起きていた)。役割ごとに数列ずつなら画面に収まる。
- 「倉庫はモグラ婆」「強化はゲンド」のように**場所と機能が結びつく**
  ことで、村が単なるメニューの入れ物ではなく生活の場になる
  (`design/village-life.md` の「NPCごとに立ち寄れる場所として
  ゾーニングする」方針を、メニュー構造まで貫徹する)。

## 方針

### 実装の骨格

`TownScreen` の各列のレンダラー(`renderColumn(N, ...)`)は
そのまま再利用する。`show()` に**「開ける列の集合」と「見出し
(建物名)」を渡せるようにし、左右キーはその集合の中だけを巡回**
する。全列を一直線に並べる現在の動きを、建物ごとの部分集合に
差し替えるだけで、列の中身(各機能のUI)は変えない。

### 建物・村人と役割の対応

| 場所(村人) | 開ける列 | 役割 |
|---|---|---|
| 洞窟の入口 | 倉庫(0)・持ち込む(1)・出発地点(2)・鍛え方(3)・つれていく仲間(4)・難易度(10)・潜るダンジョン(12) | **出発の支度一式**。ここで整えてそのまま潜る |
| モグラ婆の倉庫 | 倉庫(0)・持ち込む(1) | 持ち物の整理・預け入れ |
| ねむり小屋(新設) | つれていく仲間(4)のうち仲間の世話(夢あわせ・改名・逃がす) | 仲間の管理(`plan/game/archive/monster-fusion.md`) |
| ゲンドの工房 | 工房(5) | 強化・刻印・合成 |
| おキヨの図鑑小屋 | モンスター図鑑(7)・装備図鑑(9) | 図鑑・ギャラリー |
| 記録の間(新設) | 記録の間(6)・実績帳(8) | 記録・実績・称号 |
| オトネの依頼板 | 依頼板(11) | 依頼の受注・報告 |
| 村の発展の受付 | 村の発展(13) | 発展への出資 |
| 村の広場 | NPCと話す(16)・宵祭りの出店(17) | 交流。出店は祭り期間のみ現れる |
| ガルドの家(新設) | 身支度(15) | 衣装の着替え |
| 旅の看板 | みんなの記録・チュートリアルの読み返し | 旅の掲示。従来の「既定の入口(全列)」の役割は廃止 |

- 同じ列を複数の場所から開けるのは構わない(倉庫は入口でも
  モグラ婆でも触れる)。**禁止するのは「そこに無い役割へ左右キーで
  流れていけること」だけ**。
- システム系の列(アクセシビリティ(14)・音(18)・設定(19))は
  建物から外し、**村でもダイブ中でも開ける「≡」メニュー(または
  設定画面)へ移す**。世界の中の場所と、ゲームの外の設定を混ぜない。

### 導線の担保

- 建物に近づいたときのヒント表示(既存の`村なか歩き`の
  「決定ボタン: ◯◯へ」)に、その建物の役割が伝わる一言を添える
  (例:「ゲンドの工房(強化・合成)」)。
- 村は狭く(`VILLAGE_BOUNDS` は約18×18)、建物間の徒歩は数秒
  なので、ファストトラベルは不要。
- 進行条件で列が増える場合(祭り期間の出店等)も、対応する
  建物・場所の集合にだけ追加する。

## 対象外

- 各列の中身(倉庫・工房・図鑑等それぞれのUI・機能)の変更
- 村マップの地形・建物配置の大幅な変更(新設3件の置き場所は
  実装側の裁量。既存の空きスペースに置けばよい)
- ダイブ中のメニュー構造
