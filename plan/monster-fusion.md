# モンスター配合(夢あわせ)+ ねむり小屋

README の「これから」に挙がっている「モンスター配合」と、その前提となる
「拠点に仲間を預ける小屋」をあわせて1機能として仕様化する。
`design/world.md` の世界観(モンスター＝夢のかけら)を前提にした名称・
ルールにしている。実装は別セッションが行う想定。ここでは仕様のみ定める。

## 現状(前提の確認)

- 仲間(`Actor.kind === "ally"`)は完全にラン単位。`Game.allies` はダイブ開始時
  常に空で始まり、ダイブ中にタルから捕まえた分だけが入る
  (`src/game.ts` の `allies` フィールド、`MAX_ALLIES` は同時2体まで)。
- ラン終了時(踏破・全滅とも)、仲間は一切セーブデータに残らない。
  `src/save.ts` の `SaveData` は `storage`(道具)しか持っていない。
- つまり「仲間を拠点で保持する」「次回持ち込む」という概念自体が存在しない。
  これが README の言う「モンスター小屋がここで要る」の意味。

## 名称: ねむり小屋 / 夢あわせ

世界観(`design/world.md`)に合わせ、汎用的な「モンスター小屋・配合」ではなく
以下の名称・解釈を採用する。

- **ねむり小屋**: 拠点(ネンネ村)にある、連れ帰った夢のかけら(モンスター)を
  休ませておく小屋。道具の「倉庫」の、モンスター版にあたる。
- **夢あわせ**: 2体の夢のかけらを並べて寝かせ、片方の夢をもう片方に
  溶け込ませる行為。世間一般の「配合」「合成」という無機質な言葉ではなく、
  「隣り合って眠るうち、夢が混ざり合う」というこの世界固有の理屈にする。
  実質的な効果(1体を素材にしてもう1体を強化する)は配合と同じだが、
  必ず**夢あわせ**という名称と、この理屈で説明すること。

## データ構造の拡張案

`src/save.ts` の `SaveData` に、道具の `storage` と対になる形で追加する。

```ts
export interface StoredMonster {
  /** ねむり小屋の中で個体を識別する連番 */
  uid: number;
  speciesId: string;
  level: number;
  exp: number;
  /** 夢あわせで引き継いだ特技。最大2つ */
  skills: SkillId[];
  /** プレイヤーがつけた名前。任意 */
  nickname?: string;
}

export interface SaveData {
  // ...既存フィールド
  /** ねむり小屋に預けてある仲間 */
  hut: StoredMonster[];
}
```

`Actor` 側にも `skills?: SkillId[]` を持たせ、ダイブ中の戦闘計算
(`src/systems`)が参照できるようにする。

## 特技(SkillId)の一覧案

種族ごとに1つ、素の生態に紐づく特技を用意し、夢あわせで他個体へ
引き継げるようにする。既存の `inflicts` / `ai` / `range` の一部は
既に種族固有の挙動として実装済みなので、特技はそれとは別に
**戦闘に小さな補正を足す** ものに留め、既存ロジックへの影響を絞る。

| SkillId | 由来種族 | 効果案 |
|---|---|---|
| `quickStart` | ガジリねずみ | そのランの最初の1手を必ず先制できる |
| `drowsyBreath` | マドロミダケ | 隣接する敵を攻撃したとき、眠り付与の確率に+10% |
| `longThrow` | ツブテガエル | 遠隔攻撃の射程 +1 |
| `stubborn` | ホネガラミ | HPが1残っていれば、致死ダメージを1回だけ耐える(1ラン1回) |
| `softBody` | ぷるん | 被弾ダメージを확率5割で1割軽減する |

1体が持てる特技は最大2つ(自分の種族由来 + 夢あわせで得た1つ、程度の枠)。
効果の詳細な数値バランスは実装時に `tests` で検証しながら調整してよいが、
「戦闘の勝敗をひっくり返すほど強くしない」「既存の5体の個性を強める方向に
倒す」の2点は守る。

## 出撃前(拠点)の選択

`src/ui/town.ts` の道具の持ち込み選択(倉庫 ⇔ 持ち物)と対になる形で、
ねむり小屋からの連れ出し選択を追加する。

- ねむり小屋に何体いても、**同時に連れて行けるのは既存の `MAX_ALLIES`
  (2体)まで**。道具の「8個まで」と同じ発想の縛りにする。
- 0体を選んで身軽に潜り、ダイブ中にタルで新しく捕まえる、という
  現状の遊び方もそのまま残す(ねむり小屋は空でもゲームが成立する)。
- 連れ出した個体は、その回のダイブでは `Game.allies` の初期値として扱う。

## 帰還時の処理

`design/world.md` の「倒れると持ち物を失う/踏破すれば持ち出せる」という
理屈を、仲間にもそのまま適用する。

- **踏破して帰還**(または将来実装される中断帰還)した場合: そのとき
  生きて連れていた仲間は、レベル・特技をそのまま**ねむり小屋に格納**される
  (新規に捕まえた仲間もこの時点で初めてねむり小屋入りする)。
- **全滅した**場合: 連れていた仲間は道具と同様、その回の夢もろとも失われる。
  ねむり小屋に預けたまま連れて行かなかった仲間は影響を受けない。
- ダイブ中に力尽きた仲間(`kind: "ally"` が `alive: false` になったもの)は
  その時点で失われている(現状の実装のまま)ので、帰還時の対象に含めない。

`src/save.ts` の `recordRun` に、道具の `broughtBack` と対になる
`broughtBackAllies` 相当の引数を増やす形で対応できる。

## 夢あわせ(配合)の仕様

ねむり小屋の中でのみ行える(ダイブ中には行えない)。

1. **軸**(残す側)と**糧**(消える側)を1体ずつ選ぶ。同じ種族同士でも
   異なる種族同士でもよい。
2. 結果は軸の種族を維持したまま:
   - レベル: `軸.level + floor(糧.level / 2) + 1`
   - 特技: 軸の特技はそのまま。糧が持つ特技のうち軸が未所持のものを
     1つ引き継ぐ(軸がすでに2つ持っていれば引き継がない/選択させる)。
     糧自身の種族由来の特技(上表)も、糧が明示的に習得済みならここで渡せる。
   - HP等のステータスは種族の基礎値 × レベルから再計算する(既存の
     レベルアップ計算があればそれに合わせる)。
3. 糧に選んだ個体はねむり小屋から消える(元に戻せない)。
4. 軸・糧いずれも、直前のダイブに連れて行った当人同士であっても、
   帰還処理でねむり小屋に入った**後であれば**夢あわせに使える。

## UI/操作案

- 拠点メニューに「ねむり小屋」を追加(既存の「倉庫」「出発」と横並び)。
- ねむり小屋画面はさらに「連れ出す仲間を選ぶ」(出発前)と「夢あわせ」
  (小屋の中だけで完結する操作)の2モードを持つ。
- 一覧表示は `src/ui/town.ts` の道具リストのUIパターン(2カラム・カーソル
  移動・Enterで確定)を踏襲し、実装コストと操作感の一貫性を優先する。
