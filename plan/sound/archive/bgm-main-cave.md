> **実装済み。** `compose.ts` の `TrackParams` に `motif?: readonly number[]`
> (コード度数からの相対値の度数列)と `motifNoteBeats?: number`(既定1、
> 1音があたる拍数)を追加した。
>
> **実装方式**: 主ループ(拍ごとのランダム徘徊メロディ生成)とは別に、
> モチーフの提示は専用パス(`placeMotifRun`)として主ループの後に実行する
> 設計にした。主ループ側は「この拍がモチーフの提示区間(前半・後半それぞれの
> 最初の`motifBarsNeeded`小節)に入っているか」だけを判定し、入っていれば
> 通常のランダム徘徊メロディ(`rng()`消費含む)を丸ごとスキップする
> (太鼓・ベースの生成は提示区間でも従来どおり独立して動く)。この設計により
> **`motif`未指定時は判定が常にfalseになり、`rng()`の呼び出し順序が一切
> 変わらない**ため、村・ボス・真の目覚めなど計画書が対象外とした曲は
> バイト単位で無変化になる(実測で確認済み。region1〜8以外の`.wav`は
> `npm run audio`後に`git status`で無変更)。
>
> **前半の提示**: `motifNoteBeats`拍ずつ、通常の主旋律と同じ+1オクターブで
> そのまま1回鳴らす。各音の和声(コード度数)は、その音が実際に鳴る小節の
> `CHORD_SKELETON`をそのまま参照するため、モチーフが複数小節にまたがる曲
> (第七・第八地方)でも自然にコード進行に追従する。
>
> **後半の変奏**: 計画書どおり「1オクターブ上げる/音価を半分にして2回
> 繰り返す」をシードの偶奇で選ぶ(`seed % 2 === 0`ならオクターブ上げ、
> 奇数なら倍速2回)。どちらの変奏も前半と同じ小節数(`motifBarsNeeded`)に
> 収まるよう時間換算した(倍速2回は「音価半分×2回」で合計の演奏時間が
> オクターブ上げ版と一致する)。
>
> **第八地方のモチーフ**は計画書の指示どおり、第一地方と同じ度数列
> `[0, 1, 2, 1]`を`motifNoteBeats: 2`で流用し、「第一のモチーフを
> 引き延ばした形」を実現した(新しい仕組みは増やしていない)。
>
> **楽器選択**: モチーフの各音は`pickMelodyInstrument`に渡す乱数を、
> 主ループの`rng`とは独立した使い捨ての`mulberry32(noteSeed)()`から
> 取っている(主ループの乱数消費順序に影響を与えないため)。
>
> `build.ts`の`region1`〜`region8`エントリに計画書の目安どおりの度数列を
> 追記し(具体値は計画書が「聴感で決めてよい」としていた目安をそのまま
> 採用)、`public/audio/bgm/region1.wav`〜`region8.wav`を再生成した。
> シード・テンポ・拍子・小節数・重み・残響はいずれも変更していない
> (再生成後もファイルの再生時間は全て変化なしを確認済み)。
>
> **検証**: `npx tsc --noEmit`・`npx vitest run`(105ファイル/1356件、
> `motif`/`motifNoteBeats`の効果・決定性のテストを追加)・`npm run build`・
> `npm run audio` いずれも成功。`npm run audio`後に変更があったのは
> `region1.wav`〜`region8.wav`の8ファイルのみで、他の9曲は無変更
> だったことを`git status`で確認した(受け入れ基準3を満たす)。

# 表の寝穴のBGM: 地方ごとの固有モチーフ

## 経緯・現状

表の寝穴(`mainCave`)は8ダンジョン中で唯一、地方ごとのBGM
(`region1.wav`〜`region8.wav`+ボス階の`boss.wav`)がすでに揃っている。
`plan/sound/archive/bgm-quality-upgrade.md` の実装で、テンポ・拍子・
楽器の重み・残響の深さによる描き分けと、ベースライン・前後半の起伏も
入った。

残る弱点は**旋律が完全なランダム徘徊**であること。コード度数の周りを
シード付き乱数で揺れるだけなので、質感は地方ごとに違っても、
「この地方の歌」と口ずさめる主題が無い。曲としての記憶に残りにくい。

## 決定

**8地方それぞれに、書き下ろしの固有モチーフ(ペンタトニック上の
度数列、4〜8音)を1つずつ持たせ、旋律生成を「モチーフの提示と変奏」に
変える。**

ランダム性を捨てるのではなく、モチーフを「毎回必ず現れる背骨」として
足し、それ以外の拍は従来どおりシード付き乱数で埋める(手続き的生成+
固定の設計、というこのリポジトリの定石のまま)。

## 仕様

### 生成側(`tools/audio/`)

- `compose.ts` の `TrackParams` に `motif?: readonly number[]`
  (ペンタトニック上の度数列。コード度数からの相対値)を追加する。
- モチーフ指定時の旋律生成:
  - **各半分(前半/後半)の最初の小節**は、拍の頭からモチーフの音を
    順に鳴らす(1拍1音。モチーフが小節に収まらない分は次の小節へ
    続けてよい)。これで「ループのたびに同じ歌い出し」が保証される。
  - それ以外の拍は従来のランダム徘徊のまま。ただし揺れの中心を
    「直前に鳴らしたモチーフ音」に寄せると旋律がつながりやすい
    (実装裁量)。
  - **後半の提示は変奏にする**: 1オクターブ上げる/音価を半分にして
    2回繰り返す、のどちらかをシードで選ぶ。
- モチーフ未指定なら従来どおり(村・ボス・他ダンジョンの曲に影響なし)。

### 8地方のモチーフの性格(度数列は目安。最終値は聴感で決めてよい)

| 地方 | 性格 | 度数列の目安 |
|---|---|---|
| 第一 うたたねの参道 | 素直に上って戻る。歩き出しの歌 | `[0, 1, 2, 1]` |
| 第二 忘れ潮の湿地 | 長く伸びて半歩沈む。霧の中の遠い声 | `[2, 2, 1, -1]` |
| 第三 まどろみの茸林 | 3拍子に乗ってゆっくり降りる。まぶたが落ちる形 | `[4, 2, 0]` |
| 第四 骨積みの回廊 | 同音の連打から跳ねる。乾いた足音 | `[0, 0, 3, 0]` |
| 第五 なみだの滝つぼ | 高い所から続けて落ちる。滝の形をなぞる | `[5, 4, 2, 1]` |
| 第六 こだまの尾根 | 呼びかけ2音+同じ形の反復(こだま) | `[3, 0, 3, 0]` |
| 第七 わすれられた祭りの跡 | 囃子の掛け合い。跳ねて戻る | `[0, 2, 0, 3]` |
| 第八 めざめの前庭 | 第一のモチーフを引き延ばした形(全地方の記憶の入口が最初の記憶に戻る) | `[0, 1, 2, 1]` を2倍の音価で |

### 対象ファイル

`public/audio/bgm/region1.wav` 〜 `region8.wav`(`npm run audio` で
再生成)。`build.ts` の `BGM_SPECS` に `motif` を追記するだけで、
シード・テンポ・拍子・残響は現状のまま変えない(モチーフの効果だけを
聴き比べられるようにする)。

## 受け入れ基準

1. 同じ地方のBGMを再生し直すと、毎回同じ音列(モチーフ)で歌い出す。
2. 地方が違えばモチーフも違う(第八の意図的な引用を除く)。
3. モチーフ未指定の曲(村・ボス)は波形がビット単位で変わらない、
   または聴感上従来と同等である。
4. `composeTrack` の決定性(同シード同波形)のテストが通る。

## 対象外

- 村・ボス・真の目覚めのモチーフ(それぞれ別プランで扱うか現状維持)
- 他ダンジョン(近道屋の裏穴など)の新曲(各ダンジョンの個別プラン参照)
- テンポ・拍子・楽器重みの再調整

## 未決事項

- 各モチーフの最終的な度数列(上の表は目安。実装セッションが聴感で確定)
- 変奏のバリエーションを増やすか(反行・逆行などは今回は見送ってよい)
