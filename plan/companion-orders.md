# 仲間への指示(構え)

README の「これから」にある「仲間への指示」を仕様化する。現状の仲間AI
(`src/entities/ai.ts` の `decideAllyAction`)は常に固定の1パターン
(隣に敵がいれば殴る → 見えている敵がいれば追う → いなければ主のそばに
戻る)で動いており、プレイヤーが挙動を変える手段がない。ここに
選択式の「構え」を導入する。

## 名称

DQシリーズの「さくせん」(がんがんいこうぜ / いのちだいじに 等)をそのまま
持ち込まず、この作品独自の言葉として **構え(かまえ)** と呼ぶ。
コマンド名は「指示」。

## 構えの一覧

現状の `decideAllyAction` を分岐拡張する形で、4種類を用意する。
①は現行実装そのものなので追加コストが最小、④が最も実装コストが高い。

### ① おまかせ(既定)
現状のロジックのまま。隣接する敵がいれば攻撃、見えている敵がいれば
距離場を下って追う、いなければ主(プレイヤー)から距離1以内を保って
着いてくる。**仲間は捕まえた直後、常にこの構えから始まる。**

### ② そばにいろ
主の護衛に徹する。見えている敵がいても自分から追わず、**隣接した敵にのみ
反撃する**。距離場での追跡(`foeField` の参照)を行わず、常に主の隣接圏内
(距離1以内)へ戻ろうとする点は①と同じ。狭い部屋でモンスターハウス
(`plan/monster-house.md`)級の物量に囲まれたときや、はぐれさせたくない
弱い仲間に使う想定。

### ③ そこで待て
指示を出した瞬間の仲間の座標を**固定地点**として記憶し、主が離れても
追わずその地点を動かない。地点に留まったまま、隣接する敵にのみ反撃する
(①②と同様、待ち伏せ中も自衛はする)。通路の封鎖・部屋の入り口の見張りに
使う想定。

**例外:** 主が階段を降りる/上がる、あるいはめざめの階段で帰還する際は、
構えに関わらず必ず全員がついてくる(現状README記載の「階段にもついて来る」
仕様を維持)。フロアは踏破のたびに作り直されるため、待機中の仲間を
その場に置き去りにする仕様にはしない(取り返しがつかなくなるため)。

### ④ 先陣を切れ
斥候役。見えている敵がいなくても主のそばに留まらず、**そのフロアでまだ
視界に入っていない場所(未探索タイル)、または階段の方向へ自律的に進む**。
道中で敵を見つければそのまま応戦する。主より先に部屋へ踏み込んで安全を
確かめてくれる代わりに、単独で袋叩きに遭うリスクもある構え。

未探索タイルへの誘導は、`FloorState.tiles[].explored` を使って
「主に見えている全アクター中でこの仲間だけが到達できる、最も近い未探索の
歩行可能マス」を目的地にする形で実装できる(既存の距離場の仕組みを
再利用し、始点をその仲間1体にした距離場を都度計算する)。

## データ構造

```ts
export type AllyStance = "free" | "guard" | "hold" | "vanguard";

// Actor (ally のみ)
stance?: AllyStance;      // 既定は "free"
holdPos?: Vec2;           // stance === "hold" のときの固定地点
```

`decideAllyAction` の引数に `stance` を追加し、先頭で構えごとの分岐に
入る形にする。①のロジックは既存コードをそのまま「free」の枝として残す。

## 操作・UI

- 新規キー **T** を「指示」コマンドに割り当てる(`src/view/input.ts` の
  `Key*` マップに空きあり。F/G/I/Q/E/R とは重複しない)。
- Tキーを押すと、連れている仲間の一覧(HUDの仲間欄と同じ並び)から
  対象を選び、①〜④をカーソルで選ぶ簡易メニューを開く。
  操作感は `src/ui/town.ts` の一覧UIに合わせる。
- 全員まとめて同じ構えにする「全員に指示」もメニューの先頭に置く
  (仲間は最大2体なので、個別指定の手間は大きくないが、揃える操作を
  1回で済ませられると快適)。
- HUDの仲間表示(`src/view/hud.ts` の `ally-row`)に、現在の構えを示す
  小さいアイコン/ラベルを添える。

## ねむり小屋との関係

`plan/monster-fusion.md` で仲間が拠点(ねむり小屋)を持つ設計にしたが、
構えはダイブ中だけの一時状態として扱い、`StoredMonster` には保存しない
(次のダイブでは毎回「おまかせ」から始まる)。理由は、構えを覚えさせると
「どの構えだったか忘れて事故る」プレイヤー体験を避けたいため。

## 未決事項

- ④先陣を切れの未探索マス探索は、実装負荷次第では第一弾から外し、
  ①②③のみ先に実装する案もある(READMEの記述通り最初に欲しいのは
  「ついてこい」「その場で待て」なので、②③を優先してよい)。
- 構え変更に何らかの制約(クールダウン・満腹度消費等)を設けるかは、
  実装しながらバランスを見て判断する。現時点では無条件で即時切替でよい
  という前提にしている。
