# 地方拡張(表の寝穴を8地方・全48階に広げる)

`design/regions.md`(8地方・全48階の設計)を前提とする。この文書は
その設計を実装可能な形に落とす。

## 背景・課題

- `plan/archive/monster-compendium.md` は既に `design/regions.md` の階層帯に
  合わせて `minFloor: 7〜43` の新モンスター14種(7地方ぶん)を実装済みだが、
  `MAIN_CAVE_MAX_DEPTH` が依然として10のままなので、**11階以降がそもそも
  存在せず、これらのモンスターは通常プレイで一切出現しない**。
- `plan/archive/checkpoint-select.md` は実装時、「地方(design/regions.md)が
  まだ未実装で、6階ごとの地方境界という概念がコード上に存在しないため、
  どの階の階段でも到達すれば既知になる、という一般化した形で実装した」
  「地方の実装が進んだ段階で、対象を地方の境目だけに絞る方向に調整する
  余地を残す」と明記している。
- `plan/archive/region-bosses.md` は共通の仕組みと第一地方のボス
  (おおねぼすけ)だけを実装し、「残り7体は、8地方の床構造自体が未実装の
  ため見送った」と明記している。

つまり**8地方への床構造の拡張そのものが、複数の既存機能を完成させる
ための土台として既に必要とされている**。本文書はその土台(床構造・
チェックポイントの対象範囲)を作ることに専念する。残り7体の地方ボス・
地方固有ギミック(深み・眠りの胞子等)は本文書のスコープ外とし、
今後の個別の `plan/` 文書に譲る。

## 変更内容

### 1. `MAIN_CAVE_MAX_DEPTH`: 10 → 48

`src/entities/dungeons.ts` の定数変更のみ。`DungeonDef.maxDepth` はこの
定数を参照しているので自動的に反映される。

`NIGHTLY_DREAM_ID`(夜ごとの夢)の解放条件は `{ minDeepest: MAIN_CAVE_MAX_DEPTH }`
を参照しているため、この変更で自動的に48へ引き上がる(表の寝穴を完全
踏破しないと解放されなくなる)。`design/postgame.md` の「物語クリア
時点で村段階4に達する」ことと合わせて周回コンテンツが解放される設計と
矛盾しないため、この波及は意図した変化として明記しておく。

### 2. 地方境界表

`speciesForDepth`(`minFloor`/`maxFloor` ベースのフィルタ)が既に
以下の境界と整合しているため、出現テーブル自体は追加のコード変更が
不要(`monster-compendium.md` で先行実装済み)。本文書ではこの対応関係を
明文化するだけに留める。

| 地方 | 階 |
|---|---|
| 第一 うたたねの参道 | 1〜6 |
| 第二 忘れ潮の湿地 | 7〜12 |
| 第三 まどろみの茸林 | 13〜18 |
| 第四 骨積みの回廊 | 19〜24 |
| 第五 なみだの滝つぼ | 25〜30 |
| 第六 こだまの尾根 | 31〜36 |
| 第七 わすれられた祭りの跡 | 37〜42 |
| 第八 めざめの前庭 | 43〜48 |

### 3. めざめの階段(チェックポイント)を地方境界だけに絞る

`checkpoint-select.md` が実装時に宣言していた暫定の一般化を、地方が
実在するようになった本文書の実装をもって本来の設計に戻す。

- **地方の最終階(6, 12, 18, 24, 30, 36, 42, 48階)の階段だけ**が
  「めざめの階段」として既知になり、`checkpoint` イベントを出す。
- それ以外の階(1〜5, 7〜11, …)の階段は、次の階へ進むための通常の階段
  としての機能はそのまま(降りられる)。`checkpoint` イベントを出さない
  だけで、既存の「階段を降りる」処理自体は変えない。
- 拠点の出発地点選択(`src/ui/town.ts`)は `knownCheckpoints` をそのまま
  使っているため、記録される値の集合が地方境界だけに絞られる結果、
  選択肢も自然に地方境界だけになる。UI側の追加変更は見込まない。
- 影響: 一回のダイブでの「前半の再走」が最大6階分に短縮される(現状は
  最大10階の再走)。むしろ短縮方向の変化であり、
  `design/balance-philosophy.md` の目標プレイ時間(本編クリア約15時間)
  を圧迫しない。

### 4. 地方ボスの階(`REGION_BOSS_FLOORS`)は今回拡張しない

現状 `{ 6: "oonebosuke" }` のみ。本文書では残り7つの階
(12/18/24/30/36/42/48)に新しいボスを追加しない。各ボスの具体的な
ステータス・大技(`plan/archive/region-bosses.md` の「地方ごとのボス
(初期案)」を参照)は、1体ずつ個別の `plan/` 文書に切り出して決定する。
`REGION_BOSS_FLOORS` に未登録の階は `populateFloor` が通常どおり動作する
ため、今回はそれらの階を通常のワイルドモンスターが湧く階のままにする
(追加のコード変更は不要)。

## 影響範囲の見積もり(実装セッション向け)

- `src/entities/dungeons.ts`: `MAIN_CAVE_MAX_DEPTH` の定数変更のみ。
- `src/game.ts`: `checkpoint` イベントを出す条件に「地方境界の階かどうか」
  の判定を追加する。1地方=6階の構造は今後も変わらない前提なので、
  マジックナンバーではなく `REGION_SIZE = 6` のような定数として切り出す
  ことを想定する(`depth % REGION_SIZE === 0` で判定できる)。
- `src/ui/town.ts`: 出発地点の選択肢生成は `knownCheckpoints` をそのまま
  描画しているため、コード変更は不要と見込む。
- 既存テスト(`tests/checkpoint-select.test.ts` 等)のうち「どの階でも
  既知になる」ことを前提にしている箇所は、地方境界だけに絞る仕様に
  合わせて更新が必要。

## 未決事項

- 残り7体の地方ボス本体の実装(`plan/archive/region-bosses.md` の初期案を
  元にした個別のステータス・大技の確定)は、地方ごとに別の `plan/` 文書に
  分けて今後決定する。
- 地方固有ギミック(深み・眠りの胞子・1マス幅回廊・奔流・物音・偽の階段/
  タル・第八地方の混在)も同様に、地方ごとに個別の `plan/` 文書で
  仕様化する。
- 第八地方(めざめの前庭)の「上位種・エリート個体」は、既存の
  かがやきの夢のかけら(`monster-compendium.md` で実装済みの、
  ステータス+3割の個体)がその役割を代替できると判断し、専用の新規種
  追加は本文書のスコープ外とする。
