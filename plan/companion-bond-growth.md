# 仲間のなじみ成長

仲間の成長は現状、`plan/monster-fusion.md` の夢あわせ(他の個体を糧に
種族の枠内でレベル・特技を伸ばす)と `plan/companion-evolution.md` の
成熟(種族そのものが変わる)の2つがあり、どちらも**他の個体を消費する**
という共通点がある。ここに、**何も消費せず、ただ一緒に潜り続けるだけで
少しずつ強くなる**という第三の軸を足す。名前は **なじみ**。

## コンセプト

`plan/companion-naming.md` で名前をつけた仲間に、もう1つ意味を持たせる。
夢あわせ・成熟が「素材を使って一気に伸ばす」育て方なのに対し、なじみは
**「その個体をずっと連れ添わせる」**という、正反対の方向の愛着を
数値として裏付ける。

## 仕組み

- `StoredMonster` に、その個体を連れて**踏破・チェックポイントで区切って
  持ち帰った**ダイブの回数を記録する(`plan/checkpoint-select.md` の
  「使って戻る」が成立した回数。全滅でロストした場合は当然カウントの
  しようがない)。
- 一定回数に達するたびに、ごく小さな永続ボーナスがつく。

| なじみの段階 | 必要な同伴成功回数 | 効果 |
|---|---|---|
| なじんできた | 5回 | maxHp・atk・defにそれぞれ+3% |
| すっかりなじんだ | 15回 | 追加でそれぞれ+4%(累計+7%) |
| かけがえのない仲間 | 30回 | 追加でそれぞれ+5%(累計+12%) |

**上限は+12%に固定する。** 夢あわせ・成熟の伸び幅を上回らないよう、
`design/balance-philosophy.md` のパワーバジェットの範囲に収める
(あくまで「地道な積み重ねの愛着」であって、最適育成ルートには
しない)。

## 夢あわせ・成熟との関係

- **軸(残す側)にするとき**: なじみの段階はそのまま引き継がれる
  (`plan/companion-naming.md` で名前が引き継がれるのと同じ扱い)。
- **糧(消える側)にするとき**: なじみごと消える。**なじみが進んだ個体を
  糧にするのは、育てた時間を手放す選択になる**――という重みを、
  夢あわせの意思決定に持ち込む。数値上は小さくても、「この子を使うのは
  惜しい」という感情が生まれるようにするのが狙い。
- 成熟(種族変化)が起きても、なじみの段階・カウントは引き継ぐ
  (姿が変わっても同じ個体である、という一貫性は `plan/companion-
  evolution.md` の名前引き継ぎと同じ理屈)。

## 表示

`plan/records-hall.md` の「もっとも連れ添った仲間」の記録が、この
仕組みによってはじめて数値的な裏付けを持つ。ねむり小屋の一覧では、
種族名・名前に添えてなじみの段階を小さく示す(例:「タロ(ぷるん)・
すっかりなじんだ」)。仰々しいゲージ表示は作らず、`plan/achievements.md`
と同じ「隠さない」方針で段階だけ明示する。

## データ構造

```ts
// StoredMonster(plan/monster-fusion.md)に追加
bondSuccessCount: number; // 踏破/区切って持ち帰った回数

export function bondBonus(count: number): number {
  if (count >= 30) return 0.12;
  if (count >= 15) return 0.07;
  if (count >= 5) return 0.03;
  return 0;
}
```

`bondBonus` はそのままステータス計算(`maxHp` `atk` `def`)に掛け率として
乗せるだけで済み、既存の種族基礎値・レベル・特技の計算とは独立した
最後の一段として実装できる。

## バランス上の注意

- なじみは**種族を選ばない**(ぷるんでもホネガラミでも同じ段階なら
  同じ%)。弱い種族を長く連れ添わせても強い種族には届かないが、
  「弱いなりに頼れる相棒になる」程度の底上げにはなる。
- 夢あわせ・進化(即効性・種族改変)と、なじみ(低燃費・長期)は、
  互いの存在意義を食い合わないよう、**効果の種類を分ける**
  (夢あわせ=特技の追加、成熟=種族変化、なじみ=既存ステータスの
  微増)。同じ「強くなる」でも中身が違う、という整理を保つ。
