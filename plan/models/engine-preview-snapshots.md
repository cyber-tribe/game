# モデルのエンジン内スナップショットを常に見られる場所に置く

## 経緯

キャラクターの見た目を確認するのに、いちいちゲームを起動して
該当モデルの出る場面まで進まないといけないのが辛い、という開発上の
不満への対応。

実は `tools/preview/` に全モデルのPNGが既にあるが、2つの穴がある:

1. **鮮度**: CI(`.github/workflows/models.yml`)は
   `--no-preview` でレンダリングを飛ばすため、リモートの画像は
   ローカルで誰かが焼き直さない限り古いまま残る。
2. **忠実度**: BlenderのCyclesレンダなので、**ゲーム内の見た目
   (トゥーン階調・輪郭線・ポストプロセス)と一致しない**。
   `visual-quality-uplift.md` 施策F-2で指摘済みの問題そのもの。

## 変更内容

### 1. エンジン内レンダのハーネスを作る

- `tools/preview_engine.mjs` を新設する。実行内容:
  1. `public/models/` の glb を、**実際の描画スタック**
     (Three.js+MeshToonMaterial+gradientMap+背面ハル輪郭線+
     ACES+ブルーム+グレーディング。`src/view/renderer.ts` の
     設定値を共有して使う)で読み込む最小シーンを組む。
  2. Playwright のヘッドレスChromiumで1体ずつ撮影して
     `tools/preview/<モデル名>.png` に保存する
     (既存のCyclesプレビューはこれで置き換える。二重管理しない)。
- 撮影レシピ(確認用なので軽くてよい):
  - 解像度 **512×512**、背景は市松ではなく暗めの単色+接地床。
  - カメラは正面斜め上45度(ゲームの見下ろしに近い角度)。
  - 静止(idle 1フレーム)を基本1枚。アニメーション持ちは
    attack の中間フレームを重ねた**横並び2コマ**を同じ1枚に
    収める(ファイル数を増やさない)。
  - ライトはゲームと同じ構成(キー+アンビエント。#718/#844の
    3灯規律が入ったらそれに追従)。
- 一覧ページ `tools/preview/README.md` を自動生成する
  (全画像を名前付きで並べたMarkdownの表)。GitHubでこの1ページを
  開けばスマホからでも全キャラを見渡せる。

### 2. CIで自動更新し、GitHub上で常に最新にする

- `models.yml` を拡張する:
  - main への push でモデルが再ビルドされたら、続けて
    `preview_engine.mjs` を実行し、更新されたPNGと README.md を
    **Actionsボットがそのままmainへコミット**する
    (画像だけの追いコミット。無限ループ防止に
    `paths` から `tools/preview/**` を除外しておく)。
  - PR 上では成果物(artifact)として添付するだけにする
    (オートマージ運用なので、確認は main の `tools/preview/` で
    行えば足りる)。
- レンダリング時間は全モデルでも数分に収まる想定
  (glbロード+1フレーム描画のみ。Cyclesのサンプリングが無い分
  既存プレビューより軽い)。超えるようなら変更のあった glb だけ
  撮り直す差分モードを足す。

### 3. renderer.ts との設定共有

- トゥーン階調・露出・ブルーム等の定数を `src/view/` から
  ハーネスが直接 import できるよう、必要なら定数を
  `src/view/renderConfig.ts` に切り出す(値の二重定義を禁止。
  ゲーム側の絵作りを変えたらプレビューも同じ絵になる、を保つ)。

## 受け入れ基準

1. GitHub上の `tools/preview/README.md` を開くと、全モデルの
   最新スナップショットが一覧で見られる。
2. スナップショットの絵柄がゲーム内と一致する(トゥーン階調・
   輪郭線・ポスト込み。同一モデルをゲーム画面と並べて目視確認)。
3. `tools/models/*.py` を変更してmainにマージすると、人手なしで
   該当PNGが更新される。
4. モデル追加時に、リストへの手登録なしで自動的に撮影対象になる
   (`public/models/` の走査で拾う)。
5. 撮影ジョブがCIの所要時間を大きく延ばさない(モデル全量でも
   +5分以内。超える場合は差分モードを実装)。

## 対象外

- 高解像度・ターンテーブル動画などの豪華な出力(確認用途に不要)
- 村・ダンジョンのシーン全体のスクリーンショット
  (`visual-quality-uplift.md` 施策F-1のバリューチェックは別途)
