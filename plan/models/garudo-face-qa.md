# 顔一致QA ― 「似ているか」を機械が判定する評価関数

## 経緯

ユーザー指摘(2026-09-01):

> Claude Codeの造形センスが悪いのではなく、**現在の制作フローだと
> "顔が似たかどうか"を客観的に判定できない構造**になっているのが本質。
> プロンプトを強くするより評価関数そのものを実装するべき。
> 「似ていると思う?」と判断させるのではなく、「設定画との差は12.4px。
> 左目が4px外、顎が9px太い。直せ」という問題に変える。

実際、`overlay_sheet.py`(全身シルエット)まではあったが、顔は
レンダーを見て「近づいた気がする」で進めており、何度直しても
収束しなかった。**視覚的な自己評価を最終判定にしない**ための仕組みを
入れる。

## 実装(tools/compare_face.py)

    tools/venv/bin/python tools/compare_face.py garudo

1. モデルを組み、**平行投影・陰影なし**で顔を固定ウィンドウ
   (モデル座標 x±0.16・z0.74〜1.02、1ユニット=2000px)へ描く。
   陰影を消すのは設定画のベタ塗りと画素の色を直接比べるため。
   Workbenchのフラット表示はヘッドレスでEGLを要求して使えないので
   (実測: libEGL.so.1が無い)、全マテリアルをEmission化して1サンプルで描く。
2. 設定画の正面図を、全身シルエットの外接箱から求めた倍率で
   **同じウィンドウへ再標本化**する。これで両者が同じ物理スケールに乗る。
3. 同じ判定器で肌・髪・暗部を分類し、以下を数値で出す:
   - **ランドマーク誤差**(mm): 目の間隔・目の高さ・目の幅と高さ・
     あご先・顔の最大幅とその高さ・髪の最大幅とその高さ・髪の頂点・
     目の高さでの頭部幅
   - **高さごとの幅プロファイル**(肌・頭部を8段)。1点の最大値では
     「髪が顔にどう掛かっているか」が分からないため
   - **シルエットIoU**(肌・髪)
4. 出力画像 `tools/preview/face/<名前>-compare.png`
   (左=設定画・中=モデル・右=重ね合わせ)。

判定器の作り方で分かったこと(いずれも実測):

- 生成りのシャツは肌と色相が近く、**彩度でしか分けられない**
  (シャツ0.17に対し肌0.29)。首から下は計測に混ぜない。
- **髪と眉は同色**なので色では分けられない。**大きさ**で識別する
  (眉は細長い小さな塊、髪は高さのある大きな塊)。
- 高さ帯で切ると目の輪が左右に割れて幅が半分に見える。帯は実体より
  広めに取り、塊の大きさで選ぶ。
- 設定画の眉は前髪と融合しており検出が安定しない。**参考値**として
  出すだけで合否には入れない。

## この評価関数で見つかった実際のずれ(初回計測)

| 項目 | 設定画 | モデル | 差 |
|---|---|---|---|
| 目の間隔 | 63.3mm | 71.8mm | +8.5 |
| 目の高さz | 846.1 | 855.6 | +9.5 |
| 目の幅 | 29.2mm | 34.5mm | +5.3 |
| 髪の最大幅 | 176.5mm | 216mm | **+39.5** |
| 目の高さでの頭部幅 | 156.5mm | 183mm | **+26.5** |

さらに幅プロファイルから、**設定画の横髪は目の高さで顔の脇を20mm
覆い、あご付近(z0.79)まで垂れる**ことが判明した。板(平面)の房では
顔の膨らみに負けて裏へ隠れる(目の高さで肌が45mm余計に見えた)ため、
頭の曲面に沿う**角度スライスのシェル**(`_hair_shell`)へ作り替えた。

## 使い方(修正のループ)

1. `compare_face.py`を走らせる
2. 差が大きい項目から`garudo.py`の数値を直す
3. 1に戻る。**FAILが消えるまで繰り返す**

「似せて」ではなく「誤差を減らせ」という問題になるので、収束する。

## 第2段階: 意味的ランドマーク回帰(実装済み)

集約量(目の間隔・顔の最大幅など)だけでは「同一人物性」は測れない
という指摘を受け、**顔の部位そのもの**を点として測る回帰を足した。

測っている点(22〜25点): 目頭・目尻・上瞼・下瞼・目の中心(左右)、
眉の下端3列(左右平均)、口の左右と中央、頬の最大幅点(左右)、
顎の左右、顎先、生え際中央。設定画とモデルの**同じ検出器**で取り、
mm単位の距離誤差・平均誤差・最大誤差・ずれの大きい順を出す。

受け入れ基準: 平均<=3.0mm / 最大<=6.0mm。

### この回帰で見つかった差と対処

| 見つかった差 | 対処 |
|---|---|
| 目尻が水平(設定画は12°下がる) | パッチごと傾ける`EYE_TILT_DEG` |
| 目頭・目尻が縦の中心にある(設定画は中心より上) | アーモンドの上下半径を分ける |
| 生え際中央が37mm高い | 眉間へ垂れる中央の房を追加 |
| 首がシャツ色に塗られ、あご先の検出が20mmずれる | 肌の開始をz0.778→0.760へ |
| 眉が15〜20mm高い | 眉を目パッチ上端のすぐ上(z0.870)へ |

平均誤差 10.8mm → **5.8mm**、最大 42.0mm → **12.0mm** まで収束。

### 検出器で分かったこと(追記)

- 口の線は肌より暗いだけで「暗部」判定に入らない。彩度で拾う専用の
  マスクが要る。設定画側の口は今も安定検出できておらず、合否から
  除外している(モデル側は検出できている)。
- まぶたの上下端は塊の外接から取る。中央列だけで見ると、まぶたの線と
  虹彩が白目で切れている場合に薄い帯だけを拾う。
- 眉は設定画が左右非対称に描かれているため、左右平均で測る。

## 第3段階: 顔をSVGで持つ(実装済み)

目・眉・鼻・口・頬を`design/characters/garudo/face.svg`へ移し、
**2Dデザインとして独立に編集できる**ようにした。Pythonの数値で
テクスチャを手続き的に描くのをやめている。

要点は**SVGの座標系を顔一致QAのウィンドウと同一にした**こと:

    SVG(sx, sy) → モデル(x, z):  x = sx/2000 - 0.16,  z = 1.02 - sy/2000
    1 SVG単位 = 0.5mm

これにより、QAが出す「左目尻が3mm下」がそのまま「SVGのその制御点を
6単位上げる」という編集になる。修正指示が座標編集に一対一で対応する。

モデル側は`_decal_sample(x, z)`でこのラスタライズ画像を**平面投影**で
引き、透明なところは下地(肌)の色をそのまま使う。目のパッチも同じ
デカールから`bake_albedo`で焼くので、顔とパッチで絵がずれない。

    node tools/render_svg.mjs --transparent design/characters/garudo/face.svg
    cp tools/preview/garudo/face.png \
       design/characters/garudo/generated/garudo-face-decal.png

`--transparent`(今回追加)を付け忘れると背景が白で焼かれ、顔全体が
白くなる(実測)。

### 効果

| 指標 | 手続き描画 | SVG |
|---|---|---|
| 目尻L | 4.1mm | **0.0mm** |
| 目頭L | 5.5mm | **0.7mm** |
| 下瞼L | 5.7mm | **0.0mm** |
| 眉下端0 | 9.2mm | **0.7mm** |
| 平均誤差 | 5.8mm | **3.6mm** |

## 第4段階: SVGを設定画からトレースする(実装済み)

第3段階のSVGには**根本的な欠陥**があった。あの形は設定画をなぞった
ものではなく、**QAが出す8点(目頭・目尻・上下瞼・目の中心・眉下端3点)に
合うように描いたもの**だった。だから点は合うのに顔は似ない。
指標を最適化して対象を最適化していない、典型的な失敗である。
「設定画とかけ離れている」という指摘はそのとおりだった。

### 部位を探す方式は成立しない(実測)

最初は「目・眉・口をそれぞれ探して輪郭を取る」トレーサを書いたが、
設定画を測ると成立しないと分かった。

| 分け方 | 結果 |
|---|---|
| 色 | 髪・まつ毛・虹彩・口が**同じ茶系の明度ランプ上**にある。分けられない |
| 連結 | 暗部の最大連結成分が襟・首まで繋がった**107,174px の1つの塊**。分けられない |
| 大きさ | 帯と大きさで絞ると、抽出結果が髪の破片だらけになった(実測) |

前髪が眉と目にかぶさっているので、そもそも「眉だけ」の領域が
設定画に存在しない。

### 明度で量子化して領域ごとトレースする

部位を探すのをやめた。顔の範囲を**明度で5段に量子化し、その領域を
まるごと穴つきでトレースする**(`tools/trace_face_svg.py`)。

- 段は `val <= 0.66 / 0.45 / 0.28 / 0.155` の累積マスク。明るい順に
  重ねるので、暗い段が持つ穴から明るい段(白目)が覗く
- 各段の色は**その段に入った画素の平均色**。手で選ばない
- 輪郭はムーア近傍追跡 + Douglas-Peucker(許容1.1 = 0.55mm)
- 塗る範囲は**モデルの頭の断面表(HEAD_RINGS)を5mm内側へ縮めた形**。
  楕円で切ると設定画の**輪郭線**まで塗ってしまい、あごに黒い帯が
  乗って「あご紐」に見えた(実測)。輪郭はジオメトリが持つもので、
  塗りが持ってはいけない
- 設定画の顔は少し傾けて描かれているので、**両目の中点が正中・EYE_Z へ
  来るように平行移動してから**写す

前髪が顔にかかる部分も塗りとして入るが、モデルの髪ジオメトリが手前に
あるので二重にはならず、髪の無い所には設定画どおりの前髪が乗る
(`plan/models/hand-painted-standard.md` の「モデリングでキャラクターを
完成させようとしない」)。

### 目の高さの実測ずれ(EYE_Z)

デカールを合わせた時点で**全ランドマークが一律 4.5mm 下**に出た。
`EYE_Z = 0.8415` が、設定画をQAのウィンドウへ写した実測値 0.8461 より
低かったため。あご先・顔の最大幅の高さ・髪の最大幅の高さは 1.5mm 以内で
合っていたので、目だけが低いモデル側の誤りと判断し `EYE_Z = 0.8460` へ
修正した。

### 効果

| 指標 | 想像で描いたSVG | 設定画をトレース |
|---|---|---|
| 平均ランドマーク誤差 | 3.6mm | **2.3mm** |
| 目まわり8点 | 0.0〜0.7mm | 0.0〜0.7mm |
| 眉下端0〜2 | 0.7〜9.2mm | **0.3〜1.3mm** |
| skin IoU | 0.55 | **0.82** |
| hair IoU | 0.62 | **0.71** |

数値以上に大きいのは、**顔が設定画の顔として読めるようになった**こと。
目・眉・鼻・口が設定画そのものの形になっている
(`tools/preview/face/garudo-face-side-by-side.png`)。

なお、輪郭線を塗らないようにした結果 `顎先` の誤差は 3.0mm → 9.5mm へ
悪化した。これは**改善である**。設定画の顎先は x=+9.0(顔が傾けて
描かれている)で、モデルは左右対称の x=0。塗った輪郭線が誤差を
埋めていたのは指標を騙していただけだった。

## 第5段階: 髪の輪郭を測る(実装済み)

第4段階で顔の造作は合ったが、髪は「ヘルメット」のままだった。
これも目視でなく測る。`tools/compare_face.py` に2つ足した。

### 1. 左右別の輪郭(±12mm)

幅(span)だけでは足りない。**設定画の髪は左右非対称**で、幅が合って
いてもどちら側が出ているかが違うと別人に見える。実測:

| z | 設定左 | 設定右 |
|---|---|---|
| 0.790 | -67.0 | **+80.5** |
| 0.870 | -80.0 | **+104.5** |
| 0.890 | -84.5 | +96.0 |

+x側が大きく張り出している。左右対称に作っていたモデルは+x側が
17〜20mm足りなかった。横髪シェルを左右で別の半径にし、こめかみから
+x側へ跳ねる房を足して合わせた。

### 2. 上部輪郭の凹凸(設定画比70%以上)

高さごとの幅の1次差分の絶対値の合計。**毛先の尖りがあるか**を測る。
初回は 設定画589px に対し モデル319px(54%)。数値でヘルメットが出る。

### この指標を一度騙してしまった(記録)

凹凸を上げるために、地肌から**垂直に突き出す短いトゲ**を8本生やした。
凹凸は 349→571px(97%)になり判定はokになったが、見た目は
**ウニ**になった。指標は通ったのに品質は下がっている。第3段階の
「ランドマークに合わせて顔を想像で描く」とまったく同じ失敗である。

原因は、指標が「輪郭が上下に振れること」しか見ておらず、
**その振れが房として成立しているか**を見ていないこと。設定画の輪郭が
ギザギザなのは、頭に沿って走る長い房の**毛先が高さ方向にずれて終わる**
からで、地肌に垂直なトゲが生えているからではない。

作り直した。分け目(頭頂やや+x寄り)から放射状に流れる長い房を9本置き、
土台を上段で8〜10mm絞って、**輪郭を土台ではなく房の毛先が作る**ように
した。凹凸は71%と控えめだが、見た目は房の重なりになった。

**指標が通っても、必ず絵と並べて見ること。** 数値は「見なくてよい」
理由にはならず、「見ただけで判断しない」ためのものでしかない。

### 額の平らな明るい面(z-fighting)

もう1つ、測って分かった不具合。髪の土台の前面が、z0.892〜0.912で
頭の表面と**1mm以内で重なっていた**(実測: 頭-68.5 / 土台-68.0)。
額に平らな明るい面が出ていたのはこれ。土台のリングを高さごとに
頭の前面と比べ、顔のある高さでは頭の中へ8mm以上沈め、頭頂側では
逆に外へ出して髪の厚みを持たせるようにした。

### 横髪が頬を隠していた

「顔の脇にある髪の厚み」(頭部の幅 − 肌の幅、片側)を実測すると:

| z | 設定画 | 直す前のモデル |
|---|---|---|
| 0.790 | 37.5mm | 30.5mm |
| 0.810 | **6.5mm** | **26.5mm** |
| 0.830 | 2.0mm | 6.8mm |
| 0.850 | 30.8mm | 35.8mm |

**頬の高さでは設定画の髪は顔の前へ回り込まない。** 横髪シェルの
`deg0`(前側の端)は角度なので、正の値にすればシルエットの幅
(x=rx)は保ったまま前への回り込みだけ止められる。頬の高さで
`deg0`を正に、こめかみと目の高さで負にした。あごの脇の房も
z0.818→0.802へ下げ、頬から外した。

### 髪の色

設定画の髪の平均色を測ると (0.320, 0.242, 0.174)、モデルは
(0.298, 0.205, 0.130) で**暗く赤に寄っていた**(特に青が44/255低い)。
`HAIR` を実測値に合わせて (0.33, 0.25, 0.185) にし、差は2.4/255に
なった。

### あごを横切る水平な継ぎ目

`_body_color` に `if pos.z < 0.800: shade = 0.50`(首の影)という
**zだけの段**があり、口の高さに顔幅いっぱいの境目が出ていた。
首はあごの奥(+y)にあるので、yでも絞ってなだらかに落とすようにした。

### 口が破線になっていた

設定画の口は x-13..+13mm で val 0.31〜0.92、まわりの肌は 0.945〜0.96。
量子化の段(0.66)では真ん中(0.87〜0.92)が抜けて**2本の破線**になる。
段を0.80まで上げると今度はあご下の影の境目が顔を横切る硬い帯になった
(実測)。**口の帯(z0.784〜0.812・|x|<30mm)の中だけ**しきい値を
0.93に緩めて解決した。

### 効果

| 指標 | 第4段階 | 第5段階 |
|---|---|---|
| 髪の左右輪郭(8高さ) | 最大-21.5mm NG | **最大-8.0mm ok** |
| 上部輪郭の凹凸 | 319px(54%) NG | **419px(71%) ok** |
| 頬の高さの肌の幅(z0.870) | -12.5mm | **±0.0mm** |
| 髪の平均色の差 | 44/255 | **2.4/255** |
| hair IoU | 0.711 | **0.770** |
| 額の平らな面・あごの継ぎ目・破線の口 | あり | 無し |

## 第6段階: 目が「薄い板」に見えていた件(実装済み)

レンダリングすると目だけ**顔に貼った板**に見える、という指摘。
原因は1つではなく、測ったら4つあった。うち1つは**まばたきが
まったく効いていない**という機能の不具合だった。

### 1. まばたきが効いていなかった(機能の不具合)

`_eye_panel` は `src/view/blink.ts` が上下に潰すためだけに存在する
別メッシュ。ところが**顔テクスチャ側にも同じ目が焼かれていた**ので、
パッチを5%まで潰しても下の目がそのまま残り、細い線が1本増えるだけ
だった(実測)。

`_in_eye_panel(x, z)` を足し、パッチの内側では顔テクスチャに目を
描かないようにした。パッチだけが目を持つので、潰した瞬間に
「閉じた目」になる。同じ間違いを二度としないよう、組み立て時に
`assert` で確かめている。

パッチの向きと大きさは `_eye_basis(side)` に切り出して、パッチ本体と
この当たり判定で**同じ値**を使う(別々に持つとずれる)。

### 2. 材質だけ光沢が強かった

パッチ roughness 0.35 に対し顔本体 0.80(実測)。パッチにだけ強い
鏡面が乗り、肌色の余白ごと明るい楕円として浮き上がっていた。0.80 へ揃えた。

### 3. パッチが目の絵より大きすぎた

パッチ 31.9×39.6mm に対し目の絵は 32.0×27.5mm(デカール実測)。
上下に6mmずつ肌色の余白があり、そこが輪っかに見えていた。
**目の絵の外接箱を2mm弱の余白で包む**大きさ(36.4×32.5mm)にした。
位置と大きさは `EYE_PANEL_*` として独立に持つ。`EYE_X`/`EYE_Z` は
デカールの整合(`tools/trace_face_svg.py`)に使う値なので触らない。

### 4. テクセル密度が6倍ちがった

顔 894 texels/unit(0.9px/mm)に対しパッチ 5.3px/mm。**ぼけた顔の上に
鋭い目のシールが貼ってある**状態。glbは700KBまで(`tests/models.test.ts`)
なので本体テクスチャは512のまま、UVの取り分で稼いだ:

| boost | 顔 | 最低密度 | 充填 |
|---|---|---|---|
| 2.5(元) | 894 | 153 | 47% |
| 5.0(採用) | **1212** | 104 | 59% |
| 6.0 | 1232 | 88 | 58% |

6.0まで上げても頭打ちで、他の島の最低密度だけが落ちるので5.0にした。
パッチ側も192→128pxへ落として差を6倍→3倍に縮めた。

### 浮かせ量はふちで0へ

パッチは顔に埋まらないよう法線方向へ浮かせているが、一定量だと
境目に段ができる。中央1.2mm・ふち0.2mmへ落とすようにした
(0にするとZ争いになる)。

### 残り

パッチの輪郭に沿って**2%ほどの明るさの差**が残る(実測: 余白部分の
差は最大0.018)。パッチと顔で法線はどちらもFACE_C中心の放射方向で
一致しているので、面の分割の粗さの違いによる補間差と見ている。
消すには顔メッシュを細かくする必要があり、次段階の
「顔メッシュの専用トポロジー」と同じ話になる。

## 全身シルエットの残差(ブーツ)

顔から離れるが同じやり方。`tools/overlay_sheet.py` に**左右別の端**を
足した。幅(span)だけだと、片側が出て片側が引っ込んだ差し引きゼロを
見逃す(実測: 腕は幅では合っているのに、重ねると上腕の外側が赤・手が
青で、腕の角度が違っていた)。

### ブーツ -31px(-43mm)

まず**つま先の回転の符号が逆**だった。外股のつもりが内股で、角度を
20°→28°と増やすと幅がむしろ減った(190→186px)ので気づいた。

符号を直しても足りず、設定画のブーツを拡大して見ると**編み上げの
作業靴で、一番広いのは丸く張り出したつま先**だった。足首を膨らませ
かけたのは読み違いで、ロフトの最大幅をつま先側(0.100〜0.132)へ
寄せて解決した。

靴底の箱が甲より大きく、回転した角が靴の丸みより外へはみ出して
**接地面に平たいツバ**が出ていたのも直した(0.130→0.112幅)。

| 正面88% すね | +4px | +4px |

## 第7段階: 容量上限を役どころで分け、顔の解像度を上げる

「完成度を優先して上限を緩和/撤廃」の指示を受けての作業。

### 上限は撤廃せず、役どころで分けた

`tests/models.test.ts` は全キャラ一律 700KB / 12,000三角形だった。
主人公は**常時画面に1体だけ映り、一番カメラに寄る**。同時に十数体
描かれるモンスター・村人と同じ枠を掛ける理由がないので、表で分けた。

| | 従来 | 主人公 |
|---|---|---|
| ファイル | 700KB | **2600KB** |
| 三角形 | 12,000 | **24,000** |

撤廃しなかったのは、上限が無いと「なんとなく重い」が積もるため。
数字は変えられるが、無いと気づけない。

### 顔テクスチャ 512 → 2048

顔の密度 1,212 → **3,911 texels/unit**(3.9px/mm)。UVのboostも
5.0→3.0へ戻せたので、他の島の最低密度も 104 → 558 に上がった。
目パッチも128→256px。

### 目のドットが消えなかった

ここで詰まった。顔テクスチャを4倍にしても、レンダリングすると目が
2mm角のブロックのままだった。順に測って原因を3つ潰した。

1. **デカールのラスタが2,000px/unit**しかなかった。
   `tools/render_svg.mjs` に `--scale=N` を足し、3倍で焼くようにした
   (6,000px/unit)。
2. **`_decal_sample` が最近傍**だった。双一次補間にした。切り捨ては
   常に半画素手前へずれる副作用もあった(実測: x=0.030がfloat32では
   0.0299999になり隣の画素を引いた)。
3. **設定画を最近傍で拡大していた**。これが本命。設定画は顔の幅で
   0.65px/mmしかなく、最近傍で2,000px/unitへ引き伸ばすと1画素が
   **2.2mm角のブロック**になる。なぞった輪郭がそのまま2.2mm刻みの
   階段になっていた。双一次補間で拡大してからなぞるようにした
   (+ 輪郭にChaikinの角切り2回)。

### 測る側も揃えた(重要)

デカールを滑らかにしたら、**QAの数値が悪化した**(肌IoU 0.82→0.76、
平均誤差 2.4→3.0mm)。基準側の設定画だけが最近傍でギザギザなので、
モデルが滑らかになるほど不利に出る、という逆向きの圧力がかかっていた。

`compare_face.resample_sheet` も双一次を既定にした(整合の重心を測る
ときだけ `smooth=False`。ぼかすと目と眉の塊が繋がって重心が9.6mm動く)。
標本位置は箱の再構成に合わせて0.5引く。

これで 肌IoU 0.819 / 平均2.7mm に戻り、**基準が細かくなったぶん髪の
判定は厳しくなった**(上部輪郭の凹凸の基準が589→676px)。

### 髪の輪郭を1行ずつ突き合わせた

厳しくなった判定に対し、設定画とモデルの輪郭を0.006刻みで並べた。
z0.915の+x側だけ設定画が+100.5mm・モデルが+79.5mmと**21mm**開いて
いるのが最大の差で、そこへ房を1本足した。ほかに毛先の高さを散らす
房を4本。

| 指標 | 第6段階 | 第7段階 |
|---|---|---|
| 顔のテクセル密度 | 1,212 | **3,911** |
| デカールのラスタ | 2,000px/unit | **6,000px/unit** |
| skin IoU | 0.816 | **0.819** |
| hair IoU | 0.770 | **0.793** |
| 平均ランドマーク誤差 | 2.4mm | 2.7mm(基準が細かくなった) |
| 上部輪郭の凹凸 | 71%(旧基準) | 62%(新基準・旧基準比では改善) |
| glb | 687KB | 1,119KB(上限2,600KB) |

## 第8段階: 手をミトンから革手袋へ

設定画の手は**指の分かれた革手袋**(手首に折り返しあり)。モデルは球+
親指の球で、丸い塊=ミトンだった。

設定画を測ると手袋は手首から指先まで約110mm、**うち指が半分**。
手のひらの球を小さくして(0.030→0.024)、指4本と親指をチューブで
足した。ボクセルは指が潰れない細かさが要るので0.006→0.0038、
三角形の目標も5,200→9,000へ(上限を役どころで分けたので取れる)。

### 指の隙間はジオメトリでは作れない

指を隙間つきで置いても、**3.8mmボクセルでは4mmの隙間が埋まって
ヘラになる**(実測)。設定画も指は接していて線で分かれているので、
`_body_color` で**指の間の線を描く**ことにした
(`plan/models/hand-painted-standard.md` 規約3)。

判定は「一番近い指と二番目に近い指の距離の差が1.6mm未満」。
指の軸は `FINGERS`/`_finger_axes()` としてモジュール定数に置き、
**ジオメトリと塗りで同じ定義を使う**(別々に持つと線が指からずれる)。

### 指先がズボンの色になっていた

手袋の色は手のひらの球からの距離だけで判定していたので、指が範囲外に
なって**ズボンの青**が出ていた(実測: レンダリングで指先が青)。
指の軸からの距離も見るようにした。

なお手首の折り返しを距離場の値で帯にしようとしたら、手の甲が丸ごと
暗くなった。距離場は球の表面でほぼ一定なので帯にならない。折り返しは
未実装。

### 塗りのコスト

指の距離計算は全身のテクセルで走るので、ビルドが33秒→54秒になった。
手から75mm以上離れたら計算しないようにして34秒へ戻した。

| | 前 | 後 |
|---|---|---|
| 手 | 球+親指の球 | 手のひら+指4本+親指 |
| 三角形 | 10,272 | 14,072(上限24,000) |
| glb | 1,119KB | 1,285KB(上限2,600KB) |
| ビルド | 33秒 | 34秒 |

## 第9段階: まばたきをテクスチャ切り替えへ(実装済み)

指示された方式:「3D変形で表情を作るのではなく、**設定画として完成した
2D表情を3D顔上で切り替える**」。

### 目のための板はやめた

最初はまばたき用のパッチ(顔に沿う楕円の板)にアトラスを貼った。
しかし**目だけ特別扱いする理由はもう無い**。板は材質・解像度・法線が
本体とずれるため、どれだけ詰めても「顔に板が乗っている」ように見える
(第6段階でその4つの原因を潰したが、輪郭に2%の差が残った)。

いまは**顔のUV島だけを2つ目のマテリアル**に分け、そこに
open / half / closed を横に並べた1枚のアトラスを貼っている。目は
顔テクスチャそのものに描かれ、切り替えはUVのオフセットだけ。
余分なジオメトリはゼロになった。

### 閉じ目は設定画から取る(想像で描かない)

設定画の**右下に「表情バリエーション」**があった(通常・きりっと・
驚き・怒り・笑顔・眠そう)。**「眠そう」の目がそのまま中立の閉じ目**
なので、これをなぞる。開いた目も同じ「通常」から取り、3状態で絵柄と
線の太さを揃えた。半目は、閉じたまぶたを開いた目の上端との間へ
**持ち上げて**作る(形は設定画のまぶたのまま)。

顔の他の部分は三面図の正面図のまま。表情の区画は目〜あごが12%短く
描かれており、顔全体を差し替えると口とあごが上がる(実測)。

### 表情の区画を合わせるのに目を使ってはいけない

`eye_pair`は高さ帯の中の大きな暗部を取るので、位置が合っていない
途中の段階では**眉を目と間違える**。実測で目の間隔が 57→66→95→60mm と
振動し、最後は目の十字が眉の上に乗った。区画の外接箱の幅で合わせるのも
駄目で、あれは髪ではなく**肩幅**だった。

`find_eyes_px`(明度0.25以下・顔の内側・縦長でない塊)で目を直接
見つけて合わせる。しきい値0.30では前髪と繋がり、0.20では片目しか
残らない(実測)。

**較正は「通常」で1度だけ**行い、他の表情はその値を使う。表情ごとに
測り直すと、閉じ目のまぶたが開いた目と同じ高さへ引き上げられてしまう
(通常の目はy=66、眠そうのまぶたはy=76。この20mmの差こそが閉じ目の情報)。

### 顔の島を切り出すときの落とし穴

| 症状 | 原因 |
|---|---|
| 顔の密度が半分(3,911→1,980) | 島に**後頭部**まで入っていた |
| 顔がタイルの3.7%しか占めない | 球で切ると島が断片に割れ、遠くの断片が外接箱を広げていた |
| 高さ方向が32%しか使えない | 縦横比を保って正規化していた(島はUV上で3:1) |

順に、(1) 球にyの上限を足して前面だけにする、(2) その部位の島だけを
`pack_islands`で寄せてから外接箱を取る、(3) 縦横を独立に伸ばす、で
タイルの78.5%を使えるようにした。

### 差し替える範囲と縦の縮尺

目を差し替える範囲(`eye_zone`)は、**目の絵の外接箱をぎりぎり包む楕円**
にする(デカール実測 x17.0..49.0 / z830.5..858.0 → 半径18.2×16.3mm、
中心z 0.8442)。広げると目の外側の肌やまつ毛の先まで表情の区画の絵に
置き換わり、正面図の絵と混ざって目が薄く見える(実測)。

範囲を眉まで広げていたときは「目の高さが正面図より6mm低い」と出て
いたが、これは**眉を目の一部として測っていた**ための誤検出だった。
正しい範囲で測り直すと 区画27.2mm / 正面図28.0mm で、縦の補正は
x1.028(ほぼ等倍)で済む。

### 実行時(src/view/blink.ts)

- `blink="eyelid"` のノードから、`blinkMaterial` の名前で顔のメッシュを
  探す(glTFの複数プリミティブはthreeで子メッシュに分かれる)。
- **マテリアルとテクスチャをインスタンスごとに複製**する。
  `SkeletonUtils.clone`は両方を共有するので、複製しないと1体まばたき
  しただけで同じ種族が全員同時に目を閉じる。
- 進み具合(0=開〜1=閉)をコマへ量子化して `map.offset.x` を書く。
  同じコマなら書かない。従来のスケール方式(モンスターの`white`/`pupil`)も
  そのまま残してある。

### QAの整合基準を安定させた

この作り替えで肌IoUが0.82→0.74に落ちたが、**髪のIoUも同じだけ落ちて
いた**。髪は一切触っていないので、モデルではなく測定側が動いたと分かる。
整合量を固定して測り直すと 0.799/0.787(元は0.819/0.793)で、実質ほぼ
同じだった。

原因は、設定画をモデル側で測った両目の中点へ合わせていたこと。目の
描かれ方が1.5mm変わるだけで基準が動く。モデルは左右対称に作ってあるので、
**設定画の両目の中点をモデルの正中(x=0)へ合わせる**ようにした。
`FACE_QA_SHIFT` 環境変数で整合量を固定して比べられるようにもした。

| 指標 | 第8段階 | 第9段階 |
|---|---|---|
| 目のジオメトリ | パッチ2枚(162面) | **無し** |
| まばたき | 上下スケールで潰す | **3コマのテクスチャ切り替え** |
| 閉じ目 | 導出(描き起こし) | **設定画「眠そう」をトレース** |
| skin IoU | 0.819 | 0.782(整合基準を変更) |
| hair IoU | 0.793 | 0.780 |
| 三角形 | 14,072 | 13,784 |
| glb | 1,285KB | 1,129KB(上限2,600KB) |

### 将来の拡張(仕様のとおり)

- 左右の目を独立制御(ウインク): 顔の島を左右で分けるか、コマを
  「左だけ閉じ」「右だけ閉じ」まで増やす
- 眉・口の表情差分: 設定画には**6表情すべて**があり、区画の位置は
  `face-reference.json`の`expressions`に測って書いてある。コマを
  増やすだけで乗る

## 第10段階: 頭のロフト断面を露出した肌の輪郭へ合わせる(実装済み)

第9段階までの残差の主犯は顔の造作ではなく**頭の形**だった。
髪を毛束へ作り替えた(`garudo-hair-clumps.md`)あとに測り直すと、
髪側の指標はすべて基準内に入ったのに肌・髪のIoUが伸びず、
差は頭そのものに残っていた。

### 測り方

正面図の**露出した肌**の輪郭を高さごとに実測する(4mm刻み)。
髪に隠れる高さは測れないので、そこは髪の輪郭から
「Hair Cap(頭+4mm)がそれを超えてはいけない」で逆算する。

行の端は3画素つながっていることを条件にする(1-5)。

| 高さz | 設定画の肌の幅 | 旧モデル | 差 |
|---|---|---|---|
| 0.782 | 43.0 | 69.5 | **+26.5** |
| 0.790 | 68.5 | 82.5 | +14.0 |
| 0.798 | 87.0 | 95.5 | +8.5 |
| 0.806 | 95.0 | 110.5 | +15.5 |
| 0.814 | 122.0 | 126.5 | +4.5 |
| 0.818 | 132.0 | 133.5 | +1.5 |

**顎が根本的に太かった。** z0.818より上はもともと合っている。

頭頂は髪の輪郭から: 設定画は z0.950 で 103.5mm しかないのに、
旧モデルは頭 116mm + cap 8mm = 124mm あった。

### 奥行き(ry)の裏取り

正面図では奥行きは測れないので、側面図で確かめた。顎の高さ
(z0.791〜0.799)で設定画 88.5mm 対 旧モデル 102mm。
**幅の比0.83と奥行きの比0.87がほぼ一致した**ので、rxとryを同じ率で
絞ってよいと判断した(側面図はまだQAへ組み込んでおらず、位置合わせが
無いので比だけを使う)。

### 結果

リングを4本増やし(z0.778/0.790/0.802/0.812)、顎と頭頂を絞った。

| 項目 | 前 | 後 | 基準 |
|---|---|---|---|
| ランドマーク平均誤差 | 3.5mm | **2.9mm ok** | <=3.0 |
| 顎L / 顎R | 7.0 / 10.5mm | **1.5 / 2.0mm** | |
| 生え際中央 | 6.5mm | **0.0mm** | |
| 肌 IoU | 0.783 | **0.810** | >=0.90 |
| 髪 IoU | 0.746 | **0.750** | >=0.80 |
| 上部輪郭の凹凸 | 82% | **88%** | >=70% |
| z=0.810 の肌の幅 | +10.5mm | **+0.5mm** | |

**ランドマークの平均誤差が初めて基準(3.0mm)を通った。**

### 残る最大誤差は設定画自身の左右差

最大誤差は 顎先11.5mm・頬L9.0mm・頬R6.0mm。いずれも設定画が
左右非対称に描かれているためで、

- 頬: 設定画 +78.0 / -63.5(**差14.5mm**)、モデル ±69.0
- 顎先: 設定画 +11.0、モデル 0.0

モデルは左右対称なので**設定画の左右差のちょうど半分**が誤差として
出る(実測: 頬の誤差9.0と6.0の平均7.5 ≒ 14.5/2)。
左右対称を保つ限りこれ以上は詰まらない。

### 「目の下瞼が無い」は誤診だった(第13段階で訂正)

`目の高さ` が設定画26.0に対しモデル22.8で基準外だったので「下瞼の線が
描かれていない」と書いたが、**モデルの欠陥ではなかった**。詳細は
第13段階。

## 全身シルエットの物差しを直す(2026-09-02)

腕の角度を詰めようとして、**物差しが壊れていた**ことに気づいた。

### 1. 設定画の切り出しがAポーズの手を切っていた

`front_crop` は `[205, 495, 440, 950]` だったが、正面図の実際の左右端は
x194〜441。手首の高さで「設定画の幅=切り出し幅」になり、
**設定画の腕が途中で消えて**いた。これを信じると「モデルの腕が長すぎる」

## 第11段階: 素手と手袋を別々に作り、手袋を装着する(実装済み)

### これまで「手」が無かった

手は**手袋しか無かった**。球1個+管5本を融合ボディへ混ぜ、表面を
「手のひらの球からの距離」で革色に塗っていただけで、素手のジオメトリは
存在しなかった。指の隙間はボクセル(3.8mm)で埋まるので、
分かれ目は塗りの線でごまかしていた(=ヘラに線を描いたもの)。

### 方式: 1つの骨格から素手と手袋を作る

```
手の骨格(手首・手のひら・指4本・親指)
   ├ grow = 0        → 素手      garudo_hand
   └ grow = 革の厚み  → 手袋 + 折り返し garudo_glove
```

`_hand_parts(side, grow, prefix)` が両方を作る。**別々に形を書かない**の
が要点で、書き分けると「手袋が手に入っていない」事故になる。

### どちらも融合ボディに入れない

- ボクセル3.8mmでは指の隙間(4mm)が消える
- 融合は表面を数mm膨らませるので、**素手が手袋を突き抜ける**
  (実測: 指だけ素肌色で出た)

どちらも別ジオメトリにして手のボーン(`elbow.L-hand.L`)へ剛体で
追従させる。前腕との継ぎ目は手袋の折り返しが隠す。

### 装着の検査(`C.encloses`)

素手の頂点が手袋の内側に入っているかを組み立て時に確かめる。
**目で見ても気付けない**(素手も手袋も茶系で、突き抜けても手袋の
一部に見える)。最初の実行で 8.7% がはみ出し、内訳は

| 部位 | はみ出し |
|---|---|
| 手のひら | 0.0% |
| 人差し指・小指 | 6.1% |
| 親指 | 30.3% |

原因は**半径だけ太らせて長さを伸ばさなかった**こと。管の両端の蓋が
素手と同じ平面に来るので、そこだけ「手袋の外」になる。両端を grow ぶん
伸ばして解消。

### 設定画からの実測

正面図で革(手袋)と肌(前腕)を色で分け、高さごとに測った。

| 部位 | 設定画 |
|---|---|
| 素肌の前腕の下端 | z 0.533 |
| 手袋の折り返し | z 0.505〜0.538、幅44mm(腕の傾き29.7°で直径38mm) |
| 手 | z 0.425〜0.505、幅60mm |
| 手首→指先 | 107mm(うち指が45%) |
| 手首の中心 | (±0.201, 0.519) |

これで**前腕が50mm長すぎた**ことが分かった(旧: 手首がz0.460)。
`hand.L` ボーンも手のひらの中(z0.436)から手首(z0.519)へ移した。

### 結果

三角形 13,642 → 16,298(上限24,000)、glb 1,127KB → 1,291KB(上限2,600KB)。
増分は素手2つ+手袋2つ。素手は手袋の下で見えないが、**手袋を脱がせる
表現を足すときに作り直しにならない**ように爪・指の分かれ目まで塗ってある。

全身シルエット(高さ%):

| 高さ% | 部位 | 前 | 後 | 設定画 |
|---|---|---|---|---|
| 48 | 手首/腰 | -13px | **+3px** | 334px |
| 56 | 指先 | -16px | -26px | 386px |

48%(手首)は合った。56%(指先の高さ)が残るのは、**設定画の手は最大幅の
まま下まで伸びている**のに対しモデルは指先で細るため。モデルの手の
最大幅(±267mm)は設定画(±266mm)と一致しているので、ここを合わせに
行くと指が実測より長くなる。指の開き(FINGERSのfan)で詰める余地はある。

指を平行に並べると熊手に見えたので、**付け根を寄せて先を開く**
(fan = -0.20/-0.07/+0.07/+0.20)。設定画の手もこの開き方をしている。

## 第12段階: 背負い樽の向きを直す(実装済み)

ユーザーの指摘「背中のタルが設定画と異なっている。向きが違う」。

### 逆に読んでいた

コードには「設定画の側面図は**たがが縦に走る**・背面図は**円い鏡板**。
これは樽の軸が前後(Y)を向いているから」と断定的なコメントがあり、
それに従って軸を前後に寝かせてあった。

三面図を5倍で切り出して見直すと、側面図も背面図も

- 板が**縦**に並ぶ
- たがが**横**に走る(背面図で4本)
- 中央がふくらむ樽の輪郭
- 背面の中央にあるのは鏡板ではなく**栓(飲み口)**の突起

で、**縦置きの樽**だった。読み取りが逆だった
(`modeling-pitfalls.md` 2-7)。

### 実測

木とたがの色で領域を取り、連結成分で樽だけを切り出して高さごとに測った。

| 項目 | 設定画 |
|---|---|
| 高さ | z 0.5385 〜 0.7748(236mm) |
| 幅(背面図) | 220mm(最大 ±111) |
| 奥行き(側面図) | 130mm |
| たが | z 0.550 / 0.602 / 0.706 / 0.758 の4本 |
| 栓 | z 0.655、背面の中央 |

**断面は円ではなく楕円**(220×130)。背面図と側面図の両方を満たす形は
これしかない。背中へ密着させるため、前面のy(0.070)を固定して
奥行きに合わせてリングの中心を後ろへずらす。

### 側面の照合が使えるようになった

モデルのシルエットは-X側にカメラを置くので画面の右が顔側、設定画の
側面図は左が顔側。反転せずに比べていたので、これまで側面の左右の
数値は意味を成していなかった(実測: 靴の前後が+74/+83mm)。
反転してから重ねるようにした。

| 高さ% | 部位 | 設定画(背面側) | モデル | 差 |
|---|---|---|---|---|
| 26 | 肩/樽上端 | +105 | +102 | -3 |
| 34 | 胸+樽 | +111 | +121 | +10 |
| 42 | 背中+樽 | +97 | +99 | +2 |

樽の張り出しは -3/+10/+2mm。中央のふくらみだけ10mm残るが、側面の
照合は外接箱の中心で横を合わせているだけで基準点が無く、この程度は
物差しの不確かさの内。**正面の顔一致QAのような固定の基準点が要る**
(側面の位置合わせは次の課題)。頭・顔の奥行き・エプロンは±10mm以内。

## 第13段階: 着手前に「今も必要か」を確かめる(実装済み)

残作業リストを順に着手する前に、1件ずつ**まだ本当に必要か**を測って
確かめた。3件のうち**2件は不要**だった。

### (1) 「目の下瞼の線が無い」→ 誤診

`目の高さ` が設定画26.0に対しモデル22.8。拡大して見ると確かに下瞼の
線が弱い。しかし**同じ設定画の中の2つの図で目の高さが違った**。

| 出所 | 目の高さ |
|---|---|
| 三面図の正面図(顔一致QAの基準) | 26.0mm |
| 表情「通常」(**デカールの出所**) | 23.5mm |
| モデル | 22.5mm |

デカールは解像度が1.5倍細かい表情の区画からトレースしている。
つまり **3.5mmの差のうち2.5mmは2つの図の食い違い**で、モデル自身の
出所との差は1.0mmしかない。デカールと設定画の明度を同じ(x,z)で
突き合わせても、デカールは表情の区画を忠実に再現していた。

**対処はモデルではなく物差し側**。位置(目の間隔・高さz)は窓の基準で
ある正面図と、大きさ(目の幅・高さ)は絵の出所である表情の区画と
比べるようにした。目の4項目すべてが基準内に入った。

### (2) 「全身照合に固定の基準点が無い」→ 不要

顔一致QA(1px=0.5mm)と全身シルエット照合(1px=0.94mm)が同じ高さで
食い違うので、正規化の基準点が要ると考えていた。**モデル側は5点すべてで
3mm以内に一致**していた。

| z | モデル(重ね) | モデル(顔QA) |
|---|---|---|
| 0.890 | 185.3 | 186.0 |
| 0.870 | 189.6 | 190.5 |
| 0.850 | 168.5 | 168.5 |
| 0.830 | 147.4 | 149.0 |
| 0.810 | 123.6 | 126.5 |

食い違っていたのは設定画側で、原因は**測っている対象が違う**こと。
全身照合は図形全体(襟・肩当て・服を含む)、顔一致QAは肌|髪の分類。
z0.810で14mm差が出るのは、そこに襟と肩当てがあるため。
正規化の問題ではなかった。

### (3) 「脚の間の空き」→ **本物。しかも最大の残差**

重ねた絵で一番大きな青(モデルだけ)の領域は脚の間だった。

| z(mm) | 設定画の空き | モデルの空き | 差 |
|---|---|---|---|
| 132 | 108.1 | 44.9 | -63.2 |
| 113 | 113.7 | 42.1 | -71.6 |
| 93 | 109.5 | 37.9 | -71.6 |
| 73 | 116.5 | 35.1 | -81.4 |
| 54 | 112.3 | 25.3 | -87.1 |
| 34 | 112.3 | 2.8 | -109.5 |

接地の高さではモデルの左右のブーツが**ほぼ接している**。
外側の輪郭は±10mmで合っているので、**脚が太すぎて内側へ食い込んで
いた**のが原因。

| z(mm) | 設定画 すね幅 | モデル | 設定画 中心 | モデル |
|---|---|---|---|---|
| 132 | 54.1 | 86.3 | 71.6 | 66 |
| 113 | 49.8 | 88.4 | 73.7 | 66 |
| 73 | 60.4 | 96.1 | 80.0 | 66 |
| 34 | 99.0 | 155.9 | 100.0 | 80 |

**すねは幅50mm・中心x80mm**しかない。モデルは幅88mm・中心66mmだった。

対処:

- 脚のボーンを外へ(knee 0.070→0.078、foot 0.074→0.090)
- 脚を細く・下ほど外へ(半径 0.038/0.040/0.043 → 0.038/0.032/0.028)
- ズボンの裾だまりを円柱からロフトへ(下端まで太いままだった)
- ブーツを細く(靴の半幅 0.072→0.044、靴底 112→72mm)、開きを28°→14°、
  位置を x0.068→0.100
- **すねはブーツの中で内側へ寄せる**。足の中心はx106mm、すねの中心は
  x82mmで24mm違う。ブーツは1つの剛体なので、ローカル座標のcxで持たせる
  (このcxを `* s` し忘れて左右非対称になった。左右で使い回す
  ローカル座標は必ず側で反転する)

結果:

| z(mm) | 空きの差(前) | 空きの差(後) |
|---|---|---|
| 132 | -63.2 | -2.8 |
| 113 | -71.6 | -7.0 |
| 73 | -81.4 | -7.0 |
| 34 | -109.5 | **+0.0** |

最大差 109.5mm → 18.3mm。高さごとの幅も すね +2px・ブーツ -1px
(前は +16 / -6)。

> 教訓: **残作業リストは書いた時点の理解で書かれている。**
> 着手前に測り直すと、3件のうち2件は消え、代わりに一番大きな
> 残差(脚)が見つかった。

## 第14段階: 基準側のばらつきを測り、追う残差を選ぶ(実装済み)

第13段階の残りは 胸+12px・エプロン裾+12px・ひざ下-10px。これも
着手前に「今も必要か」を確かめたところ、**そもそも設定画自身が
それ以上ばらついていないか**を先に測るべきだと分かった。

### 設定画は自分自身と食い違う

三面図の正面図と背面図を同じ正規化で重ねると:

| 部位 | 正面図 | 背面図 | 差 |

| エプロン上(手の高さ) | 542.0 | 467.6 | **-74.4** |

## 第15段階: 外部評価の判断を反映する(2026-09-02)

第14段階までの実測をまとめて外部の3D専門家へ相談し、次の判断を得た。

| 項目 | 判断 |
|---|---|
| 顔メッシュの専用トポロジー化 | **保留** |
| 左右非対称化 | **しない** |
| 顔IoU 0.90の合格基準 | **廃止**。対称上限に対する到達率へ |
| 髪 | **最優先** |
| Hair Cap + 立体毛束の方式 | **維持**(方式の問題ではない) |
| 次の改善 | 毛先QA → **主要毛束の輪郭QA** |

### 「0.90という合格基準の方が間違っていた」

肌IoUは0.813、左右対称モデルの上限は0.825で**すでに98%**。作り直しても
最大+0.012しか動かない。基準の方を直すべきだった。

`compare_face.py` の判定を**絶対値から到達率へ**変えた
(`symmetric_ceiling()`、基準は上限の95%)。

    領域             IoU    対称の上限     到達率
    skin           0.813      0.825      98%  ok
    hair           0.752      0.860      87%  NG

顔の造作はテクスチャで描いており、まばたきもUV切り替えなので、
**顔面そのものを変形させる段階(頬を膨らませる・口を大きく開ける・
眉間を寄せる)になったときに専用トポロジーを導入する**。それが着手条件。

### 左右非対称にはしない

頬14.5mm・顎先11.0mmの非対称は、設定画が他の場所でも最大74.4mm
自己矛盾している以上、**作画誤差として扱う**方が安全。顔骨格は左右対称を
維持する(髪型のように非対称がデザインとして明示されている場合は別)。

### 食い違う図の扱い: 平均を取らない

**用途ごとに正を決める。** 平均すると「どちらの絵にも存在しない
キャラクター」になる。

| 用途 | 正とする図 |
|---|---|
| 正面のシルエット・顔 | 三面図の正面図 |
| 横方向の奥行き | 三面図の側面図 |
| 後頭部 | 三面図の背面図 |
| 顔のパーツ | 表情「通常」 |
| 閉じ目 | 表情「眠そう」 |

第14段階の「基準側のばらつきを引いた超過で優先順位を付ける」は、
**平均化の代わりに不確実性として扱う**やり方として妥当と評価された。

### スクリプト生成はまだ限界ではない

問題は生成手法ではなく**何をパラメータ化しているか**。`HEAD_RINGS`
だけで微妙な顔面形状を作るのは限界だが、毛束に
「root / 中心線 / 左右の輪郭 / 断面厚 / twist / 浮き量 / tip」を持たせれば
まだ詰められる。

> **限界の見分け方**: 設定画 → トレース → パラメータ化 → メッシュ生成
> という変換関係を保てているうちは続ける価値がある。
> **数字を何百個も直接調整し始めたら限界。**

## 16. 耳を作る / 作画の左右差を測って判定から外す(2026-09-02)

### 耳が無かった

設定画には耳が描かれているのに、モデルには耳が無かった。
`髪の左右輪郭` が z0.810/z0.830 で落ちていたのは髪の問題ではなく、
**その高さの輪郭を作っているのが耳だから**だった。

設定画の耳: +x側 x59..81 / -x側 x-68..-50、どちらも z813..851。
左右で11mmずれて描かれているので、**左右の平均**を取って対称に置く。

上端は入力 z832 で切る。ボクセル融合(3.8mm)は上下に10mmほど膨らむので、
設定画どおり z851 まで入れると耳の頭がこめかみの毛束の外へ出る。

### 設定画は顔がわずかに振られて描かれている(実測)

| 部位 | 設定画 左 | 設定画 右 | 左右差 |
|---|---|---|---|
| 頬 | -63.5 | +78.0 | 14.5mm |
| z0.965 の輪郭 | -33.0 | +58.0 | 25.0mm |
| z0.870 の輪郭 | -79.5 | +104.0 | 24.5mm |
| あご先(中心線のはず) | \multicolumn — x=+11.0 | | 11.0mm |

**モデルは左右対称に作ると決めている**(外部評価: 作画の非対称は誤差と
して扱い、顔の骨格は対称を維持)。だから片側に合わせれば必ず反対側が
外れる。領域IoUで「対称の上限」を出したのと同じ考え方で、判定も直した:

| 検査 | 直し方 |
|---|---|
| 意味的ランドマーク | **左右を平均した設定画**に対して測る。設定画自身の左右差を併記 |
| 中心線の部位(あご先・生え際中央・口中央) | **高さだけ**で測る |
| 髪の左右輪郭 | 設定画の左右差が許容(12mm)を超える高さは**参考**にする |

結果: ランドマークの平均誤差 2.9mm → **1.4mm**、最大 11.5mm → **3.5mm**。
数字が良くなったのではなく、**測れないものを測るのをやめた**。
