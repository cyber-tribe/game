# 5体だけを2Dから全面再設計し、通過するまで残りへ展開しない

## 経緯

外部審査が3Dモデルの評価を「パイプライン9/10・モデリング技術6〜6.5/10・
**キャラクターデザイン4〜5/10**」へ分離・下方修正した。要点:

- AO・高解像度テクスチャ・輪郭線・まばたき等をいくら足しても、
  **元のデザインを見て欲しいと思えなければ商品力は上がらない**。
  優れたデザインは白黒の設定画でも魅力がある。これまでの改善は
  既存デザインの修繕であり、「この生物そのものを好きになれるか」
  という上流の問いに答えていない。
- 特に主人公は妥協できない。パッケージ・ストア・タイトル画面の
  すべてに出るため、ここで「安っぽい」と分類されるとゲーム
  システムが9点でも触ってもらえない。
- **59体への展開を今すぐ止めるべき**。魅力の弱いデザインを
  高品質に仕上げることになりかねない。
- 戦闘の判断密度(`plan/game/region1-tactical-validation.md`で
  検証中)とキャラクターデザインが、現時点の二大リスク。

## 診断(今回はコードではなく、実際のレンダー画像の目視)

`tools/preview/flagship_lineup.png`・`garudo.png`を直接目視して
確認した。審査の下方修正は妥当と判断する:

- **ガルド**(`garudo.png`): 目は眼窩修正後もなお「顔に載った白い
  楕円板2枚」に見え、左右の傾きが揃わず焦点の合わない表情になって
  いる。眉は顔から浮いた棒。髪(鉢巻き?)は黄色い塊で、髪とも
  帽子とも読めない。上着の焼き込み模様は織り目ではなく
  格子柄のテーブルクロスのように見える。腕は先細りの筒で手の形が
  無い。そして**生業の象徴である背負いダルが正面からほぼ見えず**、
  「樽守りの少年」という一番の個性が第一印象に一切寄与していない。
  総じて「素朴な量産木彫り人形」であり、記憶に残る要素が無い。
- **看板6体の並び**(`flagship_lineup.png`): 掘り杭の主は青と赤の
  左右塗り分けが「配色ミスのマネキン」のように読める。おおねぼすけは
  塊を積んだだけの体形で、眠りの主というテーマが輪郭から読めない。
  ぷるんは単純な水滴形+大きな目で、この中では例外的に成立している。
  また比較画像自体も、小さな模型が遠くにまばらに置かれた構図で、
  「商品棚の1枚」としての体を成していない。
- 根本原因は審査の指摘どおり: **Skinモディファイア由来の丸い胴体+
  プリミティブ部品+特徴物の後付け**という制作方式は、技術的には
  成立するが「描きたい姿が先にあって、それを作る」の逆順であり、
  デザインが工程のどこにも存在しない。

## 決定

### 1. 磨き込みの展開を凍結する

- 残り59体への品質展開(テクスチャ全展開の続き・硬い部品の追加・
  シルエット改善・看板手法の横展開)を、本ゲートを通過するまで
  **すべて停止する**。
- 例外(継続してよいもの): 明確な不具合の修理(アニメーションで
  部品が置き去りになる`hard-part-bone-pinning-audit.md`等)、
  ダンジョン・小物・タイル等キャラクターでないモデル、音・UI。

### 2. 5体を2Dコンセプトから全面再設計する

対象は以下の5体(プレイヤーが最初の1時間で最も長く見る顔ぶれ):

1. **ガルド**(主人公。妥協不可)
2. **ぷるん**(マスコット枠。現デザインは例外的に成立しているため、
   「全面改稿」ではなく2Dで描き直して再確認し、通れば微調整のみ)
3. **通常敵2体**(第一地方の頻出種から選ぶ。たたき台: がじりねずみ
   +もう1体は第一地方の出現率から実装時に選定)
4. **ボス1体**(たたき台: おおねぼすけ。第一地方ボスであり、
   最初に出会う主だから)

工程は`2d-turnaround-first-workflow.md`(導入済みの三面図工程)の
**さらに上流**に「コンセプト設計」を足す:

1. **1体につきラフ案を3案以上**、SVGの線画で描く(正面1枚でよい。
   シルエット・図形言語・「この生物の何が好きになれるか」を1行
   添える)。既存デザインの微修正案だけでなく、ゼロから考えた案を
   必ず含める。
2. 案を並べて選ぶ。判断基準は「**以前より良くなったか」ではなく
   「白黒の線画の時点で魅力があるか**」。
3. 選ばれた案を三面図(`2d-turnaround-first-workflow.md`の形式)に
   起こし、承認後に3Dへ進む。
4. 3D化では、ガルドに限り**現行のprocedural前提(build_skinnedの
   素体+塗り分け)を捨ててよい**。三面図に合わせた頂点の手作業
   配置・専用メッシュを許可する(Blender Pythonという手段は
   維持するが、共通素体の制約に縛られない)。

### 3. 合格判定(ゲート)

- 5体のみを大きく写した**商品カット1枚**(現`flagship_lineup.png`の
  ような遠景の並びではなく、パッケージを意識した構図)を作り、
  判定は次の1問だけ:
  **「この5体だけ載ったゲームのパッケージを店頭で見て、
  手に取りたくなるか」**
- 通過するまで残りのモンスターへ展開しない。通過したら、確立した
  「2Dコンセプト→三面図→3D」の工程で残りへ順次展開する
  (その時点で展開の優先順位を別途計画する)。

### 4. 既存計画との関係

- `eye-socket-eyelid-construction.md`(眼窩+まぶた)・
  `garudo-hero-quality-pass.md`(テクスチャ解像度)は、**再設計後の
  ガルドに対して**適用する(現行デザインの上に先に施工しない)。
- `2d-turnaround-first-workflow.md`は本ゲートの実行手段として
  そのまま使う(本書はその上流のコンセプト段階と、展開凍結の
  意思決定を足すもの)。

## 受け入れ基準

1. 5体それぞれにラフ3案以上のSVG線画が`design/characters/<キャラ名>/
   concepts/`にあり、採用案と選定理由が1行ずつ記録されている
   (plan/はキャラクター個別の資産ではなく開発内容の設計を書く場所の
   ため、キャラクターごとの絵はdesign/側に置く)。
2. 採用案の三面図があり、3Dモデルがその三面図とシルエット照合で
   一致する。
3. 5体の商品カット1枚が`tools/preview/`に出力され、「店頭で
   手に取りたくなるか」の判定が(ユーザー・外部審査の目視で)
   下せる状態になっている。
4. ゲート通過まで、残り59体への品質展開PRが1本も出ていない。

## 対象外

- ゲームシステム側の変更(判断密度の検証は
  `plan/game/region1-tactical-validation.md`で並行して進行中)
- 不具合修理・非キャラクターモデル・音・UI(凍結の例外)
