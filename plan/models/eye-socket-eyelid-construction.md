# 目を「顔に貼った楕円の板」から「眼窩に収まる眼球」へ作り直す

## 経緯

「楕円形のタブレットを目玉として顔面に付けただけというのが多く、
人体の作りから乖離している」という指摘。`eye-socket-fix.md`で
「目が頭部から突き出さない」問題には対応済みのはずだったが、
その対応の**やり方自体**が今回指摘されている歪みの原因になっている。

## 診断(実測)

`garudo.py`の目:

```python
white = C.uv_sphere(
    f"eyewhite{side}", head + Vector((0.056 * side, -0.100, 0.004)), 0.044,
    segments=16, rings=12, scale=(1.25, 0.45, 1.35),
)
```

奥行き(Y軸)のscaleが**0.45**。球ではなく、厚みが半分以下に潰れた
円盤(レンズ)になっている。これは`character-design-language.md`が
定めた既存の規約そのものが指示している内容:

```
- 目(白目)の表面は、頭部メッシュの表面から突き出してはならない
  (eye-socket-fix.md)。...「目を大きくする」ときは半径ではなく、...
```

`eye-socket-fix.md`は「目が頭部から突き出す」問題を、**眼窩を彫って
球を沈めるのではなく、球自体を潰して平たくする**ことで解決していた。
突き出しは無くなったが、代わりに「眼球のはずの部品が扁平な板になる」
という別の不自然さを生んだ。これが今回指摘されている「タブレットを
顔に貼っただけ」の直接の原因。

同じ潰し方は`garudo.py`だけでなく`villagers.py`の各所にも見られる
(奥行き方向のscaleが0.42〜0.55程度に潰された`uv_sphere`が複数、
下記はその一部):

```
tools/models/villagers.py:925:  scale=(1.25, 0.55, 0.75)
tools/models/villagers.py:935:  scale=(1.0, 0.94, 0.44)
tools/models/villagers.py:1212: scale=(1.35, 0.48, 0.42)
```

加えて`eye_slit()`(同ファイル、6キャラで使用)は、そもそも球体ですら
なく**平らな箱を顔の丸みに合わせて角度だけ回して貼り付けた板**
(閉じ気味の目を意図的に表現する部品としては妥当だが、開いた目の
代用として使われている箇所は同じ問題を持つ)。

一方`build_pochi`の目(`pochi_eyewhite`)は潰していない素の
`uv_sphere`(scale指定なし=真球)で、`_face_point`により頭部球面上に
置かれている。犬のように頭部そのものが小さく目が相対的に小さい
造形では突き出しが問題にならず、球のまま使えている。**人型の顔
(ガルド・多くの村人)でだけ、目を大きくする過程で潰す対症療法が
定着してしまった。**

## 調査(一般的な3Dキャラクター制作の知見、特定作品への参照なし)

- 眼球は、たとえ様式化されたキャラクターであっても**位置とスケール
  以外では歪めない**のが原則。歪めるべきは眼球ではなく、その周りの
  **まぶた(眼窩の縁)のジオメトリ**である。
- まぶたは、外側の輪と内側の輪の最低2重のループで作り、外側のループを
  頭部(顔)側の眼窩の縁に、内側のループを眼球の表面にかぶせるように
  配置する。これにより、外から見える目の形(アーモンド形の開口部)を
  まぶたが決め、眼球自体は内側で丸いまま隠れる。
- 誇張された大きい目を持つ様式化キャラクターほど、まぶた側の
  ジオメトリを厚く・密にして眼球の丸みに沿わせる必要がある
  (眼球を潰すのではなく、まぶた側で覆う量を増やす)。

(参考: [Eyelid Topology](https://www.pinterest.com/ideas/eyelid-topology/935454285256/), [3D Modeling Eyes: Techniques, Tips, and Best Practices](https://www.tripo3d.ai/blog/explore/3d-modeling-eyes), [Lets talk about eyelids. — polycount](https://polycount.com/discussion/133437/lets-talk-about-eyelids))

## 変更内容

### 1. 規約そのものを書き換える(`character-design-language.md`)

- 「目の表面は頭部から突き出してはならない」という受け入れ基準は
  維持するが、**達成手段を「球を潰す」から「眼窩を彫って沈め、
  まぶたの縁で覆う」に変更する**。
- 「目を大きくするときは半径を変えず○○で」という現行の但し書きを、
  「目を大きくするときは眼球の半径をそのまま保ち、眼窩を大きく
  彫ってまぶたの開口部を広げる」に書き換える。

### 2. `common.py`に眼窩+まぶたのヘルパーを足す

- 既存の`_sculpt_bump`(inset_region+法線押し出し)は、負の`push`で
  くぼみを彫る用途に既に使われている(ガルドの眼窩まわりの
  くぼみ、`garudo.py:165`)。これを土台に、**同じinsetの境界線を
  再利用してまぶたの薄いリング状ジオメトリを作る**関数を追加する:
  1. 頭部メッシュに眼球の大きさに見合う眼窩をくぼませる
     (`_sculpt_bump`と同じ手順)。
  2. くぼみの境界(inset後の外周ループ)を複製し、わずかに眼球側
     (-Y方向)へ押し出して薄いリング(まぶた)を作る。素材は肌と
     同じでよい。
  3. 眼球(白目)は**潰さず、ほぼ真球のまま**眼窩の中心に置く
     (現状の`scale=(1.25, 0.45, 1.35)`のような大きな潰しをやめ、
     せいぜい±15%程度の軽い調整に留める)。
- まばたき機構(`eye-blink-liveliness.md`)は白目・瞳を頭の骨へ
  直接つなぐ仕組みなので、まぶたのリングを本体側(join対象)に
  含めても、白目・瞳側の可動には影響しない。

### 3. まずガルドで検証する

- 看板モデル化の流れ(`flagship-model-program.md`)と同じく、
  最初にガルド1体で新しい眼窩+まぶたの構成を試し、黒塗り
  シルエット・レンダーで「板を貼った目」から「丸い眼球が
  覗いている目」に変わったことを確認してから、他キャラへの
  展開を判断する。

### 4. 対象を分ける

- `eye_slit()`(閉じ気味の目、眠い・好々爺系のキャラの意図的な
  デザイン)は、様式として目を線1本で表現する選択自体は妥当なため、
  今回の対象に含めない。**開いた丸い目の代用として板を使っている
  箇所だけ**が対象。

## 受け入れ基準

1. ガルドの黒塗りシルエット・クローズアップレンダーで、目が
   「顔に貼った板」ではなく「眼窩の中に丸い眼球が収まり、まぶたに
   縁取られている」ように見える(新旧比較)。
2. 白目メッシュのscaleが、どの軸も真球から大きく(頭身に対して
   目立つほど)潰れていない。
3. 目が頭部表面から突き出さないという既存の受け入れ基準
   (`eye-socket-fix.md`)を、眼窩+まぶたの構成のままでも満たす。
4. `character-design-language.md`の該当箇所が、「潰して対応する」
   から「眼窩+まぶたで対応する」に書き換わっている。
5. まばたき(`eye-blink-liveliness.md`)が引き続き正しく動く。
6. ポリゴン予算(`texture-pipeline-adoption.md`基準)を超えない
   (まぶたのリングは低ポリゴンの薄いバンドで足りる見込み)。

## 対象外

- `eye_slit()`を使う閉じ目・眠そうな目のキャラの様式変更
- まばたき機構自体の変更
