# ガルドの髪を「立体的な大きな毛束」へ作り替える

外部評価(2026-09-02)を受けた設計。現在の「板(`_hair_card`)+頭皮に沿う
殻(`_hair_shell`)」をやめ、**Hair Cap + 大きな立体毛束 + 手描きの塗り**の
3層へ移行する。

`plan/models/hand-painted-standard.md`(手描きテクスチャ規約)と
`plan/models/modeling-pitfalls.md`(落とし穴)を前提とする。

---

## 1. なぜ変えるか

### 現状の限界

`plan/models/modeling-pitfalls.md` 3-2 に「髪がヘルメット。幅は合っているのに
別人」と記録し、「輪郭を作るのは土台ではなく毛先」と結論した。診断は正しいが、
**対処が板とシェルの微調整に留まっている**。

`_hair_shell` は名前のとおり頭の楕円体を角度方向に切り取った殻で、構造としては

```
頭 → 頭皮に沿った茶色い殻 → その端を尖らせる
```

に近い。一方、設定画の髪は

```
        毛束
      ／    ＼
   ／          ＼
  ╲    頭      ╱
   ╲          ╱
```

**頭皮から生えた大きな毛束が、途中で頭から浮き、互いに重なって毛先を作る**。

### 実際に起きた失敗

輪郭の凹凸(設定画比)を上げるために、地肌へ**垂直なトゲ**を8本生やしたら
54%→97%になったが、見た目は**ウニ**だった。指標は「輪郭が上下に振れること」
しか見ておらず、**その振れが毛束として成立しているか**を見ていない
(Goodhart's law の実例。`modeling-pitfalls.md` 1-2)。

構造の概念(毛束)を持たないまま外形の数値だけを追うと、必ずこれが起きる。

### 設定画の裏付け(実測)

側面図を6倍で確認したところ、提案どおりの構造だった:

- 根元は頭皮に**密着**(頭頂は頭蓋に沿う)
- 毛先へ向かって**離れる**(後頭部の毛束は頭から浮いて点で終わる)
- 輪郭は**毛束の毛先が作る**。滑らかな殻ではない
- 頭頂に**アホ毛**が1本
- 耳の前に細い**もみあげ**が1本、あごの高さまで
- 毛束の中に「根元が暗く・中央が明るく・毛先がまた暗い」弱い色差がある

正面(表情「通常」の区画。三面図より1.5倍細かい)でも、分け目がやや+x寄りに
あり、そこから左右へ大きく流れる構造が読める。

## 2. 方式: 3層

```
Hair Cap  →  Major Clumps  →  Painted Detail
(地肌隠し)     (シルエット)      (毛の流れ)
```

### 2-1. Hair Cap

頭皮を隠すためだけの薄い土台。**シルエットを絶対に作らせない。**

- 頭部より数mm(3〜5mm)だけ外側
- 毛束と毛束の隙間から肌が見えないためだけに使う
- 現在の `h_base` は z0.91〜0.965 で**それ自体がシルエットになっている**。
  これをやめる

**受け入れ条件(機械で判定可能)**: capだけを描いたシルエットが、
clumpsだけを描いたシルエットの**内側に完全に入る**こと。
正面・側面・3/4の3方向で確認する。

### 2-2. Major Clumps(立体毛束)

`hair_clump()` という新しいプリミティブを `tools/models/common.py` に足す。
4点程度の中心線に沿って断面をロフトする。

```python
hair_clump(
    name,
    spine=[root, mid1, mid2, tip],   # 中心線(モデル座標)
    width=(0.030, 0.036, 0.025, 0.000),      # 各点の半幅
    thickness=(0.012, 0.015, 0.010, 0.002),  # 各点の半厚
    lift=(0.000, 0.006, 0.014, 0.022),       # 頭からの浮き量
    twist=(0.0, ...),                        # 断面のひねり(度)
    segments=8,
)
```

**断面は丸ではなくレンズ(潰したダイヤ)**:

```
   ／\
  /  \
  \  /
   \/
```

こうすると

- 正面では太いアニメ髪に見える
- 横から見てもちゃんと厚みがある
- 毛先が鋭い

`_hair_card`(平たい板)と `_hair_shell`(頭皮の殻)の中間ではなく、
**一段上の表現**である点に注意。板の厚みを増やしただけでは足りない。

### 2-3. 根元は密着・毛先ほど浮かせる

`_hair_shell` が有効だった理由は「顔の曲面に負けて横髪が隠れる」問題を
防げたこと(実測: 目の高さで肌が45mm余計に見えた)。**この利点は残す。**

```
根元  →  頭皮に密着        (lift 0mm)
中間  →  5〜10mm 浮く
毛先  →  10〜25mm 浮く
```

```
頭部断面
       毛先
         ▲
       ／
     ／
  ●──────
 /        \
|   頭     |
 \        /
```

これで「頭に沿う髪」でありながらヘルメットにならない。
`lift` は中心線の各点で頭部楕円体の法線方向へ押し出す量として与える。

### 2-4. 前髪と横髪は作りを変える

**前髪**は正面の形が最優先なので、板寄りの幅広い立体リボンでよい。

```
root █████
      ████
       ███
        ██
         ▼
```

**横髪**は頭の側面を回り込みながら頬の前まで出る必要があるので、
中心線を3Dで曲げる。

```
上から見る
      頭
   ／────＼
  │        │
  │        ╰── 毛先
   ＼────／
```

### 2-5. 後頭部はCap主体でよい

プレイヤーが見る距離を考えると、

| 部位 | 作り |
|---|---|
| 前髪 | 毛束 |
| 横髪 | 毛束 |
| 頭頂 | 毛束 |
| 外周 | 毛束 |
| 後頭部の中央 | Hair Cap |

これで三角形数を抑えられる。

## 3. 設定画からの毛束の分解

**まず大きな塊から。** 細かい房を大量に作らない。

```
               A
          ┌────────┐
       B ／         ＼ C
        /             \
      D│      顔       │E
        \             /
```

最初は6ブロック:

| 記号 | 毛束 | 備考 |
|---|---|---|
| A | 頭頂〜アホ毛 | 分け目から立ち上がる |
| B | 左前髪 | 分け目から左へ流れ、左眉の上で尖る |
| C | 右前髪 | 分け目から右へ流れ、右こめかみで尖る |
| D | 左側頭部 | こめかみ→頬の前、あご近くまで |
| E | 右側頭部 | 同上。設定画では**右が広い** |
| F | 後頭部 | Cap主体+襟足の房 |

そこから必要な所だけ枝分かれさせて8〜12本にする。

### 毛先は自動で測れる(手で描かない)

顔の作業で得た原則「なぞれるものを手で描かない」をここでも守る。
設定画の髪の輪郭から**外側への張り出しの極大**を取ると、毛先の候補が出る
(`tools/compare_face.py` のウィンドウで実測):

| 側 | 高さ z(mm) | x(mm) |
|---|---|---|
| 左 | 956.5 | -61.0 |
| 左 | 930.5 | -84.0 |
| 右 | 965.5 | +48.5 |
| 右 | 912.5 | **+94.0** |
| 右 | 866.0 | **+98.0** |

右側に大きな張り出しが2つある(設定画の髪が左右非対称である実測の裏付け)。

**根元と中間は輪郭から測れない**(他の毛束の下に隠れている)ので、そこだけ
人手でアノテーションする。外部評価では「10房なら30点」とあったが、
**毛先が自動で取れるぶん、手で置くのは root と mid の 2点 × 本数**で足りる。
手で置く点が減るほど「想像で描く」余地が減る。

アノテーションの置き場: `design/characters/garudo/hair-clumps.json`
(`face-reference.json` と同じ流儀)。

## 4. 法線

現在は `spherize_normals(hair, (0,0.016,0.900), strength=0.55)` を
**joinした髪全体**に掛けている。これは顔には非常に有効だが、髪に使うと
せっかく毛束を作っても**また一枚の丸いヘルメットのように光る**。

```
髪全体 → 同じ法線基準     ← やめる
前髪A → Aの法線
前髪B → Bの法線           ← こうする
横髪A → Aの法線
```

毛束ごとに、その毛束自身を一つの滑らかな立体として法線を整える。
照明が当たったときに毛束の境界が出る。

**確認**: 法線を毛束ごとにした前後で、同じライティングのレンダーを並べる。

## 5. QAを「外形」から「構造」へ

現在の髪QA(`tools/compare_face.py`)は

- 髪の最大幅 / 高さごとの幅 / IoU / 上部輪郭の凹凸

と、**基本的に外形しか評価していない**。だからトゲでウニになった。

ここに**毛束の構造**を足す。顔のランドマーク回帰の髪版:

```
中央前髪:
  root OK
  mid  +3mm
  tip  -14mm  ← FAIL
左横髪:
  root OK
  tip  +8mm   ← FAIL
```

- 基準は `hair-clumps.json`(毛先は自動計測、root/mid は人手)
- 受け入れ: 毛先の平均誤差 <= 6mm / 最大 <= 12mm(顔より緩い。
  髪は設定画側の描写も曖昧なため)
- 既存の外形指標は**残す**。構造QAは置き換えではなく追加

## 6. 実装順序

外部評価の提案順から**1点だけ変える**。読み取り(分解)を先にする。
顔の作業で最も高くついた失敗が「設定画を全部見る前に作り始めたこと」
だったため(`modeling-pitfalls.md` 2-1)。

1. **設定画から毛束を読み取る** → `hair-clumps.json`
   (毛先は自動計測、root/mid は人手で最小限)
2. **構造QAを先に作る**(`compare_face.py` に毛束ランドマーク回帰)
   — 作り替えの前に物差しを用意する。顔で有効だった順序
3. `hair_clump()` を `common.py` に実装(レンズ断面・lift・twist)
4. Hair Cap を頭部より内側へ縮め、シルエットを担当させない
   — cap単体のシルエットが clumps の内側に入ることを機械で確認
5. 6ブロックを置く → front / side / 3/4 の3方向で詰める → 8〜12本へ枝分かれ
6. 法線を毛束ごとにする
7. 手描きアルベド(根元暗い・中央基本色・上面明るい・毛先暗い)

**`_hair_card` / `_hair_shell` はこれ以上微調整しない。** 4以降で置き換える。

## 8. 受け入れ基準と実装結果(2026-09-02)

| 項目 | 基準 | 結果 |
|---|---|---|
| 毛先ランドマーク | 平均 <= 6mm / 最大 <= 12mm | **平均2.2 / 最大6.6 ok** |
| Hair Cap | capが正面の輪郭を作らない | **正面0% ok**(側面72%は仕様2-5どおり) |
| 上部輪郭の凹凸 | 設定画比 >= 70% | **82% ok** |
| 髪の左右輪郭 | 高さごと ±12mm | **ok** |
| 髪 IoU | >= 0.80 | 0.746(0.681→0.746。下記) |
| 三角形 | <= 24,000 | 13,642 |
| 見た目 | **設定画と並べて確認する** | 実施(`tools/preview/face/garudo-compare.png`) |

### 受け入れ基準の書き換え

**Hair Cap の基準を「3方向で内側」から「正面の輪郭を作らない」へ変えた。**
仕様2-5で「後頭部の中央はCap主体でよい」と決めているので、側面・上面では
capが表面そのものになるのが正しい。3方向で内側という当初の基準は自分の
設計と矛盾していた(実測: 側面33.6%・上面26.1%が「外れ」と出る)。

測り方も変えた。面の包含ではなく**高さごとにcapと毛束のどちらが外に
あるか**を見る(`C.wider_than`)。さらに、頂点だけを見ると長い毛束が
高さの段を飛び越して「その高さには毛束が無い」ことになり、capが輪郭を
作っていると誤判定する(実測: 毛束32.8mm vs 実際の輪郭68.5mm)。
**辺を刻んで測る**必要がある。

### 髪IoUが0.80に届かない理由

0.681 → 0.746 まで上げたが基準未達。残りは**髪ではなく頭の残差**:

| 高さ | 設定画 | モデル | 差 | 原因 |
|---|---|---|---|---|
| z=0.810 頭部幅 | 120.5 | 132.5 | +12.0 | 顔の幅そのものが+10.5mm(肌の幅で確認) |
| z=0.940 輪郭 | ±62〜67 | ±68〜71 | +6 | 頭頂がふくらんでいる。capは51mmで内側 |

どちらも `plan/models/garudo-face-qa.md` の残差詰め(頭頂・あご)の範囲で、
髪の毛束をこれ以上動かしても縮まらない。頭を絞ってから再測定する。

## 9. 発想の転換

> **「髪のシルエットを再現する」から「設定画に描かれている毛束を3D化する」へ。**

幅が合っていることより、**どの毛束がどこからどこへ流れているか**の方が
キャラクターの同一性に効く。現状は

```
設定画のシルエット → 必要な幅を測る → 殻を広げる
```

というアプローチが強く、形の意味が失われやすい。

## 10. 第2次改訂: 毛先ではなく毛束の輪郭を合わせる(2026-09-02)

外部評価の第2回。方式(Hair Cap + 立体毛束)は妥当で、**次は形状設計の
問題**という判断。

> 毛先の位置は合っているのに、髪全体の形は合っていない。
> これは「指標を満たしても対象そのものを最適化していない」と同型。

実測がそれを裏付けている: 毛先ランドマークは平均2.2mmで合格、しかし
髪IoUは左右対称の上限の87%どまり。

### 何を変えるか

| いま | これから |
|---|---|
| 毛束 = 中心線4点 + 幅の配列 | 毛束 = **左右の輪郭** |
| 22本を同格に並べる | **主要毛束5〜8本 + 補助の小さい毛束** |
| QA = 毛先ランドマーク | QA = **毛束の輪郭** |

同格の房を22本並べると「ギザギザした一個の髪型」になる。設定画は
**大きな房の中に小さい毛先がある**という階層構造。

### 毛束は色でも線でも自動分割できない(実測)

- どの明度で切っても髪は**1つの連結成分**のまま(明度0.20〜0.32で試行)
- 描かれた分け目の線を局所コントラストで抜き、太らせて閉じようとしても
  面にならない(被覆56〜77%、面は1個のまま)

線は毛束の境目を**示唆するだけで囲っていない**。だから分解は
**人が読む**しかない。読み取りを検算できるように、線を稜線として
抜いた画像を出す:

    tools/venv/bin/python tools/trace_hair_clumps.py garudo --ridge

20mm方眼つき。→ `tools/preview/face/garudo-hair-ridge.png`

### 主要毛束8本(読み取り結果)

分け目は **(x -26mm, z 0.942)**。そこから放射状に流れる。

| 毛束 | 範囲 x(mm) | 範囲 z(mm) | 備考 |
|---|---|---|---|
| ahoge | -26 〜 -6 | 944 〜 984 | 頭頂の跳ね |
| crown_L | -26 〜 78 | 928 〜 967 | 分け目から+x側へ流れる板 |
| flare_L | 55 〜 103 | 888 〜 930 | シルエットの最大幅 |
| temple_L | 58 〜 106 | 852 〜 888 | こめかみへ降りる |
| crown_R | -75 〜 -26 | 905 〜 952 | 分け目から-x側へ |
| flare_R | -90 〜 -58 | 866 〜 905 | |
| fringe_L | -8 〜 55 | 850 〜 938 | 額にかかる前髪 |
| fringe_R | -58 〜 -10 | 857 〜 934 | |

**測れる辺は測る。** 輪郭に乗る辺は `["edge","L",z0,z1]` /
`["top",x0,x1]` で髪の輪郭をなぞらせ、毛束どうしの境目だけ
`["at",x,z]` で人が置く(顔の「なぞれるものを手で描かない」と同じ)。

主要毛束が覆う髪の面積は **67%**。残りは補助の小さい毛束で埋める。

確認画像:

    tools/venv/bin/python tools/trace_hair_clumps.py garudo --major

→ `tools/preview/face/garudo-hair-major.png`

3. QAを毛先ランドマークから**毛束の輪郭**へ広げる
