# ダンジョン地方別タイルセットの全展開 ― 地方判定の穴を埋める

## 経緯

`dungeon-dreamscape.md`(実装済み・アーカイブ)は、8地方それぞれに
壁・床・階段のタイルセットを与える本体そのものを「別セッション・
別docに委ねる」として保留していた。理由は実装ノートに明記されている:

> 地方色のグラデーション: 「地方」を検出する仕組み(表の寝穴の
> depthからregionByIndexへの変換)は横穴・ひなたの寝穴・樽比べ・
> 腕試しの間など複数のダンジョン種別をまたいで安全に判定する必要が
> あり、今回の差分の範囲を超えると判断した。

実際に第一地方へ潜って確認したところ、この保留のため**地方1すら
パイロットのタイルセットが作られておらず、全ダンジョンが依然として
同一の灰色い直方体タイルのまま**だった(`ps2-quality-adversarial-review`
の指摘の核心が未解決)。本書は保留されていた「地方の判定」を解決し、
全地方タイルセットの生産を進められる状態にする。

## 調査結果 ― 判定の材料は既にすべて揃っている

`src/entities/dungeons.ts`を確認すると、心配されていた「複数の
ダンジョン種別をまたぐ判定」は、実はほぼ機械的な計算で解ける:

- 地方ダンジョン本体(`REGION_DUNGEON_IDS`の8つ)は、既存の
  `regionIndexForDungeonId(id)`がそのまま地方番号(1〜8)を返す。
- それ以外の特殊ダンジョンは、いずれも`floorOffset`(生成テーブルの
  ずらし量)で「どの地方のテーブルを借りているか」が既に決まっている:
  - `ぬかるみの底`(横穴): `floorOffset = REGION_SIZE * 1`(=6)
    → 第二地方のテーブルを流用、とコメントに明記
  - `こだまの巣`(横穴): `floorOffset = REGION_SIZE * 5`(=30)
    → 第六地方のテーブルを流用
  - `山の芯`・`はじめの夢`: `floorOffset = 42`
    → 第八地方のテーブルを流用、とコメントに明記
  - `近道屋の裏穴`: `floorOffset = 2`(区切りの良い地方境界と
    一致しない、地方1→2をまたぐ短いダンジョン)
  - `夜ごとの夢`: `floorOffset`指定なし(=0)、深さの上限も無い

## 決定 ― 地方インデックスを深さから一律に計算する式

`floorOffset`と現在の深さ(depth)から地方インデックスを求める
共通関数を1つ用意し、**個別のダンジョンごとに特殊対応を書かない**:

```ts
function regionIndexForFloor(floorOffset: number, depth: number): number {
  const absoluteFloor = floorOffset + depth - 1; // 0始まりの通し階数
  const wrapped = absoluteFloor % TOTAL_REGION_FLOORS; // 夜ごとの夢のような無限ダンジョンを地方1へ周回させる
  return Math.floor(wrapped / REGION_SIZE) + 1; // 1始まりの地方番号
}
```

この1本の式が、既存の全ダンジョン種別を過不足なく処理する:

- **地方ダンジョン本体**: `floorOffset = REGION_SIZE * (地方番号-1)`と
  一致するため、常にその地方自身の番号を返す(既存の
  `regionIndexForDungeonId`と結果が一致することをテストで確認する)。
- **ぬかるみの底・こだまの巣・山の芯・はじめの夢**: コメントに明記
  された「流用元の地方」がそのまま出る。
- **近道屋の裏穴**(`floorOffset=2`、maxDepth 5): 深さが進むにつれ
  地方1→地方2のタイルセットへ**自然に切り替わる**。「近道屋が
  無理やり掘った、地方をまたぐ手荒な抜け道」という説明文とも
  相性がよい偶然の一致で、狙って作るより自然な効果になる。
- **夜ごとの夢**(`floorOffset`なし、無限に潜れる): 深さが
  `TOTAL_REGION_FLOORS`(48)を超えるたびに地方1から周回する。
  「終わりのないダンジョン」を潜り続けると地方の景色が一巡して
  また一巡する、という体験になる。
- **忘れ物蔵**: `floorOffset`が定義されていないため式は地方1を返す。
  地方1のタイルセットで代替する(専用の見た目を作るかは未決事項)。
- **腕試しの間**(ボスラッシュ、`maxDepth = REGION_BOSS_ORDER.length`):
  1階ごとに別のボスと再戦する構成のため、上の式ではなく
  **「その階のボスが属する地方」をそのまま使う**
  (`REGION_BOSS_ORDER[depth - 1]`から地方番号を逆引きする)。
  当初「専用装飾は後続で検討」として対象外にしていたが、既存の
  地方タイルセットをそのまま使い回せるため追加の生産コストが無く、
  今回のスコープに含める。
- **樽比べ**: ダンジョン探索ではなく的当てミニゲーム(既存の専用の
  見た目を持つ)のため、引き続き対象外のままにする。
- **ひなたの寝穴**(チュートリアル): `floorOffset`を持たない
  独立ダンジョンのため、明示的に**地方1のタイルセットを流用する**
  と決め打つ(式に頼らず直接指定)。`plan/game/tutorial-dungeon.md`
  が定めた「明るく見通しがよい」という照明・視界の方針はタイルの
  形状と独立した設定のため、そのまま維持される(見た目の形は地方1、
  明るさ・視界だけチュートリアル専用のまま)。

## 実装への引き継ぎ

- 上記の`regionIndexForFloor`(仮称)を`src/entities/dungeons.ts`か
  `src/entities/regions.ts`に追加し、描画側(`dungeonMesh.ts`等の
  壁・床モデル選択)がダンジョンの種類を個別に分岐しなくても
  地方タイルセットを引けるようにする。
- タイルセットそのものの制作(壁3種+床3種×8地方、
  `dungeon-dreamscape.md`本体の造形)は本書の対象外。地方の判定が
  解決したことで、**まず第一地方を1式作ってエンジン内プレビューで
  検証する**という元の計画(`dungeon-dreamscape.md`「展開順」)に
  そのまま進めるようになる。

## 受け入れ基準

1. 8地方それぞれのダンジョンで`regionIndexForFloor`が正しい地方
   番号を返す(`regionIndexForDungeonId`と一致)。
2. ぬかるみの底・こだまの巣・山の芯・はじめの夢が、コメントに
   明記された流用元の地方番号を返す。
3. 近道屋の裏穴が深さに応じて地方1→2の番号を返す(境界の深さで
   切り替わることをテストで確認)。
4. 夜ごとの夢が、深さ48を超えたところで地方1へ周回する。
5. 腕試しの間が、各階でその階のボスの地方番号を返す。
6. ひなたの寝穴が常に地方1のタイルセットを使う一方、明るさ・視界の
   既存設定(チュートリアル専用)は変わらない。

## 対象外

- タイルセットそのものの造形(`dungeon-dreamscape.md`本体、

- 樽比べの専用装飾
- 忘れ物蔵の専用の見た目(まず地方1で代替し、必要になれば別途検討)
