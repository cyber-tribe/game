# ガルドの歩行モーションの見直し(人間離れした歩き方を直す)

## 実装状況(このセクションは実装セッションが追記した注記)

`tools/models/garudo.py`の`walk`クリップを打ち直した。接地
(frame1・15)は前脚をほぼ伸ばし(shin 6度)、通過(frame8・22、脚が
交差する中間点)で遊脚側の膝を46度まで曲げるようにし、コンパス歩行の
原因だった「膝がほぼ伸びたまま」を直した(曲げる向きの符号は、
Blenderを診断用ポーズでレンダリングして目視確認した)。腕振りは
±24度から±15度へ抑えた。停止時のidleへのクロスフェードは
`ActorView.play()`が元から持っていた0.15秒相当のfadeIn/fadeOutで
足りていたため、新規実装はしていない。

足滑りの解消(`src/view/village.ts`の`VILLAGE_WALK_TIME_SCALE`、
`src/view/actorView.ts`の`ActorView`コンストラクタに足した
`walkSpeedMul`)は、村の主人公のwalkクリップだけ再生速度を上げる
仕組みを実装したが、倍率(2.2)は運動学的に厳密な歩幅から逆算した値
ではない。脚の長さから素直に逆算すると等倍の十数倍という現実離れした
値になり(この体格のクリップが前提にする歩調と`VILLAGE_MOVE_SPEED`の
桁がそもそも違う)、実機での見え方を確認しながら追い込む前提の
経験的な目安値にとどめている。未決事項として書かれていた「ストライドの
具体値」は、この理由により実装時に確定させず、今後の実機確認での
微調整に委ねた。

骨盤のロール・肩の逆位相・頭の追従補正・肘の曲げ(修正内容の1節に
挙げられている細かな上乗せ)は、今回はコアの膝の曲げと腕振り縮小に
絞り、見送った。前腕(肘から先)を回すボーンエイリアスがそもそも
既存コードに用意されておらず、符号の検証をレンダリングで確認する
コストが今回のセッション予算に見合わなかったため。

受け入れ基準1(膝が曲がって交互に運ばれる)は診断用のBlenderレンダー
静止画で確認済み。基準2(足が滑らない)は上記のとおり厳密な検証は
できていない。基準3(ダンジョンの1マス移動に違和感が出ていない)は
`walk`クリップを使うダンジョン側の再生速度は変更していない
(`walkSpeedMul`は村の主人公インスタンスにだけ渡している)ため
影響なし。基準4(`tools/preview/`と実機の目視確認)は、実機確認は
持ち越し。

## 経緯

村なか歩き(自由移動)でガルドの歩き方が人間離れして見える。
現行の `walk` クリップ(`tools/models/garudo.py`)を読むと原因は
明確で、**脚が付け根から±26度振れるだけで、遊脚の膝がほとんど
曲がらない**(shinは-12〜10度)。膝の伸びたまま脚を振る歩きは
コンパス(ぶんまわし)歩行になり、人形が滑っているように見える。
腕振り±24度も脚に対して大きすぎる。

さらに村は連続移動(`VILLAGE_MOVE_SPEED`)なので、クリップの
歩幅と移動速度が合っていないと**足が地面を滑る**。ダンジョンは
1マス移動の補間なので目立たなかった問題が、村で露呈した。

## 修正内容

### 1. walkクリップの打ち直し(1サイクル=左右2歩、4フェーズ)

人の歩行の基本4フェーズをキーに置く:

| フェーズ | 要点 |
|---|---|
| 接地(コンタクト) | 前脚は膝ほぼ伸展でかかと接地、後脚はつま先残し。胴はやや低い |
| 沈み込み(ダウン) | 接地脚の膝がわずかに曲がって体重を受ける(現行のhipc沈みは活かす)。胴が最も低い |
| 通過(パッシング) | **遊脚の膝を40〜50度曲げて**前へ運ぶ(ここが最重要)。支持脚は伸び、胴が最も高い |
| 蹴り出し(アップ) | 後脚のつま先で押し出し、次の接地へ |

- 腕振りは±15度程度に抑え、肘をわずかに曲げる(棒腕にしない)。
- 骨盤に小さなロール(左右2〜3度)とねじれを入れ、肩は逆位相。
- 頭(neck)は胴の上下動を打ち消す向きに1〜2度だけ補正
  (視線が安定して見える)。
- 少年らしさとして、テンポは軽快寄り(のしのし歩かせない)。

### 2. 足滑りの解消(村側の再生同期)

- クリップの1サイクルで進む歩幅(ストライド)を決め打ちし、
  村の移動速度に対して `再生速度 = 移動速度 / ストライド` で
  同期する(実装は `AnimationAction.timeScale` の調整のみ)。
- 停止時は `idle` へ0.15秒程度でクロスフェード(現状の即切り替えで
  カクつくようなら)。

### 3. 影響範囲

- ダンジョン側も同じ `walk` クリップを使うため、見た目は
  自動的に改善される(1マス移動の再生速度は現状のまま)。
- クリップ名・ボーン構成は変えない(既存の再生コードに手を
  入れない。村側のtimeScale同期だけが追加実装)。
- 村人モデル(`plan/models/model-*.md` の8人)は `idle`/`talk` のみで
  歩かないため影響なし。ただし本クリップの作りを、今後歩く村人を
  作る際の雛形にする。

## 受け入れ基準

1. 村なか歩きで、膝が曲がって足が交互に運ばれる人間の歩きに見える。
2. 足が地面を滑らない(移動速度と歩幅が同期している)。
3. ダンジョン内の1マス移動でも違和感が出ていない。
4. `tools/preview/` のレンダリングと実機の両方で目視確認。
