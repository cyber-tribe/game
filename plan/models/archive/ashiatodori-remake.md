# あしあとどりを設定画に合わせてリメイクする

## 経緯

設定画ベースのリメイク12体目。あしあとどり(`species.ts`の
`ashiatodori`、第二地方7階〜のswarm AI、群れ3〜4羽)の設定画が
提供された。同様に**承認済みの2Dコンセプト+三面図**として扱う
(`turnaround-drawing-craft.md`「5. 正直な逃げ道」)。設定画は
`plan/models/reference-ashiatodori-sheet.png`として保存した。

## 設定画の読み取り(実物を目視)

- **概念**: 消えていく足跡を追いかける鳥。1羽では頼りなく、
  群れで現れる(swarm AIの現行挙動と一致)。距離を取り、空から
  急降下して鋭いクチバシで突く。
- **頭(最大の記号)**: **骨白の頭蓋骨**。ざらついた骨質感で、
  大きな黒い丸い眼窩、長く尖った嘴。
- **羽**: くすんだ紫の**ぼさぼさと層になった羽**が体を覆い、
  **縁は霧に溶けるように半透明**。背・翼・尾から霧の房が
  流れ出ている。体は軽く、風に揺れるとわずかに浮く。
- **脚**: 細い鳥の脚+鉤爪。
- **パレット8色**: 頭骨(生成り)/羽(くすんだ紫)/羽の影/
  羽(薄い部分)/霧・気配/目(黒)/クチバシ・足(茶)/
  足跡の気配(エフェクト用、淡紫)。
- **状態**: 通常(漂う)/気配を察知/追跡開始/警戒(音に反応)/
  威嚇(鳴き声)/急降下準備/急降下(攻撃)/突いた後(離脱)/
  被弾(よろめき)/消散(霧に還る)。
- **攻撃**: ①距離を取って漂う ②足跡を追跡 ③上空へ上昇
  ④急降下して突く ⑤再び離れて漂う。
- **行動**: 足跡の数に応じて群れの数が増える/交互に攻撃/
  途切れると霧に紛れて姿を消す。

## 現行モデルとの差分(実測)

`build_ashiatodori()`は、swarm負荷を抑えるため関節を極限まで
絞った丸い小鳥 — 丸い胴+小さな頭+尾の突起、畳んだ翼は
「胴の両脇の瘤」1個ずつ、青緑系の背腹塗り分け、目玉球、
小さな尖り箱の嘴:

| 項目 | 現行 | 設定画 |
|---|---|---|
| 頭 | 丸い頭+目玉球 | 骨白の頭蓋骨+大きな黒い眼窩 |
| 嘴 | 小さな尖り箱 | 長く尖った嘴(茶) |
| 羽 | 滑らかな胴+瘤の翼 | ぼさぼさの層の羽、縁は霧に溶ける |
| 霧 | 無し | 背・尾から霧の房が流れる |
| 脚 | 塗り分けのみの短足 | 細い鳥の脚+鉤爪 |
| 配色 | 青緑系 | くすんだ紫の羽+骨白の頭 |

「関節数を最少にして群れ描画を軽くする」という現行の設計意図は
正しく、リメイク後も維持する。

## 変更内容

### 1. 頭を頭蓋骨に作り直す

- 頭を骨白の頭蓋骨にする: 丸い頭骨+大きな黒い眼窩2つ
  (暗色の丸いくぼみパッチ+小さなハイライト。目玉球・発光は
  使わない)+**長く尖った嘴**(茶。現行の箱を細く長く)。
- 骨の「ざらつき」はテクスチャで再現しない(フラット方針)。
  頭骨の輪郭に浅い凹凸を1〜2箇所つける程度に留める。

### 2. 羽を層で造形する

- スリガラスのリメイク(`surigarasu-remake.md`)で定めた
  **スカラップ状の羽の段**の手法を流用し、胴・翼にぼさぼさの
  切れ込みを作る。swarm種のため段の枚数は絞る(まぶたむしと
  同じく予算下限寄りの意識)。
- **縁が霧に溶ける**表現は、羽の段の末端・尾の先を「霧・気配」
  色に塗り分けて消す(半透明は使わない。あくびとかげの尾・
  きりみずちの柱下端と同じ翻訳)。
- 霧の房(小さなもこもこ)を尾・背に1〜2個添える。

### 3. 脚

- 塗り分けだけの短足をやめ、細い鳥の脚2本+前指の鉤爪を
  つける(茶)。関節は現行のleg/footの2節をそのまま使える。

### 4. 配色

- 青緑系をやめ、パレット8スウォッチから直接サンプリングする
  (羽=くすんだ紫の3階調、頭骨=生成り、嘴・脚=茶)。
  「足跡の気配」はランタイムエフェクト用の色でありモデルには
  使わない。

### 5. アニメーションを設定画に合わせる

- idle: 「通常(漂う)」— 軽い体がわずかに浮き沈みし、頭が
  風に揺れる(接地したままの軽い上下+首の揺れ)。
- walk: 「追跡」— 一直線に素早く滑るように進む(足跡を辿る
  一途さを、脇目を振らない直進的な動きで表す)。
- attack: 「急降下して突く」— 上へ跳び上がり(タメ)、嘴から
  鋭く突き下ろす(LINEARのツメ)。突いた後すぐ離れる戻りを
  短くつける(「着地はせずすぐ離れる」)。
- hit: 「被弾(よろめき)」— 羽が乱れてよろける。
- die: 「消散(霧に還る)」— 羽がほどけて霧の房ごと崩れ消える。

### 6. 工程・検査

- 2D承認は設定画の提供をもって完了済み。3D化後に平行投影・
  黒塗りレンダーを三面図と重ねてシルエット照合する。
- swarm種(3〜4羽同時)のため、三角形数はモンスター予算
  (1,200〜5,000)の**下限寄り**を目標にする(現行の
  「関節最少・負荷最小」の設計意図を引き継ぐ)。

## 受け入れ基準

1. 正面・側面・背面の黒塗りシルエットが設定画の三面図と重なる
   (照合画像で確認)。
2. 頭が骨白の頭蓋骨+黒い眼窩+長い嘴になっており、目玉球が
   無い。
3. 羽の段がぼさぼさの切れ込みとして読め、羽・尾の末端が
   霧の色に溶けている。
4. 青緑系の旧配色が残っていない。
5. 三角形数が予算の下限寄り(3〜4羽同時表示で負荷が増えない)。
6. attackが「跳び上がって突き下ろす」急降下の動きになっている。
7. エンジン内プレビューの新旧比較で、設定画のキャラクターだと
   一目で分かる。

## 対象外

- 足跡の気配(淡紫のエフェクト)・急降下の軌跡などの
  パーティクル演出(`particles.ts`側。パレットの「足跡の気配」は
  その際の参考色として残す)
- 群れの規模の変化・交互攻撃のゲームシステム化(swarm AIの
  現行挙動のまま)
- ステータス・出現階層の変更(設定画「B2F〜」と現行
  `minFloor: 7`=第二地方の食い違いは本書では触らない)

## 未決事項

- 霧の房を尾・背のどちらに何個置くか(シルエット照合と予算で
  調整)
- 眼窩をくぼみジオメトリにするか暗色パッチだけで済ませるか
  (swarmの予算次第。パッチで読めるならパッチ優先)

## 実装結果(2026-09-21)

マブタムシ・スリガラス・ワスレガニ・あくびとかげで固まった手順
(設定画を実寸マスクへ起こす → Anatomy Gate → Color Gate → 96px 判定)で
作り直した。造形は新設した `tools/models/ashiatodori.py`。
`monsters.py` の旧実装(Skin 修飾子の丸い小鳥 約110行)は削除し、
`build_ashiatodori()` は新モジュールへ委譲するだけにした。

### 設定画マスクの作り方(この種に固有の難しさ)

この設定画は**体のまわり一面に霧が描かれている**ので、明度だけでは
体と切り離せなかった。実測すると

| | L | R−B | G−B |
|---|---|---|---|
| 紙 | 226 | +30 | **+15** |
| 霧 | 190 | +23 | **0** |
| 頭骨 | 147 | +27 | +8 |
| 羽 | 110 | +5 | −13 |

頭骨(明るい)と霧(明るい)は明度が重なる。**明るい側だけ G−B(暖色か)
で切る**と分かれた(`lum < 198 かつ ¬(lum > 172 かつ G−B < 5)`)。
足元は霧が地面いっぱいに広がって脚と1つの塊になるので、下から 28% の帯
だけ「暗い(L<135)」を足して脚だけ残す(handbook 4-34)。

### 実測(全高 0.267m 換算)

| 部位 | 値 |
|---|---|
| 頭骨ドーム | 幅 98mm・上端 z=262・最大幅の高さ z=190・顎下 z=158 |
| 眼窩 | 径 39mm・中心 x=±36 / z=203(中心間 72mm に対し 0.54) |
| 嘴 | 付け根 z=176 → 先 z=119、前へ 52mm(水平から約 48°) |
| 体の最大幅 | 193mm(z=85〜105) |
| 後ろへの最大 | y=+110mm(z=115)。z=145 ではない |
| 脚 | x=±24・接地〜z=72、指は前3本+後ろ1本 |

**頭骨は上下対称の楕円体ではない。** 正面図の骨の幅を 5mm ごとに測ると、
最大幅 98mm の z=190 から上は z=262 までなだらかに、下は z=158 で急に
終わる。上半分 R_z=0.072 / 下半分 R_z=0.032 の非対称な楕円体にした。

### 構造

* **頭骨が最大の記号**。ドーム + 掘った眼窩2つ + 長い嘴に面を使う。
  眼窩は黒い球を置くのではなく**掘ってから黒く塗る**(handbook 4-73)。
* **羽は「芯 + 輪郭を作る羽毛」**。滑らかな芯(隠れる前提)を小さく作り、
  シルエットは `C.hair_clump` の羽毛 68 枚が作る(handbook 3-2)。
  行は 襟・項・喉・冠羽・背・翼面・雨覆・風切羽・尾・脇腹・胸・腹の裾 の 12。
  翼は **大きな翼面 → 雨覆(中羽)→ 風切羽** の3層にした(handbook 4-53)。
* **霧は別体で作らない**(下記)。
* swarm(3〜4羽同時)なので三角形 6,110・容量 504.7KB に収めた。

### 失敗と対処

**羽が「ヤマアラシの針」になった。** 最初は半幅 12〜15mm・長さ 60〜90mm で
縦横比 1:4〜1:6。handbook 4-50 のとおり**縦横比を先に直す**(1:2.3 前後)。
半幅を 1.35 倍にしたら、同じ枚数・同じ三角形数のまま「重なった羽」に
見えるようになった。

**背中が後ろへ伸びすぎていた。** 側面図の実測では後ろへの最大は
**z=115 で y=+110mm**。モデルは z=145 で +140mm あり、尾が高い位置で
後ろへ突き出して「孔雀」になっていた。尾・背の行を下げて詰めた
(側面の胴 IoU 0.59 → 0.78)。

**頭と胴の間に首が見えていた。** 設定画のあしあとどりに首は無く、羽が
頭骨の際まで来ている。項(nape)と喉(throat)の行を足して埋めた。

**霧の房(球)は作ってはいけなかった。** 設定画の霧は数えられる房では
なく空気。球を置くと 96px で「体に付いた泡」になり、背面からは体の上に
乗る(あくびとかげの煙とまったく同じ失敗 ―― handbook 4-101)。
**羽の先端を霧の色へ寄せる塗り**だけに任せた。先端の判定は、テクセルごとに
68 枚の羽を最近傍探索すると遅いので、羽の中心線から粗いボクセル場
(4.5mm)へ「その点を覆っている羽の t」を先に焼いて添字引きにした
(handbook 4-16)。

### 塗り

設定画のパレット(色み)と絵の中の実測(明度)を分けて使う(4-63)。
絵の実測 sRGB: 頭骨 (220,200,178) L203 / 嘴 (150,133,119) L137 /
羽 基調 (116,103,116) L108 / 羽 暗部 L81 / 霧へ溶ける先 L167 / 目 L41。

**頭骨は羽の 1.88 倍**。この対比が 96px で「骨の顔」を読ませている。

ダンジョンの灯りが寒色なので中性の羽色だけ R を B より上げて相殺した
(handbook 4-99)。実機の R−B は −15〜−19 で、近隣のモンスター
(まどろみ −18 / スリガラス −16 / ホネガラミ −9)の範囲に収まる。

### アニメーション

設定画の状態に合わせて全クリップを書き直した。翼のボーン(`body-wing.L/R`)
を新設し、

* idle(漂う): 体が軽いので浅く浮き沈みし、翼が呼吸のように開閉。
  尾は頭より2フレーム遅れて追従する
* walk(追跡): 一直線に滑る小走り。翼は畳んだまま小さく煽る
* attack(急降下して突く): 翼を広げて跳び上がるタメ → LINEAR で突き下ろし
  → 行き過ぎ → すぐ離れる(着地しない)
* hit(よろめき): 羽が乱れて後ろへ泳ぐ。入りは LINEAR
* die(消散): 翼がほどけて広がり、低く崩れて消える

### 次回への持ち越し

- **側面の IoU 0.680。** 設定画の三面図が食い違っている(正面図・背面図は
  頭骨の上端 z=262、側面図は z=240)。2対1で正面・背面を採ったので、
  側面では頭が設定画より上へ出る(handbook 4-98 の代償)。
  側面の脚 IoU 0.24 も、設定画の側面だけ歩行中の開いた脚で描かれている
  ことによる差。
- **背面図で頭骨のドームが隠れる。** 設定画は背面からドーム全体が見える。
  `hair_clump` の羽は「横に広く・表裏に薄い」断面なので、頭骨の脇に置くと
  背面から見て幅が出てドームを覆う。断面の向きを羽ごとに指定できるように
  すれば直せるが、ゲームカメラは 3/4 前方なので優先度は低い。
- 羽1枚が設定画より大きい(枚数を増やすと swarm の予算を超える)。

## 追記(2026-09-21): 羽をスリガラス方式へ作り直す

「羽に関してはスリガラスを参考に」という指示で、羽毛だけを
`tools/models/surigarasu.py`「羽毛」節の方式へ入れ替えた。

### 何が違ったか

初版は 1 枚を `C.hair_clump`(レンズ断面の立体)で作っていた。1枚 48 三角形
なので、swarm の予算に収めると 68 枚しか置けず、どれだけ幅を調整しても
「重なった羽」ではなく「刺さった羽の束」にしかならなかった。

スリガラスの方式は3つの部品でできている。

1. **帯(`_strap`)** ―― 1枚 6 三角形の板。胴・襟・翼の雨覆のように
   **面を覆う**羽はこれ。同じ予算で枚数が 8 倍置ける。
2. **楔(`_blade`)** ―― レンズ断面の立体。冠羽・尾羽・中羽・風切羽のように
   **輪郭に切れ込みを作る**羽はこれ(帯は 90° で消える)。
   翼弦が稜線に直交するので、側面からも幅を持って見える。
3. **縞テクスチャ**(横=縞の種類 16 本、縦=根元 0 →先 1)。1枚の UV は
   1 列ぶんの縦帯。根元が暗く先が明るい階調が**無料で**付く。

3 が効いた。あしあとどりの「羽の先が霧へ溶ける」は、初版では羽の中心線から
粗いボクセル場を焼いてテクセルごとに引いていた。縞テクスチャなら同じ絵が
16×32px = **0.7KB** で出る。本体のアルベドも 384px で足りるようになり、
テクスチャの合計は 170KB → **26KB** になった。

### 帯で覆う体は「縦軸」でパラメタ化する

最初、胴の芯(前後 y のロフト)の上に帯を貼った。`core_surface` の法線は
常に放射方向(x–z)なので、**正面から見ると胸の羽が全部 edge-on** になり、
胸だけ裸の卵に見えた。スリガラスが直立姿勢で `trunk_surface(v, th)` ――
v=高さ、th=方位角 ―― を使っているのは、羽が「上から下へ垂れる」からで、
姿勢の違いではなく**羽の流れの軸**でパラメタ化しているのだった。

芯を縦軸の輪切り(`BODY_RINGS` / `body_surface(v, th)`)へ作り直し、
羽は v を下げる向きへ垂らした。胸が face-on になり、正面の胴の IoU は
0.729 → 0.839 に戻った。

### 左右対称は「角度の符号」では作れない

冠羽を `th = ±deg` の2本で書いたら、正面図で左 −59mm / 右 +84mm という
**非対称**になった。`_blade_point` の翼弦は `稜線 × X` で決まるので、
稜線の x 符号が違うと翼弦の向きが左右で揃わない。
スリガラスと同じく **0〜180° の片側だけ書き、`_blade(side=-1)` で鏡にする**。

### 左右 45° の房は「耳を立てたフクロウ」(handbook 4-50 の再発)

正面図で頭の脇に出る幅を作ろうとして、頭骨の脇(th 40〜102°)へ大きな房を
6本立てた。結果は頭のまわりに角が並んだ**道化の帽子**。4-50 にそのまま
書いてあった失敗を、種を変えてもう一度踏んだ。撤去して冠羽を前後の稜線
(th 0〜48°)へ一本化したら直った。

### 冠羽は「背中の上」ではなく「頭の真後ろ」

側面図の実測では z=195〜215 の帯に体はほとんど無く、あるのは頭骨
(y −0.139〜−0.058)と**その真後ろの冠羽**(y −0.02〜+0.01)だけ。
背中の上(th≈180)から立てると、頭の後ろではなく**胴の後ろ**へ
大きくはみ出す(側面の頭まわりが 39cm² 過大になった)。

**IoU は下がった。** 外周だけを見れば hair_clump 版のほうが合っていたが、
あれは「羽の形をしていない太い棒」で外周を作っていたからで、
handbook 4-72(シルエットを崩すと IoU は下がる ―― 下がることが正しい
場合がある)と同じ関係にある。96px の判定画像では、重なった羽・霧へ
溶ける先・層になった翼のどれもスリガラス方式のほうが読める。

### 次回への持ち越し

- 正面・背面の外周が設定画より 4〜8% 小さい(帯は面に沿うので、棒より
  外へ出ない)。段を増やすか、外周に届く楔を数枚足すかは次版で。
- 側面の脚 IoU 0.40 は設定画の側面だけ歩行中の開いた脚で描かれている差。

## 第3版 ―― 骸をホネガラミ方式で作り直す

前版の骸は `Vector` の半径3つで作った楕円体に、眼窩の窪みを1つだけ
足したものだった。96px でも45度でも「つるんとした卵に顔を描いた」形で、
ホネガラミが第7版まで止まっていたのと同じ状態だった(handbook 4-109)。

`tools/models/honegarami.py` の「頭蓋」節の方式へ全面的に置き換えた。

### 方式

1. **輪切りの表** `SKULL_RINGS = [(t, rx, ry, cy), ...]`(19段)。
   t=0 が頭頂(z=260)、t=1 が骸の下縁(z=162)。段ごとに前後の中心
   `cy` を持つので、「下へ行くほど上顎が前へ出る」が表そのもので出る。
2. **彫りと張り出し**。方位角と t の楕円窓で `(1-d1²)(1-d2²)` の
   落ち方で半径を増減する。`DENT_SHARP = 0.45` で底を平らに・壁を立てる。
   **張り出しを先に集め、窪みがあれば窪みを採る**(4-111)。
3. **`_skull_uv()`** で表面の点を (方位角, t) へ戻し、**塗りを彫りと
   同じ窓で書く**。ホネガラミが眼窩を彫るのを諦めた理由
   (「塗りの穴と彫りの穴が45度でずれる」)は、座標を共有すれば
   原理的に起きない(4-110)。
4. **下縁は方位角ごとに高さを変える**。真正面(嘴が出るところ)は
   t を 0.15 持ち上げて z=176、頬では z=162。±2mm の決定的ジッタで
   割れた縁にする(4-115)。

鳥の骸なので、ホネガラミの6項目は
丸く広い脳函 / 眼窩の下の張り出し / 深い眼窩 / 鼻梁と鼻腔の溝 /
前へ出る上顎(嘴)/ 割れた下縁 と読み替えた。

### 実測(設定画、全高 267mm 換算)

| | 値 | 出どころ |
|---|---|---|
| 骸 正面 | 幅 98.1 × 高さ 102.4mm | `at_bone.py` |
| 最大幅 | z=190 で 98mm(輪郭線込み 101) | 正面図の行ごとの幅 |
| 眼窩 | 中心 x=±27.5 / z=199、27 × 28mm | `head_front.png`(mmグリッド) |
| 眼窩の光 | 上の外側に 3mm | 正面・側面とも |
| 骸 前縁 | z=246 で y=-0.111 → z=190 で y=-0.150 | `head_side.png` |
| 嘴 | 最大半幅 14mm(z=155) | 正面図 |

**側面図の頭は正面図より 9mm 低く描かれている**(眼窩の中心 z が
188 と 199、頭頂が 248 と 258)。側面の数値は +9 して使った(4-98)。
嘴の先端の高さは三面図が食い違う(正面 z=108 / 側面 z=137)ので
中間の 119 を採った。

### 途中で踏んだ穴

- 眉庇と眼窩下縁の張り出しが眼窩の上下を埋め、**眼窩が「閉じた目」の
  線**になった(4-111)。
- 骸と嘴の塗り分けが `p.y > 付け根.y` という粗い条件で、**眼窩の
  下半分が嘴の茶色**で塗られていた(4-113)。判定結果をそのまま色に
  して焼いたら5分で判った。
- 骸の UV 島が 512x512 のうち 110x110 しかなく、眼窩が 14 テクセルに
  潰れていた。羽毛の帯が UV を取り合っていたため(4-114)。
  `organic_uv` の boost を 3.4 → 9.0、`BONE_TEX` を 512 → 1024 にした。

  価値がある(ホネガラミの「頭蓋は塊の中に埋まっていて顔だけが出て
  いる」と同じ処理)。
- 実機の暗部は L41.5 で頭打ちになる(ホネガラミも同じ)。設定画の
  眼窩/羽 比 0.33 はこの床のせいで実機では 0.55 までしか下がらない。

## 第4版 ―― 眼窩を設定画からトレースし、骸を項の羽で囲う

第3版の「次回への持ち越し」に書いた2点をそのまま実行した。

### 1. 眼窩のトレース(`tools/ashiatodori_decal.py`)

眼窩の縁の形・中の階調・光の位置を手で置くのをやめ、設定画の正面図から
**骸の媒介変数 (方位角, t) の空間へ**写した1枚のデカールにした。
`_skull_uv()` が表面の点を同じ座標へ戻すので、彫った眼窩と塗った眼窩が
原理的にずれない(4-110)。

デカールに入れるのは **R=暗さ / G=光 / A=被覆** だけで、紙の色も広い陰影も
持ち帰らない(4-116)。色はモデル側のパレットから出すので、ダンジョンの
寒色の灯りへの暖色補正(4-99)がそのまま効く。

彫りの窓(`SOCKET_AZ` / `SOCKET_HW` / `SOCKET_HT`)も、手で置かず
**トレースが出した値を書き写す**:

```
  眼窩0  23.3x30.6mm  x=-26.2 z=196.1  -> 方位角 -123.8度 半幅 16.5度 t 0.6517 半幅 0.1553
  眼窩1  23.5x30.1mm  x=+24.5 z=196.0  -> 方位角  -58.6度 半幅 16.1度 t 0.6527 半幅 0.1523
```

### 2. 項の羽(`HOOD`)

Anatomy Gate の**帯ごとの半幅**を取ると、頭の高さで設定画が一貫して
6〜27mm 広かった。差はぜんぶ骸を囲う羽で、骸のドームを丸ごと露出させて
いたのが「兜をかぶった鳥」の正体だった(4-117)。

* **帯(strap)で作る。** 帯の幅は必ず水平なので正面のシルエットに幅が
  そのまま出る。1枚 6 三角形なので 23 枚でも 138 三角形しか使わない。
* **いちばん高いのは羽の先で、骸ではない**(4-118)。全高 267mm の
  てっぺんを羽に渡したので、骸の頭頂が設定画どおり 258mm に落ち着いた。
* **頭頂の真後ろには置かない**(4-119)。置いた版は背面が「棘の冠」に
  なった ―― 背面から見て帯がドームの上にかかるため。

### 結果

| 指標 | 第3版 | 第4版 |
|---|---|---|
| Anatomy Gate 正面 | 0.788 | **0.799** |
| Anatomy Gate 側面 | 0.663 | **0.670** |
| Anatomy Gate 背面 | 0.759 | **0.770** |
| 正面の面積(設定画 290.71cm²) | 281.63 | **290.21** |
| 頭の帯の半幅の差(z=266/258/250/242) | −16/−11/−14/−7 | **+0/−6/+0/+3** |
| 嘴/骸の明度比(実機) | ― | 0.625(設定画 0.609) |
| 三角形 / 容量 | 9,000 / 557KB | 9,000 / 553KB |

嘴の明度比は測ったうえで**触っていない** ―― 設定画と合っているので、
正面で淡く見えるのは実機の暗部の頭打ち(L41.5)のほうの話である。

### 次回への持ち越し

- 側面で項の羽が細い棘に見える。帯は 90° で消えるため(4-54)で、側面の
  かさは楔(`CREST`)が担うべき ―― 冠羽を数枚足すのが次の一手。
- 背面図の骸は正面図より大きく・高く描かれている(106.9x85.2 / 上端 266.8
  対 98.1x102.4 / 258.3)。正面を採ったので、背面はドームの脇に羽が出る。
