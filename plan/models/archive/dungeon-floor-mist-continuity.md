# ダンジョンの床が空中に浮いて見える問題を直す

## 経緯

「なんかダンジョンが空中に浮いて見えます」という指摘。実際に
`dungeon-dreamscape.md`(実装済み・アーカイブ)の実装内容を確認すると、
原因になりうる欠落が2つ見つかった。

## 診断

### 1. 床の縁ともやの間に、何もない隙間がある

`src/view/dungeonMesh.ts`の`buildDreamMist`は、フロアの外周
(`floor.width`/`floor.height`)から**1.5マス離れた位置**にもやの板を
置いている:

```ts
const margin = 1.5; // 境界からの張り出し
```

ところが元の仕様(`dungeon-dreamscape.md`「1. 夢の演出言語」)が
求めていたのは「**床の最外周タイルは縁がもやに溶けるようにフェード
させる(頂点アルファ)**」、つまり**床自体の縁を透明にして、隙間なく
もやへ連続させる**ことだった。実装ノートを見ると、この頂点アルファの
縁フェードは「地方色のグラデーション」等と同じく**今回は見送られ、
外周にもやの板を1枚置くところまでしか実装されていない**。

結果として、**床は縁で唐突に(不透明のまま)途切れ、そこから1.5マス
ぶんの何もない虚空を挟んで、ようやくもやの板が現れる**という構成に
なっている。この「床の縁 → 虚空 → もや」の隙間が、床が宙に浮いた
台座のように見える直接の原因。

### 2. 夢空(スカイドーム)がカメラに完全追従し、床との繋がりが無い

`src/view/renderer.ts`の`buildDreamSky`は、頂点カラーの半球を
**`Renderer.camera`の子として**追加している:

```ts
this.dreamSky = buildDreamSky();
this.camera.add(this.dreamSky);
```

カメラの子であるため、位置だけでなく**カメラの傾き(斜め見下ろしの
48度)もそのまま引き継いで回転する**。実装コメントは「半球は放射状に
対称なので、カメラの向きが変わっても絵は崩れない」としているが、
これは正しくは**ヨー(左右の首振り)についてのみ**成り立ち、
カメラが常に48度下を向いている**ピッチ**については当てはまらない。
結果、夢空は実質的に「画面に固定されたグラデーション背景」として
描かれ、床・壁の3D的な奥行きとは無関係に常に同じ絵になる。
床の遠い端が実際の地平線へ自然に消えていく感じが出ず、**書き割りの
背景の前にジオラマを置いただけ**のような、奥行きの繋がりを欠いた
絵になっている。

## 修正方針

### 1. 床の縁ともやの隙間を埋める(優先度・高)

- `buildDreamMist`のもやの板を、床の外周から離した位置ではなく
  **床の外周ぎりぎり(隙間ゼロ)**に置き直す。
- あわせて、元の仕様どおり床タイルの最外周1列に頂点アルファの
  フェードを入れる(`dungeonMesh.ts`の床メッシュ生成に、フロアの
  端に接するタイルだけ縁を透明化する処理を足す)。もやの色と
  自然になじむよう、フェード後の色ともやの色を近づける。
- この2点だけで、「床が唐突に途切れて虚空を挟む」感覚は解消できる
  見込みが高い(スカイドームに手を入れなくても効果が出るはず)。

### 2. 夢空をカメラのピッチに追従させない(優先度・中)

- `dreamSky`をカメラの子にしたまま、**ローカル回転をカメラの
  ピッチぶんだけ打ち消す**(`dreamSky.rotation.x`にカメラの
  `elevation`の符号反転を毎フレーム設定する。ヨーは引き継いだまま
  でよい)。これにより、グラデーションの「地平線寄りの明るい色」が
  画面の中の実際の遠景(床の奥)に近い位置へ来るようになり、
  奥行きの繋がりが自然になる。
- 影響範囲がカメラ制御に近く、1のもやの隙間修正より慎重な検証が
  要るため、まず1を先に直して効果を確認し、それでも「奥行きが
  平面的」という印象が残る場合に着手する。

## 受け入れ基準

1. ダンジョンの床の縁が、はっきりした境界線や虚空の隙間なく、
   もやへ連続して見える。
2. 「床が空中に浮いている」という印象が、新旧比較のスクリーン
   ショットで明確に軽減されている。
3. 生成ロジック・当たり判定・ミニマップは変更しない
   (`dungeon-dreamscape.md`の対象外方針を維持)。
4. モバイル実機で60fpsを維持する。

## 対象外

- 地方別タイルセットの造形(`dungeon-region-detection.md`が
  地方判定を解決済みなので、別PRとして進める)
- ヨリシロの記憶の断片(巨大日用品)等、他の未着手項目

- 夢空のピッチ追従打ち消し(修正方針2)に実際に着手するかどうかは、
  修正方針1の効果をエンジン内プレビューで見てから判断する

## 追記 ―― もやの色が気分と食い違う・四隅に隙間がある(2026-09-03)

「壁の外側は黒く塗るのが良いのでは、もしくはブロックで埋めるか」との
指摘。調査すると、空が見える経路は2つあると判明した:

1. **マップの外周**(もやで覆っている範囲) ―― もやが固定の青
   (0x8fa0c8)のままで、`plan/mood-visual-effects.md`が導入した
   気分ごとの霧色(`setMoodVisual`)と食い違い、外周だけ唐突に
   別の色の帯が浮いて見える。加えて、床の縁との隙間を消すために
   `margin`を1.5→0にした際(本書の最初の修正)、板の幅を伸ばして
   四隅で重ねる分もmarginと同じ変数で計算していたため、marginを
   0にしたことで四隅の重なりも一緒に失われ、対角線上から覗くと
   隣の板との継ぎ目に夢空が覗く隙間ができていた。
2. **壁の上端を越えて見える空**(マップの外周に限らず、部屋の中でも
   数タイル先の壁の上には常に空が見える) ―― 壁の高さが約1.04と
   低く、天井が無く、カメラが48度・高さ5〜13ユニットから見下ろす
   構図のため。こちらは壁の高さ・天井の有無・カメラ角度という
   ゲーム全体の見た目に関わる変更が要るため、**今回は対象外**とし、
   ユーザーの選択で1のみに絞った。

### 直したこと(1のみ)

- `src/view/dungeonMesh.ts`に`DungeonView.setMistColor(color)`を追加。
  もやの共有マテリアルの色を書き換えるだけの薄いメソッド
- `src/main.ts`の`setMoodVisual`呼び出し箇所(ダイブ開始時・
  フロア移動時の両方。前者だけだと2階以降でもやの色が固定の青へ
  戻ってしまう)で、同じ気分値から`setMistColor`も呼ぶ
  (`currentMoodVisual()`/`syncMistColor()`として共通化)
- 板の**位置**(margin、境界ぎりぎりのまま)と**四隅の張り出し幅**
  (`cornerOverhang`)を別の変数に分離。位置は動かさず、幅だけ
  伸ばして隣の板と重ねる

実機のPlaywrightスクリーンショットで、外周のもやが気分の色調と
揃い、四隅の継ぎ目からも夢空が覗かなくなったことを確認した。

### 見送ったこと(2)

壁を高くする・天井を足す・カメラ角度を変える、のいずれも
`dungeon-dreamscape.md`が「対象外」としてきた既存のカメラ・
生成ロジックに触れる変更になるため、今回は着手しなかった。
必要になれば別の計画書として起こす。

## 追記 ―― カメラをもう一段近づけ、天井案を試して撤回(2026-09-03)

「もう一歩カメラは近付いて良さそう」「周りの空は見えないように
したい」との指示。

### カメラ距離

`dungeon-camera-distance.md`が定めた既定値8(可変域6.5〜18)から、
ズーム1段ぶん(±キーの刻み幅1.5)さらに寄せ、可変域の下限である
6.5にした(`src/view/renderer.ts`)。FOV・仰角・可変域そのものは
既存方針どおり変更していない。

### 天井案は幾何学的に成立しないと判明、撤回

フロア全体を覆う不透明な板を、壁の高さ(約1.0)より上・カメラの
高さより下に置けば、遠くの壁の上だけを塞げるはずと考えて実装したが、
実機で確認すると**画面全体(床・キャラクターごと)が板の色で
覆われた**。

原因: このゲームのカメラは常に見下ろす角度(仰角48度)で、フロア
全体を覆う水平な板を「カメラの高さ」と「床の高さ(0)」の間に
置くと、**カメラから伸びるどの視線も、床に届く前に必ずその高さを
通過する**。板の平面(XZ方向)がフロア全体を覆っている以上、
どの視線もその通過点で板に当たってしまい、「壁の上を越える視線
だけ」を選んで塞ぐことができない。この方式は見た目の遮蔽と
「これ以上手前は塞がない」という条件を同時に満たせず、幾何学的に
不成立と判断し、実装を撤回した(`DungeonView`への
`buildCeiling`/`setCeilingColor`追加、`main.ts`の呼び出しを削除)。

空を根本的に消すには、壁自体を高くする(視線が壁を越えられる
距離を物理的に縮める)しかなさそうだが、複数地方のタイルセット
全部に関わる変更のため、着手前にユーザーと相談する。

## 追記 ―― 壁を高くする代わりに、夢空自体を常に真っ黒にした(2026-09-04)

複数地方(第一・第二地方・既定の`wall`)の壁を同時に高くする作業を
実際に試した(`build_wall`の2段ブロック・`_build_wall_region1`の
`height`・`_build_wall_region2`の葦の丈を、いずれも旧仕様の約3倍
(3.3〜3.5)まで伸ばす)。実機で複数の高さを比較し、3.5前後で
部屋の中の空はほぼ見えなくなることを確認したが、その後
「空をなくして真っ黒にするか、隙間をブロックで埋めるかのどちらか
にしてほしい。壁の高さは戻す」との指示を受け、**壁の高さ変更は
全て撤回**(`tools/models/props.py`を元の高さへ戻し、再ビルドして
差分が消えることを確認した)。

代わりに、夢空(`src/view/renderer.ts`の`dreamSky`)を気分の色に
合わせず**常に黒(0x000000)**にした。外周の夢のもや
(`src/view/dungeonMesh.ts`の`buildDreamMist`)も同じ理由で固定の
黒に変更し、気分の色と同期する`DungeonView.setMistColor`・
`App.syncMistColor`は不要になったため削除した。フォグ
(`this.fog`)・環境光(`this.ambient`)は気分演出のまま変更していない
(ダンジョン本体の照明のトーンは従来どおり気分で変わる。「空」だけ
黒に統一した)。

実機のPlaywrightスクリーンショットで、部屋の中・マップの外周
いずれも壁の上やもやの向こうが色の付いた帯ではなく暗い影として
見えることを確認した。
