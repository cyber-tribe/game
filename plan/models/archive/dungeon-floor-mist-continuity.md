# ダンジョンの床が空中に浮いて見える問題を直す

## 経緯

「なんかダンジョンが空中に浮いて見えます」という指摘。実際に
`dungeon-dreamscape.md`(実装済み・アーカイブ)の実装内容を確認すると、
原因になりうる欠落が2つ見つかった。

## 診断

### 1. 床の縁ともやの間に、何もない隙間がある

`src/view/dungeonMesh.ts`の`buildDreamMist`は、フロアの外周
(`floor.width`/`floor.height`)から**1.5マス離れた位置**にもやの板を
置いている:

```ts
const margin = 1.5; // 境界からの張り出し
```

ところが元の仕様(`dungeon-dreamscape.md`「1. 夢の演出言語」)が
求めていたのは「**床の最外周タイルは縁がもやに溶けるようにフェード
させる(頂点アルファ)**」、つまり**床自体の縁を透明にして、隙間なく
もやへ連続させる**ことだった。実装ノートを見ると、この頂点アルファの
縁フェードは「地方色のグラデーション」等と同じく**今回は見送られ、
外周にもやの板を1枚置くところまでしか実装されていない**。

結果として、**床は縁で唐突に(不透明のまま)途切れ、そこから1.5マス
ぶんの何もない虚空を挟んで、ようやくもやの板が現れる**という構成に
なっている。この「床の縁 → 虚空 → もや」の隙間が、床が宙に浮いた
台座のように見える直接の原因。

### 2. 夢空(スカイドーム)がカメラに完全追従し、床との繋がりが無い

`src/view/renderer.ts`の`buildDreamSky`は、頂点カラーの半球を
**`Renderer.camera`の子として**追加している:

```ts
this.dreamSky = buildDreamSky();
this.camera.add(this.dreamSky);
```

カメラの子であるため、位置だけでなく**カメラの傾き(斜め見下ろしの
48度)もそのまま引き継いで回転する**。実装コメントは「半球は放射状に
対称なので、カメラの向きが変わっても絵は崩れない」としているが、
これは正しくは**ヨー(左右の首振り)についてのみ**成り立ち、
カメラが常に48度下を向いている**ピッチ**については当てはまらない。
結果、夢空は実質的に「画面に固定されたグラデーション背景」として
描かれ、床・壁の3D的な奥行きとは無関係に常に同じ絵になる。
床の遠い端が実際の地平線へ自然に消えていく感じが出ず、**書き割りの
背景の前にジオラマを置いただけ**のような、奥行きの繋がりを欠いた
絵になっている。

## 修正方針

### 1. 床の縁ともやの隙間を埋める(優先度・高)

- `buildDreamMist`のもやの板を、床の外周から離した位置ではなく
  **床の外周ぎりぎり(隙間ゼロ)**に置き直す。
- あわせて、元の仕様どおり床タイルの最外周1列に頂点アルファの
  フェードを入れる(`dungeonMesh.ts`の床メッシュ生成に、フロアの
  端に接するタイルだけ縁を透明化する処理を足す)。もやの色と
  自然になじむよう、フェード後の色ともやの色を近づける。
- この2点だけで、「床が唐突に途切れて虚空を挟む」感覚は解消できる
  見込みが高い(スカイドームに手を入れなくても効果が出るはず)。

### 2. 夢空をカメラのピッチに追従させない(優先度・中)

- `dreamSky`をカメラの子にしたまま、**ローカル回転をカメラの
  ピッチぶんだけ打ち消す**(`dreamSky.rotation.x`にカメラの
  `elevation`の符号反転を毎フレーム設定する。ヨーは引き継いだまま
  でよい)。これにより、グラデーションの「地平線寄りの明るい色」が
  画面の中の実際の遠景(床の奥)に近い位置へ来るようになり、
  奥行きの繋がりが自然になる。
- 影響範囲がカメラ制御に近く、1のもやの隙間修正より慎重な検証が
  要るため、まず1を先に直して効果を確認し、それでも「奥行きが
  平面的」という印象が残る場合に着手する。

## 受け入れ基準

1. ダンジョンの床の縁が、はっきりした境界線や虚空の隙間なく、
   もやへ連続して見える。
2. 「床が空中に浮いている」という印象が、新旧比較のスクリーン
   ショットで明確に軽減されている。
3. 生成ロジック・当たり判定・ミニマップは変更しない
   (`dungeon-dreamscape.md`の対象外方針を維持)。
4. モバイル実機で60fpsを維持する。
