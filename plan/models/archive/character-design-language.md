# キャラクターデザインの質を上げる ― デザイン言語の制定とデザインシート先行工程

## 実装状況(このセクションは実装セッションが追記した注記)

パイロット(ガルドの再デザイン)を実装した。`tools/models/garudo.py`:

- **樽守りを姿に載せる**: 背中に小さな背負いダル(`props.barrel_body`/
  `props.barrel_lid`を縮小して流用)を足し、肩ひも2本で背負わせた。
  ベルトは皮ベルトから金具の箍(たが)へ替え、鋲を10個並べた。
  `props.py`の`_barrel_body`/`_barrel_lid`は元々モジュール内だけの
  想定(先頭アンダースコア)だったが、実物の樽と意匠を統一するため
  公開名(`barrel_body`/`barrel_lid`)へ変え、`barrel_lid`は高さ・半径を
  引数で受けられるようにした(既存呼び出しは既定値のままなので
  非破壊)。
- **配色**: 基色(上着)をくすんだ赤茶から樽と同じ飴色(明るい黄土)へ、
  差し色(鉢巻きの房紐)を最高彩度の赤にした。従色(ズボンの灰青)は
  現行維持。
- **顔の規格**: 目を一回り大きくし、黒目にハイライト(白点)を追加、
  閉じ口の線を新規に足した。鼻の大きさは維持(「大きい部位は1つだけ」
  の原則は鼻ではなく目の拡大で扱った)。
- **デザインシート**: `plan/models/sheets/garudo.md`を新設(今後の
  改修・新規キャラすべてに義務付けられる先行工程)。

三角形数は5,864→7,400(施策A新予算15,000〜30,000の範囲内、まだ余裕
あり)。エンジン内(Three.js・トゥーンシェーダー)のヘッドレス
プレイテストのスクリーンショットで、ダンジョン・村どちらでも新配色が

**新旧比較スクリーンショットのPR添付(受け入れ基準5)は今回は

## 診断 ― なぜデザインが素人っぽいのか

`design/characters.md` の設定は十分に豊かだが、それを**絵に翻訳する
工程が存在しない**。現状はテキスト設定から直接 `tools/models/*.py` の
座標打ちへ飛んでおり、デザイン(シルエット・比率・配色・記号の設計)は
誰も行っていない。その結果:

1. **全員が同じ語彙でできている。** どの種族も「球をつないだ胴+
   共通の `eyeball()`+球の鼻」。ぷるんもねずみもきのこも、造形の
   文法が同じなので**全部同じ生き物の色違い**に見える。
2. **シルエットの設計が無い。** 黒塗りにしたとき種族を言い当てられる
   キャラがほぼいない(ガジリねずみの耳・尻尾など一部の例外だけが
   機能している)。
3. **配色が場当たり。** 各モデルのRGB直書きで、パレットの規律
   (基色・従色・差し色の比率、彩度・明度の帯)が無い。ガルドは
   くすんだ赤茶+暗青+暗茶で、**主人公なのに画面で一番地味**。
4. **職業・性格が姿に載っていない。** ガルドは「鉢巻きの少年」で
   あって「樽守り」に見えない。設定上の一番の個性(タルと生きる
   仕事)がデザインに一切現れていない。
5. **顔の規格が無い。** 白目+黒目+眉のみで口が無いモデルが多く、
   表情の器がない。目のハイライトも無いため生気が出ない。

## 1. デザイン言語(全キャラ共通の文法)

### シルエット第一の原則
- **黒塗りシルエットだけで「誰か/どの種族か」が分かる**ことを
  全キャラの合格条件にする。判別に使える要素は輪郭だけ
  (耳・尻尾・傘・たが・武器・髪など、外形に出る記号)。
- 新規・改修キャラは、造形前にシルエット案を3つ描き比べて
  1つ選ぶ(下記デザインシート)。

### 形の言語(性格を輪郭で語る)
`design/characters.md` の性格・AIを、図形の印象に対応させる:

| 性格・役割 | 基本図形 | 例 |
|---|---|---|
| 無害・愛嬌(ぷるん系、coward) | 丸。重心低く、角ゼロ | ぷるん、わたあめのおばけ |
| 頑固・不動(guard、骨系) | 台形・四角。接地が広い | ホネダタミ、かざりだるま |
| 危険・すばやい(ambush、thief) | 三角・鋭角。先端が細い | モヤウツボ、スリガラス |
| 主人公・村人 | 丸+四角の混合(親しみ+芯) | ガルド、ゲンド |

- 同じ「丸」でも、**浅い階ほど輪郭を単純に、深い階ほど輪郭を
  複雑に**する(夢の深さ=形の情報量、という規律)。

### 比率の言語
- 頭身を役割で使い分ける: 村人・ガルド=**2.5頭身**(頭が大きい=
  愛嬌・可読性)、地方ボス=**実質1.5頭身の塊感**(大きさより
  「詰まった重さ」で強さを出す)。
- 「大きい部位は1つだけ」の原則: 目が大きいなら鼻は小さく、
  耳が大きいなら目は点に。全部大きいと素人絵になる。

### 色の言語
- **1キャラ = 基色60% + 従色30% + 差し色10%** を上限にする
  (差し色は彩度最高の1色。ガルドなら鉢巻き)。
- 地方ごとに**モンスターの色相族**を定める(第一=緑〜黄緑、
  第二=青緑〜灰青、第三=紫〜茶、第四=白〜黄土、第五=青、
  第六=橙〜灰、第七=朱〜金、第八=薄光色)。同じ画面に出る
  種族が自然に調和し、地方の空気も濃くなる。
- 影・光の色相シフト規則は `visual-quality-uplift.md` 施策Bに従う。
  基色→従色→差し色の導出も `tools/models/common.py` のパレット
  関数に一元化する。

### 顔の規格
- 全キャラ共通: **黒目に必ずハイライト(白点)を入れる**。
  口を必ず作る(閉じ口の線でよい。die/attackで開ける)。
- 目の型を3種に整理する: 丸目(愛嬌)/半眼(眠い・まどろみ系)/
  つり目(危険)。種族の性格で選ぶ。共通 `eyeball()` に型引数を
  足して実装する。

## 2. デザインシート先行工程(新しい作業手順)

モデル改修・新規作成の前に、**1キャラ1枚のデザインシート**を
`plan/models/sheets/<キャラ名>.md` に書く。項目は5つだけ:

1. **三語コンセプト**: そのキャラを3語で(例: ガルド=
   「がんこ・まっすぐ・樽育ち」)。造形判断に迷ったらここへ戻る。
2. **シルエットの記号**: 輪郭で判別に使う要素1〜2個。
3. **図形と頭身**: 形の言語からの選択。
4. **パレット**: 基色/従色/差し色の3色(RGB値まで)。
5. **設定の見せ場**: `design/` の設定のうち、姿に載せるもの1つ
   (載せないものは書かない。1つに絞るのがデザイン)。

シートは短くてよい(10行程度)。**シート無しの造形着手を禁止**する。
これが「設定→絵」の翻訳工程になる。

## 3. パイロット: ガルドの再デザイン

主人公から直す。三語コンセプトは「**がんこ・まっすぐ・樽育ち**」。

- **樽守りを姿に載せる**(施策4の穴を塞ぐ):
  - **背中に小さな背負いダル**(行商の背負い籠のように、肩ひもで
    背負う)。ガルドのシルエットを一発で特定できる記号になり、
    捕獲ゲームの主役であることが立ち姿で分かる。
  - ベルトを**タルのたが**(金具付きの箍)に替える。
    `design/village-buildings.md` の「たがの再利用」の作法とも合う。
- **配色を主人公の色に**: 上着を樽と同じ**飴色(明るい黄土)**に
  変え、村の景色(樽色)の主として立たせる。ズボンは灰青のまま
  従色、**鉢巻きの黄+差し色の赤い房紐**を彩度最高点にする。
  現行の「くすんだ赤茶の上着」は暗すぎて主役感が出ない。
- **顔**: 目を一回り大きく+ハイライト、閉じ口の線を追加、
  眉はさらに太く(現行の眉は良い)。鼻の大きさは維持
  (「大きい部位は1つだけ」を鼻ではなく**目**に切り替えるか、
  エンジン内プレビューで両案を比較して決める)。
- 頭身・ずんぐり比率は現行を維持(可読性の判断は正しい)。
- `visual-quality-uplift.md` 施策Aの新ポリ予算(15,000〜30,000)で
  造形し、新旧比較スクリーンショットをPRに添付する。

ガルドで工程(シート→シルエット3案→造形→エンジン内確認)を
検証してから、ぷるん→地方ボス8体→村人の順に展開する
(ぷるんは「顔」なので2番手。ボスは1体あたりの画面価値が最大)。

## 受け入れ基準

1. ガルドの新デザインが、黒塗りシルエットだけで「タルを背負った
   少年」と分かる。
2. ガルドのパレットが基色・従色・差し色の3色+肌色に収まり、
   差し色の彩度が画面上で最も高い。
3. 全改修キャラの黒目にハイライトがあり、口がある。
4. デザインシートが `plan/models/sheets/` に置かれてから造形が
   始まっている(以後の運用ルール)。
5. 新旧比較スクリーンショットで第三者が新を選ぶ
   (`visual-quality-uplift.md` の基準と同じ)。
