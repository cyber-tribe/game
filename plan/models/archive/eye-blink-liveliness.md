# 目にまばたきを実装し、静止した表情から抜け出す

## 経緯

`ps2-quality-adversarial-review.md` 重大4の指摘: `monsters.py` の
`eyeball()` は `look` を造形時に一度だけ焼き込む静的パラメータで、
**まばたき・視線の動きの仕組みが存在しない**。村のカメラは背後寄りで
顔が画面に大きく映る構図を既に採用しており、無表情固定が目立つ。
その世代の主役級キャラクターでも、まばたきは生命感の最低ラインとして
標準的に入っていた。

## 現状の技術的な壁

目(白目球+瞳球)は `garudo.py`・`monsters.py` のどちらでも、体の
他パーツと一緒に `join()` で**1枚の固定メッシュへ統合**されてから
armatureへバインドされる。統合後は個別に動かせないため、まばたきを
実現するには**目を統合前の独立したノードのまま残し、実行時
(Three.js側)から直接いじれる状態にする**必要がある。

## 変更内容

### 1. 目を `join()` の対象から外し、頭の骨へ剛体で追従させる

- `common.py` に `parent_to_bone(obj, armature, bone_name)` を
  新設する。Blenderの「ボーンへの親化」(`obj.parent = armature`;
  `obj.parent_type = 'BONE'`; `obj.parent_bone = bone_name`)を行い、
  スキンウェイトを持たない剛体の子として頭骨に追従させる
  (現実の目玉が頭の骨に対して動かないのと同じ扱い。変形は要らない)。
- `eyeball()` が返す白目・瞳オブジェクトを、これまでの
  `join([body] + extras, ...)` 対象から外し、代わりに
  `parent_to_bone(eye, armature, "head")` で頭骨へ直接つなぐ。
  `garudo.py` の手組みの目(`eyewhite{side}`/`pupil{side}`)も同様に
  独立ノードのまま残す。
- glTFのノード階層としては、目メッシュが頭ボーンの子ノードとして
  書き出される。Three.jsはボーンもOjbect3Dなので、スキニングを
  介さずとも親ボーンのアニメーションに追従する(既存の
  `SkeletonUtils.clone` の複製対象にも自然に含まれる)。

### 2. まばたき対象として印を付ける(glTF extras経由)

- モデルごとに目の命名が揃っていない(`eyeball()` 系は
  `_w`/`_p` 接尾辞、`garudo.py` は `eyewhite{side}`/`pupil{side}`)。
  名前に頼らず、Blenderのカスタムプロパティで印を付ける:
  `obj["blink"] = "white"` または `"pupil"`(左右をまとめて同時に
  閉じるので左右の区別は不要)。
- glTFエクスポート時にカスタムプロパティは自動的に `extras` として
  書き出される。Three.jsの `GLTFLoader` はこれを `object.userData`
  として読み込むため、`src/view/` 側は名前に依存せず
  `userData.blink` の有無だけで対象を判別できる。

### 3. 実行時のまばたき制御(`src/view/blink.ts` を新設)

- `Instance` ごとに、`userData.blink` を持つオブジェクトを
  `instantiate()` 直後に収集し、キャッシュする。
- インスタンスごとに独立したランダムタイマー(目安2〜6秒間隔)を持ち、
  同じ種族が画面に複数いても同期して瞬きしないようにする。
- まばたきは目の**ローカルZ軸(上下)スケールを一瞬0.05倍まで潰し、
  数フレームで戻す**(閉じ2〜3フレーム→止め1フレーム→開き
  2〜3フレーム)。まぶたのメッシュを新設せず、既存の目玉を潰す
  簡便な手法(スライム系の潰れ表現と同じ「スケールでごまかす」
  精神を踏襲)。
- 更新は既存のアクター描画更新ループ(`src/view/` のアクター表示側)
  に1行差し込む形にし、新しい毎フレームループを増やさない。

### 4. ついでに入れる、ほぼ無料のおまけ: 待機中の視線の微揺れ

同じ仕組み(目を独立ノードとして直接動かせる)を使い、待機
(idle)中に瞳の位置をごくわずかに(半径のごく一部)ランダムな
方向へ数秒おきに動かす「サッケード」的な微揺れを加える。目を
凝視状態から解放するだけの安価な効果で、実装は
まばたきタイマーと同じ仕組みに乗せられる。**カメラやプレイヤーを
実際に見る本格的な視線追従(gaze tracking)は対象外**(下記)。

## 対象外

- プレイヤー・カメラなど実在ターゲットを注視する視線追従AI
  (ターゲット認識の設計が別途必要になるため、独立した検討課題とする)
- まぶたの造形追加(まつ毛・二重線等)。今回は目玉のスケール潰しで
  代替する
- 口の開閉・表情差分(別課題)

## 受け入れ基準

1. ガルドと代表的なモンスター数種が、待機中に自然な間隔で
   まばたきする。
2. 同じ種族が複数画面にいても、まばたきのタイミングが揃わない。
3. まばたき中も攻撃・被弾等のボーンアニメーションと干渉しない
   (目は頭骨の子のため、頭の動きにはそのまま追従する)。
4. `parent_to_bone` を使った目が、既存の頂点カラー・輪郭線
   (背面ハル)の対象から外れない(目には元々輪郭線を掛けていない
   ことを確認。掛かっている場合は影響を確認する)。
5. モバイル実機で60fpsを維持する(タイマー処理はアクター数に対して
   軽量)。

## 未決事項

- まばたきの間隔・速さの具体値(2〜6秒はたたき台。エンジン内
  プレビューで違和感のない範囲に調整する)
- サッケード的な視線の微揺れを全種族に適用するか、一部(表情の
  意味が強い種族)に絞るか

## 実装状況

パイロット3体(ガルド・つぶてガエル・まぶたむし)で技術基盤を実証し、
アーカイブした。まぶたむしは題材(瞼の隙間に湧く夢)ともよく合う選定。

- **1. 目をjoin()の対象から外し頭骨へ剛体で追従**: 実装済み。
  `common.py`に`parent_to_bone`を新設(`bpy.ops.object.parent_set(type="BONE",
  keep_transform=True)`)。`monsters.eyeball()`に`blink: bool`引数を足し、
  Trueなら白目・瞳にカスタムプロパティを付ける。garudo.pyは手組みの目に
  直接付けた。3体ともarmature構築後にparent_to_boneで頭の骨
  (ガルド:neck-head、つぶて:chest-head、まぶたむし:body-head)へつないだ。
  実機での動作確認: 頭骨からの相対位置(idle再生中の複数時刻)がアニメーション
  中も一定であることを検証し、頭が回転する場面でも目が正しく追従して
  離れないことをスクリーンショットで確認した。
- **2. glTF extras経由の印**: 実装済み。`export_glb`に`export_extras=True`を
  追加。`GLTFLoader`が`object.userData.blink`として読み込むことを確認。
- **3. 実行時のまばたき制御**: `src/view/blink.ts`を新設(`BlinkController`)。
  `ActorView.update(dt)`に1行差し込んだ。インスタンスごとに乱数タイマーを
  持つ(2〜6秒間隔、閉じ0.1秒→止め0.04秒→開き0.12秒、Y軸スケールを
  0.05倍まで潰す)。ユニットテスト(`tests/blink.test.ts`)で、まばたきの
  タイミング・スケール変化・個体ごとの非同期・対象外オブジェクトへの
  無干渉を検証済み。
- **4. サッケード(視線の微揺れ)**: 実装済み。瞳のバウンディング半径の
  12%以内でランダムに位置をずらす(2.5〜5.5秒間隔)。パイロット3体全部に
  適用した(全種族への展開可否は未決事項のまま残す)。
- **輪郭線への影響(受け入れ基準4)**: 目は元々輪郭線の対象「だった」
  (本体メッシュに統合されていたため、シルエット全体の背面ハルに含まれて
  いた)。join()から外すとこの輪郭線を失うため、`assets.ts`に
  `addRigidOutlineMesh`を新設し、非スキンメッシュ向けの輪郭線を目の
  **子**として追加した(兄弟ではなく子にすることで、まばたきのスケール
  変更にも自動で追従する)。既存の`addOutlineMesh`(スキン付きメッシュ用)は
  `objectNormal`(USE_SKINNING/USE_ENVMAP時のみ宣言される変数)に依存して
  おり、非スキンメッシュではシェーダーコンパイルエラーになったため
  (`npm run playtest`で実際に検出)、生の`normal`属性を使う専用の
  `makeRigidOutlineMaterial`を別途用意した。
- 対象外(視線追従AI・まぶたの造形追加・表情差分)には手を付けていない。
- 全モンスターロースターへの展開は今回のスコープ外。`eyeball()`の
  `blink`引数は既定でFalseなので、他の全種族は変更前と同じ挙動のまま。
