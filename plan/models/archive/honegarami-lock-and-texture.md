## 明度の階層(設定画の実測)

設定画の骨画素(明るい側の半分)と領域の平均輝度。

| 部位 | 骨色 | 領域の平均輝度 |
|---|---|---|
| 頭蓋 | (195,171,144) | 107 |
| 手 | (185,166,138) / (175,156,127) | 97 / 89 |
| 足 | (166,148,126) | ― |
| 胸郭 | (163,141,111) | **61** |

**いちばん暗いのは胸郭**。手が「汚れて暗い」ように見えるのは骨の色では
なく、骨と骨のあいだの暗部が広いから。塊としての暗さはトレース(隙間の
絵)に持たせ、材質側は頭蓋を基準にした部位ごとの明度比だけを持つ
(`RIB_BONE` / `DIRTY_BONE` / `HAND_BONE`)。

## 完了時の実測(archive 時点)

| | 設定画 | モデル |
|---|---|---|
| 手 / 頭蓋 の平均輝度比 | 0.91 | 0.90 |
| 胸郭 / 頭蓋 の平均輝度比 | 0.56 | 0.92 |

胸郭がまだ明るい。**アルベドでは埋まらない** ―― 骨の色を 0.74 → 0.62 まで
落としても比は 0.92 → 0.88 しか動かなかった。ゲームの環境光(寒色 ×1.7)が
明るさの床を作っているため。設定画の胸が暗いのは「骨が暗い」からではなく
「暗い蔦と影の**面積**が広い」からで、ここを本当に詰めるなら胸の暗部の
面積を増やす話になる。密度を戻す誘惑と直結するので、ゲーム内で見てから
判断する。

## 次にやること(この順で)

1. **ゲームカメラで意味のある Secondary Vine だけ足す**(完了)
   96px へ落として設定画と区画ごとに相対輝度を比べ、**大きな流れ**が
   足りない所にだけ主要蔓と同じ太さの蔦を足す。細い蔦は96pxで消えるので
   足さない。計測: `scratchpad/vinecam.py`。
2. **テクスチャ**(完了)。骨と四肢を `C.bake_albedo` で描いた ――
   手前を明るく奥を暗く / 下ほど汚れる / 蔦が触れる所を暗く /
   まだらのくすみ / 骨端の明暗差 / 明るい所だけ暖色へ。
3. **ゲーム内評価**(未)。実際のダンジョンで見て判断する。
4. 棘・芽は**最後**(完了)。**主要蔓と頭部の蔦にだけ**生やす ――
   二次蔓や細枝まで付けると外周が紫のもやになる。細枝(twig)は
   96px で読めないので出さないまま。

## やらないこと

- 設定画の情報量を3Dで全部再現すること。96px では細い指・細枝・小さな
  骨片・細かな蔦の潜行はほぼ読めず、読めるのは 頭蓋・胸郭・大骨片・
  太い紫蔓・巨大な足 だけ。
- 三角形数を当初の 1,200〜5,000 に収めること。この種は構造そのものが
  デザインなので、他のモンスターと同じ予算へ押し込むと魅力を壊す。
  上限は `tests/models.test.ts` の 24,000。最終的にどこまで落とせるかは
  実機画面で LOD 検証する。
- 顎の下の暗部を埋めること。**頭蓋と胸郭を分離する negative space** で、
  90度で頭を救うために作った空間でもある。ゲームカメラで「胴体の大穴」に
  見える場合だけ、肩帯ではなく鎖骨・胸骨上端の細い形を少量見せる。
