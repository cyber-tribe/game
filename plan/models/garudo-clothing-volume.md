# ガルドの衣装を「体の塗り分け」から「独立した立体」へ

## 経緯

「キャラクター造形がそもそも弱く、小手先の技術的な改善では治らない」
という指摘を受け、`garudo-hero-quality-pass.md`(テクスチャ解像度の
引き上げ)を出す前に、実在する3Dキャラクター制作の一般的な工程・
原則を調査した(特定の作品名を参照するものではなく、業界一般の
知見として引く)。

調べて分かったこと: プロの制作工程は概ね「単純図形でのブロッキング
→**衣装を体とは別の独立した形状として抽出し、厚みを持たせる**
→皺を彫る→(必要なら)高解像度でテクスチャへ焼く」という順序で
進む。**衣装が体の「色分け」で済まされることはなく、必ず独立した
立体として作られる。** また、シルエットは細部より先に評価される
(「黒塗りシルエットで判別できるか」が制作途中の検査項目になる)。

## 診断(実測)

`garudo.py`の`classify_body`を確認すると、この原則が守られて
いないことが分かる:

```python
def classify_body(center) -> int:
    """面の位置から 肌0 / 上着1 / ズボン2 / 靴3 / 鉢巻き4 を決める。"""
    z = center.z
    ...
    return 1  # 上着
```

上着・ズボン・靴は、いまも`build_skinned()`が作る**1枚の連続した
ボディメッシュの上の色の境界**でしかない。`flagship-model-
program.md`で顔(鼻・眼窩・口)は彫り込み造形に作り直したが、
**画面占有面積が最も大きい衣装だけが、色分け止まりのまま**残って
いた。黒塗りシルエットにすると、上着の裾も袖口も襟も存在せず、
なめらかな一本の輪郭にしかならない。これが「造形が弱い」という
指摘の核心だと考えられる(`ps2-quality-adversarial-review.md`
重大3の指摘が、看板モデル化後もガルドの衣装にだけ残っていた形)。

なお頭身比率(頭部半径0.150に対し全高およそ0.86、頭身にして
およそ2.5〜3頭身)は、デフォルメキャラクターの一般的な目安
(2〜3頭身)の範囲に収まっており、**比率そのものは問題ではない**。
問題は、形の情報のすべてが色(テクスチャ)に押し付けられ、
シルエットの外形に一切反映されていないことにある。

## 変更内容

### 1. 上着を独立した形状にする(最優先)

- `build_skinned()`の胴体表面をそのまま塗り分けるのをやめ、
  **上着を体からわずかにオフセットした別メッシュ(シェル)**として
  作る。
- 裾は体の輪郭から外側へ張り出す(体に張り付いた色ではなく、
  実際に体より一回り大きい輪郭にする)。袖口は絞る。襟元は
  一段厚みのある折り返しを作る。
- これらは`silhouette-hard-surface-parts.md`が既に確立した
  「硬い部品を`box`/`cylinder`で作り、`pin_weight_to_bone`で
  該当の骨へ固定する」手法をそのまま転用できる(上着の裾・袖口・
  襟をそれぞれ小さな独立ジオメトリとして胴体に足す)。

### 2. 皺を実ジオメトリで彫る

- 負荷のかかる場所(肘の内側、腰の帯の上下)に、2〜3本だけ
  皺を実ジオメトリの窪みとして入れる(頂点を少し押し込むだけで
  よい。`build_wall`の手彫りの粗さと同じ、頂点を直接動かす手法を
  流用できる)。
- 皺は多すぎると安っぽくなる(格好悪いシワの入れすぎは避ける、
  との一般的な注意点も調査で確認した)。2〜3本に絞る。

### 3. ズボン・靴への展開(範囲は実装時に判断)

- 上着で工程を検証してから、ズボンの裾の折り返し・膝の緩み、
  靴の甲と底の段差にも同様の考え方を広げる。上着だけで
  効果が確認できれば同じPRでまとめてよいし、切り分けても構わない
  (未決事項)。

### 4. `garudo-hero-quality-pass.md`との順序

- テクスチャ解像度の引き上げ(`garudo-hero-quality-pass.md`)は、
  **衣装が独立した立体になってから行うほうが筋が通る**
  (皺・裾の陰影を高解像度テクスチャで焼き込めるようになるため)。
  ただし両者は独立して実施可能なため、実装の都合でどちらを
  先に進めても成立するようにする。

## 受け入れ基準

1. ガルドの黒塗りシルエットで、上着の裾・袖口・襟の輪郭が、
   体そのものの輪郭と別れて見える(現状は完全に同一の輪郭)。
2. 肘・腰まわりの皺が、光の当たり方で陰影として視認できる。
3. ポリゴン予算(`texture-pipeline-adoption.md`の看板モデル向け
   基準、ガルド4,000〜7,500)の範囲内に収まる。
4. モバイル実機で60fpsを維持する。
5. 新旧比較スクリーンショットで、衣装が「塗り分け」でなく
   「着ている」ように見える。

## 対象外

- 全モンスター・他の看板モデルへの同時展開(まずガルドで検証する)
- 布のシミュレーション等、動的な布の揺れ(静的な造形の範囲に
  留める)

## 未決事項

- ズボン・靴を同じPRで扱うか、上着の検証後に分けるか
- 皺の本数・位置の最終的な調整(エンジン内プレビューで見ながら
  決める)
